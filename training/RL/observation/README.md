# 관측 (G3)

> **E2 지시문·스킬·목표 감추기(2026-10-04)** — 아래 "지시문" 절. X0 는 이제 432 칸이다.

`include/obs.h` 의 `obsv::assemble` 하나가 G1 관측 80(`env.h`)과 G2 지도 토큰 `MapTok`(1,280 B, `map_tok.h`)을 신경망 입력으로 바꾼다. CPU·GPU 같은 소스(비트 동일).
롤아웃(정책 앞 계산)과 갱신(미니배치 모으기)이 같은 함수를 쓰므로 같은 (스텝, 판)이면 입력 비트가 같다. 그래서 첫 미니배치의 PPO 비율이 정확히 1 이다.

| 입력 | 자리 | 정규화 (가정) |
|---|---|---|
| G1 관측 80 (몸 상태 56 + 벽 광선 16 + 목표 칸 8) | X0[128, 208) | 그대로, ±10 자름 |
| 지도 벽 56 (`MapTok::wall`) | X0[208, 264) | 그대로(이미 /4 m) |
| 방 10 | X0[264, 274) | 문 x·y·거리만 /4 |
| 완성도 4 | X0[274, 278) | 그대로 |
| 안 본 곳 광선 8 (`MapTok::front`, `use_map` 2 만) | X0[279, 287) (편향 278 뒤의 0 칸) | 그대로(이미 /4 m) |
| 물체 칸 16 × (숫자 33 + 이름 원-핫 7 + 생김새 원-핫 7 + 1) | 칸 줄 | 마지막 본 뒤 시간 /10, 본 횟수 /20, 나머지 그대로, ±10 자름 |

- 롤아웃 버퍼에는 정책이 실제로 본 지도 토큰을 스텝마다 저장한다(5.3). `TokenRecorder(N, T+1)` 의 줄 t = 스텝 t 에 본 토큰. 바퀴가 끝나면 마지막 줄을 0 줄로 옮긴다.
- 지도 토큰(물체 칸·벽·방)은 G2 의 자라는 지도(slam 오차·검출 실수 포함)다.
- `use_map = 0` 이면 지도 입력(칸·벽 56·방·완성도)을 모두 0 으로 한다. 목표 출처(아래)는 그대로 지도를 따른다.
- `use_map = 1` 은 G3/G4 입력 그대로(안 본 곳 광선 칸 0 — 예전 체크포인트를 같은 입력으로 평가), `use_map = 2` 는 + 안 본 곳 광선 8(`../map/README.md` "본 칸 토큰"). 칸 자리가 X0 의 0 칸이라 신경망 모양(288)·GEMM 은 그대로다.

## 목표 출처 `goal_mode` (G4, 계획서 5.4 교사 특권 한정)
G1 관측 80 의 배치는 그대로다(`env.h` step_core). 바뀌는 것은 정책 입력에서 목표 값을 **언제 보여 주느냐**뿐이다.

| G1 관측 자리 | 뜻 | `goal_mode 0`(특권, G3) | `goal_mode 1`(지도, G4 기본) |
|---|---|---|---|
| 0–52 | 몸 상태(관절·팔 끝·몸통 속도·직전 명령) | 그대로 | 그대로 |
| 53–55 | 손끝 → 목표(base_link) | 참값 | 목표가 지도에 확정됐을 때만 참값, 아니면 0 |
| 56–71 | 벽 광선 16(/4 m, 방 벽 참값) | 그대로 | 그대로 |
| 72–78 | 목표 몸 기준 xy, 거리, 방위, 보임, 겉면, 카메라 거리 | 참값 | 확정됐을 때만 참값, 아니면 0 |
| 79 | 목표 표시 | 늘 1 | **목표를 앎** 1 / 0 |

- "확정" = 그 스텝 지도 토큰의 목표 칸(맨 앞 칸 `T_TARGET` = 1). 목표 칸은 참 컵에 짝 문턱 안 같은 이름의 확정(사라짐 아닌) 칸이다(`map_tok.h`). 곧 **이미 보고 확정한 물체의 정확한 자세만** 교사에게 준다(5.4). 아직 못 본 컵은 교사도 모른다 → 찾아야 한다.
- 처음 지도 C0 은 컵이 처음부터 확정, C1 은 약 절반, C2 는 늘 모름(`../map/README.md` G4).
- 롤아웃 버퍼에는 G1 참값을 그대로 두고 정책 입력을 만들 때만 가린다. 그래서 환경 보상·퍼텐셜 모양 잡기(`../reward`)는 참값으로 계산된다(보상은 관측이 아님 — 비대칭 정보, 가치 머리도 가린 입력만 봄).
- 롤아웃(`assemble_k`)과 갱신(`gather_k`)이 같은 `assemble` 과 같은 저장 토큰으로 가리므로 같은 (스텝, 판)이면 입력 비트가 같다(V6 비트 동일, 첫 미니배치 비율 1 그대로).

## 지시문·스킬(E2, 2026-10-04) — X0 304 → 432
- 지도 토큰 `MapTok` 의 예전 `pad2` 자리에 `instr1`(판의 지시문 행 + 1 = 환경 `I_B_INSTR` + 1, 0 = 없음)·`bkind`(BEHAVIOR 단계 1–3, 0 = 상자 방)를 둔다 — 지도가 판 리셋 때 환경에서 읽어 둔다(`BMapEnv::instr`). 상자 방은 예전과 같은 바이트(0). 토큰 줄이 롤아웃 버퍼·BC 자료에 그대로 저장되므로 갱신 모으기·BC 표본도 같은 행을 본다.
- `assemble` 이 X0 [304, 432) 에 `training/data/pnp_v1/instr128.f16` 의 그 행(bf16 그대로, `VecTab::pinstr`, 표 708 행)을, [291, 294) 에 스킬 원-핫 B1·B2·B3 을 넣는다. 둘 다 과제 값이라 `use_map`·지도 끄기 흔들기와 무관하게 늘 넣는다.
- **교사도 받는다**(결정): POLICY 4.2 (가) "학생과 같은 값 — 영상만 없음" 이고, B2 찾기는 지도에 확정되기 전에 무엇을 찾는지(목표 정체)를 알아야 한다. 교사 특권(목표 자세)은 예전처럼 지도에 확정된 뒤에만. 스킬 원-핫은 POLICY 3.2 "교사: 스킬 원-핫"(학생은 BC 에서 같은 X0 를 받지만 토큰 학생 arch 1 은 글 토큰으로만 지시를 봄).
- 신경망: A1·C1 입력 432(편향 칸 278 그대로 — 초기화는 예전처럼 편향 칸 앞만 무작위, 지시문·스킬·광선·경유 지점 칸 가중치는 0 에서 시작 **(가정)**). 변수 391,488 → 457,024. 상자 방에서는 그 칸 가중치·Adam 이 늘 0 으로 남는다(`snap` 이 확인 — "instruction-column weights/Adam != 0: 0"). 변수 배치가 길어져 기울기 노름 합의 묶음 나눔이 바뀌므로 상자 방 해시도 바뀐다(학습 길은 같음).
- 검증: `ppo_verify obs [--aug] [--stage 3]` CPU == GPU 0 낱말 + 지시문·스킬 칸 독립 확인(표 행 그대로, 토큰 행 = 환경 `I_B_INSTR`): env 3 N 512 에서 309 판이 지시문, B1/B2/B3 203/155/154, 0 다름. 음성 대조(CPU 가 표 열을 하나 밀어 읽음) 39,520 다름.

## 목표 표시 감추기(학생, `ObsAug::p_goal_drop`, 2026-10-04)
- 학생만(BC 학생 입력 흔들기). 판·스텝 열쇠마다 확률 p 로 **칸의 "목표인지"(`T_TARGET`)·목표 특권 값(G1 53–55·72–79)·다음 경유 지점**을 감춘다 → 학생은 지시문 128-d 와 칸 이름 벡터(같은 얼린 공간)를 맞춰 목표 물체를 찾아야 한다. 나머지 표본은 표시가 그대로. 교사(PPO 학습기·BC 교사 라벨 입력)는 늘 0. `on` 과 무관(흔들기 끔이어도 p 가 켜져 있으면 감춤).
- 기본: BC 설정 `goal_drop` 0.5 **(가정)**, 장치 값 `bc_set_goal_drop`. 접지 평가 = 학생 평가마다 표시를 늘 끈 판(`<이름>_noflag`, p = 1)을 한 번 더 — "B2·B3 판 끝에 로봇에서 가장 가까운 과제 물체가 목표인가" 비율과 B2·B3 성공(`BcLog g_n·g_ok·p_n·p_succ`, results.json `grounding`).
- 검증: `ppo_verify obs --gdrop [--stage 3 --aug]` 0 낱말 다름, 512 판 중 250 판 감춤·새는 낱말 0. `bc_verify v5 --lite --gdrop [--stage 3 --txt]`·`--arch1 --act8 --gdrop`: 기록 = 본 것(감춘 표본 290/512)·모으기 CPU == GPU 0 다름, V6(`--lite --aug --gdrop`, `--arch1 --aug --raug --act8 --gdrop`) 0 낱말.
- **nvcc 12.8 최적화 문제**: 감추기 해시를 `assemble` 안에 펼치면(-O3) 같은 함수의 속도 잡음 칸이 실행마다 다른 값이 됐다(`-G` 면 맞음, 입력·열쇠 같음 — `ppo_verify obs --aug`·V6 `--aug` 가 잡음). 판정을 따로 부르는 함수(`goal_off_hash`, `__noinline__`)로 빼서 피했다.
