# 근사판 대 진짜 scenemap (계획서 GPU_TRAINING.md 5.2)

GPU 지도 근사판(`../map`)과 진짜 scenemap(behavior-2026 서브모듈 `src/scene_graph/scenemap`, LIMO + OMX, CPU)에 **같은 입력**을 넣고 keyframe 마다 지도를 비교한다.
처음에는 규칙만 비교하려고 **잡음을 양쪽 다 끈다**. 근사판은 `-DMAP_NOISE_V=0` 으로 따로 빌드한다(`map.h` 의 스위치, 커밋 af9730c. 기본값 1 은 비트가 그대로이고 `map_verify 2048 600` 해시 `ce67f18f6556df76`, `--force-kf` 해시 `6c34f99830ac169e` 가 전과 같다). 진짜 쪽 입력에는 잡음을 넣지 않는다.
파이썬은 쓰지 않는다. C++ 하나(`tools/map_cmp.cpp`)가 G1 환경(GPU), 근사판(GPU), 렌더(CPU), scenemap C ABI(CPU)를 모두 부른다.

## 방법
- 판 N 개(기본 50)를 GPU 에서 돌린다. 판마다 첫 에피소드만 쓴다. 행동은 `map_verify` 와 같다(무작위 행동, 짝수 판은 접근 제어). stage 1 이다.
- 같은 환경 상태로 근사판 둘을 돌린다. **A** 는 확정 규칙 그대로이고, **B** 는 음성 대조로 확정 규칙을 끈다(`bug 1`, 한 번 보이면 확정, `map_verify --negative` 와 같음). 장면 상자와 keyframe 이 A·B 에서 같은지는 매 스텝 확인한다(어긋남 0).
- 진짜 scenemap 은 판마다 `sm_create({"robot":"limo_omx","odom":"pose"})` 로 만들고, 이름표는 근사판 종류 6 개(cup, item, chair, table, cabinet, bin)다. table·cabinet 은 scenemap 기본 표에서 고정 종류이고, 근사판 `is_static` 과 같다. 자세 모드는 SLAM(기본), 넣기 정책은 0(움직임 거르기, 근사판이 흉내 내는 정책)이다.
- **매 스텝** `sm_push_proprio` 로 LIMO proprio 12 개를 넣는다. 0–2 는 근사판이 믿는 자세(오도메트리, 잡음을 끄면 참 자세), 3–5 는 v, 0, w, 6–10 은 env `q[0..4]`, 11 은 `q[5]`(그리퍼 0 = 닫힘)다. stamp 는 0.1 s × 판 안 스텝이다.
- **근사판 keyframe 마다** 같은 stamp 로 `sm_push_image(cam 0)` 를 부른다.
  - 깊이 640×400: 근사판이 쏘는 같은 장면(`MapCore::prim` 상자 9 개 + 방 벽·바닥·천장, 근사판 `ray_room`/`ray_box_inv`/`pix_dir` 그대로)을 **화소마다** CPU 로 렌더한다. 카메라는 근사판 식(참 베이스 + (cam_x 0.084, 0, cam_z 0.18), 기울기 0)이다. 내부 파라미터는 근사판 `cam_consts()` 의 fx = fy = 475.313(가로 FOV 67.9°)이고, cx = 319.5, cy = 199.5 다. 깊이 범위 0.3–3.0 m 밖은 0(없음)으로 둔다.
  - 완벽한 검출: 렌더 id 버퍼에서 보이는 물체마다 마스크(640×400 칸 그대로, `mask_s = 1`)와 상자를 만든다. 이름은 근사판 종류, 점수는 0.9 다. 검출기 잡음은 없다.
- keyframe 마다 `sm_snapshot` 을 근사판 상태와 비교한다. 진짜 지도의 원점은 첫 proprio 의 베이스이므로 그 자세로 세계 좌표에 옮긴다.
  - 물체를 참 물체(장면 상자)에 짝짓는다. 같은 종류이고, 중심이 상자 xy + 0.2 m 안이거나 중심 거리가 max(0.3, 0.5·최대 변) 안인 것 중 가장 가까운 것이다. 집합 = 짝지은 참 물체(중복은 하나로) + 짝이 없는 물체(각각 하나)이고, 사라짐(GONE)은 뺀다. 정밀도·재현율은 진짜를 기준으로 keyframe 마다 더한다.
  - 확정까지: 참 물체마다 그 지도에 처음 붙은 keyframe → 처음 확정된 keyframe 수. 진짜 쪽은 `sm_last_assoc` 가 0 이 아닌 첫 keyframe, 근사판은 그 참 물체에 짝지은 칸이 처음 생긴 keyframe 이다.
  - 위치 오차: 확정·짝지은 물체 중심 − 참 상자 중심(3D)을 keyframe × 물체마다 모은다.
  - 격자: 근사판 칸(0.10 m) 중심이 방 + 0.15 m 안인 칸만 본다. 진짜 격자(0.05 m)는 그 중심 점을 읽는다. 3 종은 모름(본 적 없음 / −1 / 50 %), 빈칸(L < 0 / < 50 %), 점유(L > 0 / > 50 %)다. 참고로 진짜 0.05 m 칸 넷을 모은 값도 낸다(점유가 하나라도 있으면 점유, 없고 빈칸이 하나라도 있으면 빈칸).
- 카메라 외부 자세: keyframe 마다 같은 proprio 로 `sm_robot_fk(SM_ROBOT_LIMO_OMX)` cam 0(베이스 ← 광학)을 근사판 식과 원소별로 비교한다.

## 빌드·실행
```
cmake -S training/RL/map_cmp -B ~/ra_mapcmp && cmake --build ~/ra_mapcmp -j --target map_cmp
~/ra_mapcmp/map_cmp 50                    # 기본: SLAM, 넣기 정책 0, 씨앗 20261004
~/ra_mapcmp/map_cmp 50 --mode odom        # 진짜 쪽 자세 = 적분만(맞추기 없음)
~/ra_mapcmp/map_cmp 50 --policy 1         # 진짜 쪽 넣기 정책 1(사건 기반, scenemap 기본값)
~/ra_mapcmp/map_cmp 50 --seed 7           # 다른 장면·궤적
~/ra_mapcmp/map_cmp 10 --trace 3          # 판 3 의 keyframe 마다 검출·확정 물체 목록
```
scenemap 소스는 서브모듈에서 읽기만 하고 빌드 폴더 안에 빌드한다(`SCENEMAP_DIR`). `RL_DIR` 로 env·map 소스 폴더를 바꿀 수 있다. 다른 작업이 `map/` 를 고치는 중이면 커밋된 판을 `git archive HEAD training/RL/env training/RL/map | tar -x -C <dir>` 로 꺼내 `-DRL_DIR=<dir>/training/RL` 로 빌드한다. 아래 결과는 이렇게 빌드한 커밋 af9730c 의 `map/`로 냈고, 작업 트리 빌드와 출력이 바이트까지 같았다. N = 50 한 번에 3.0 s 걸리고(RTX 5070 Ti, CPU 32 스레드), 최대 메모리는 0.66 GB 다.

## 다른 점 진단 (잰 값)

### 1. 위치 오차 — 실패. 관측 위치를 정하는 규칙이 다르다
- 근사판은 검출을 **참 상자 중심**에 놓는다(`put_det` 는 중심 + 평균 0 잡음). 그래서 잡음을 끄면 오차가 0 이다. 잡음을 켜도 평균은 0 이다(옆 0.04 m, 깊이 0.006·z²).
- 진짜 objmap 은 **보이는 면의 깊이 점**(마스크를 1 칸 깎은 안쪽, MAD 띠 안)의 축별 중앙값을 위치로 쓴다. 큰 가구(> 0.5 m·고정 종류)는 10–90 백분위 상자의 합집합 중심을 쓴다. 그래서 위치가 카메라 쪽으로 치우친다.
  - 수평 시선 방향 성분(+ = 카메라에서 멀어짐) 10/50/90 % 는 −0.233 / **−0.096** / −0.032 m 다. 높이 성분은 −0.034 / 0.000 / 0.003 m 로 거의 없다.
  - 종류별 3D 오차 50/90 %: cup 0.039 / 0.043(반지름 0.04 = 앞면), item 0.089 / 0.117, bin 0.152 / 0.181, cabinet 0.196 / 0.263, chair 0.232 / 0.264, table 0.259 / 0.421 m. 물체가 클수록 오차가 크다(앞면까지 거리 ≈ 깊이의 반, 큰 가구는 일부만 본 상자).
- 고칠 곳(근사판): 관측 위치를 상자 중심이 아니라 "보이는 면 쪽"으로 옮긴다. 작은 물체는 시선 방향으로 깊이 반폭쯤, 큰 물체는 시야에 든 부분의 상자를 쓴다. 이 비교의 50 % 차(0.106 m)는 검출 잡음 σ 0.04 m 보다 크다.

### 2. 검출(물체 기억에 들어가는 관측) — 기준 안이지만 진짜가 더 많이 받는다
keyframe × 참 물체 관측: 근사 2,294, 진짜 2,544, 둘 다 2,283 이다(근사 정밀도 0.995, 재현율 0.897). 진짜만 받은 261 건을 근사판 판정에 다시 넣어 까닭을 나눴다.

| 근사판이 안 받은 까닭 | 건수 | 종류 |
|---|---|---|
| 물체 **중심** 깊이가 [ozmin 0.15, ozmax 3.0] 밖 | 167 | table 79, bin 39, cabinet 27, chair 15, item 7 |
| 보임 점 9 개(중심 + 0.8 배 모서리)가 다 시야 밖·가림 | 94 | table 31, bin 17, item 16, chair 14, cabinet 13, cup 3 |
| min_px·넓이 사전 판정, 넓이 × 보임 비율 < 20, 기타 | 0 | |

- 근사판은 물체 전체를 **중심 하나**의 깊이와 **9 점**으로 판정한다. 진짜는 **화소마다** 깊이(0.15–5 m, 렌더가 3 m 로 자름)를 본다. 그래서 중심은 3 m 밖이어도 가까운 부분이 3 m 안인 큰 물체나, 시야 가장자리에 일부만 든 물체는 진짜만 받는다.
- 근사판만 받은 11 건: 진짜 쪽 마스크를 1 칸 깎은 안쪽의 유효 깊이 화소가 20 미만인 것이 9 건(근사판 넓이 어림 `af` 이 실제 화소 수보다 큼), 기타 2 건이다.
- 이 차이 때문에 진짜가 먼저 확정하는 물체가 있다. 같은 참 물체에서 근사판이 늦은 경우가 34 건, 빠른 경우는 0 건이다. 씨앗 7 에서는 재현율이 0.903 으로 기준(0.9)에 가깝다.
- 고칠 곳(근사판): 깊이 범위 판정을 중심 대신 "물체 상자의 가장 가까운 점 ≤ ozmax"로 바꾸고, 시야 판정을 9 점 대신 상자의 투영이 화면과 겹치는지로 바꾼다.

### 3. 격자 — 기준 안. 모름/빈칸 경계가 다르다
모은 칸 비교에서 가장 큰 어긋남은 근사 모름 · 진짜 빈칸(314,006 칸 × keyframe)이다. 카메라와의 거리는 < 1.15 m 13,999, 1.15–2 m 106,480, 2–3 m 168,228, ≥ 3 m 25,299 다.
- 근사판의 빈칸 광선은 열 64 × 줄 8 이다. 장애물이 없는 열의 빈 광선 끝은 띠 아래 줄 중 가장 먼 바닥 점이다. MP 값으로 계산하면 바닥에 닿는 줄의 광학 깊이는 3.42 / 1.14 / 0.68 / 0.49 m 이다. 3.42 m 는 깊이 범위 3.0 m 밖이므로, 벽이 3 m 안에 없으면 빈칸이 **약 1.14 m** 에서 끝난다. 진짜는 화소 간격 4(160 × 100 점)의 모든 바닥 점으로 3 m 까지 빈칸을 만든다. 잰 분포도 1.15–3 m 에 몰려 있다(87 %).
- 진짜만 점유인 칸(모은 값): 벽 띠 33,635, 작은 물체(컵·물건) 5,706, 가구 5,651, 빈 바닥 0 이다. 벽 띠가 많은 것은 근사판 열 64 개(1.06° 간격)가 비스듬한 벽에서 칸 사이를 건너뛰고, 진짜는 방위 칸 720 개와 수직면 맞추기 점(dense, 0.05–3.0 m)을 모두 맞음으로 넣기 때문으로 보인다(까닭은 추정, 자리는 잰 값). 작은 물체(높이 0.12–0.35 m)는 근사판의 줄 8 개가 띠 [0.10, 1.80] 안에서 맞히는 거리가 좁다.
- 띠도 다르다. 근사판은 R1 값 [0.10, 1.80] 이고, 진짜 LIMO 는 [0.05, 0.50] + 맞추기 점이다. 이 장면은 벽과 바닥에 놓인 상자뿐이라 띠 차이가 따로 보이지는 않았다.
- 칸 크기 차이(0.10 대 0.05)는 진짜 칸 넷을 모으면 근사 점유 · 진짜 모름이 22,443 → 2,389 로 줄어든다. 곧 그만큼은 해상도 때문이다.
- 고칠 곳(근사판, 일치율을 더 올리려면): 바닥 쪽 줄을 늘리거나 장애물이 없는 열의 빈칸을 깊이 범위(3 m)까지 그린다. 열 수를 늘린다.

### 4. 확정 규칙 자체
같은 관측이 들어간 물체에서 확정 시점은 같다(근사 − 진짜 = 0 이 120 건, 음수 0 건). 서로 다른 keyframe 2 번이라는 규칙은 맞다. 차이(근사가 늦은 34 건)는 모두 2 번 진단의 관측 차이에서 온다. 진짜 쪽 중복 확정이 17 건(keyframe × 물체, 큰 가구를 따로 본 것), 사라짐은 양쪽 모두 0 건이다.

## 한계
- 잡음을 끈 규칙 비교뿐이다. 근사판의 잡음 모형(오도메트리 치우침, 놓침, 유령, 틀린 이름)과 진짜 쪽 검출기·SLAM 잡음의 비교는 아니다. 같은 잡음 검출을 넣는 길은 아직 없다(근사판이 검출을 밖으로 내지 않음).
- G1 동역학은 장면 상자와 부딪치지 않는다(근사판 README). 로봇이 상자 안을 지나가면 양쪽 모두 그 상자를 못 본다(렌더는 근사판 광선과 같은 규칙).
- 팔은 홈 자세로 고정이다(stage 1). 잡기 규칙, 손 거르기, 몸 가리기는 시험되지 않았다.
- 벽 벡터 56과 지도 토큰은 근사판에 아직 없어 비교하지 않았다.
- scenemap 은 고치지 않았다(필요 없었음).
