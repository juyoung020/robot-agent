# 정책·가치 신경망 (G3)

계획서 [GPU_TRAINING.md](../../../docs/map_vla/GPU_TRAINING.md) 3·6·7절. 손 커널(CUDA)만 쓴다. PyTorch·JAX·cuBLAS 는 없다.

## 구조 (`include/net.h`)
```
지도 물체 칸 16 × 입력 48 ──S1 48→64 ELU──S2 64→64 ELU──┐  (16 칸 같은 가중치)
                                                         ├ 빈 칸 가린 평균 64 + 최댓값 64 = 128 (집합 인코더)
X0 = [집합 128 | G1 관측 80 | 벽 56 | 방 10 | 완성도 4 | 1 | 안 본 곳 광선 8(use_map 2, 아니면 0) | 0] = 288
정책  A1 288→256 → A2 256→256 → A3 256→128 (ELU) → A4 128→8 평균,  log σ 8 개(상태 무관)
가치  C1 288→256 → C2 256→256 → C3 256→128 (ELU) → C4 128→1
```
- 변수 366,912 개(정렬 포함), 평평한 FP32 버퍼 하나(K9). 편향은 따로 없고 입력의 "1 칸"에 대응하는 가중치 열이다.
- 칸 입력 48 = 칸 숫자 33(VLA_INPUT 3절) + 이름 번호 원-핫 7 + 생김새 번호 원-핫 7 + 1. 계획서 4.4 의 SigLIP 이름·생김새 표(각 128) 대신 원-핫이다 **(가정: 표가 아직 없음)**. 원-핫 × 첫 층 = 학습되는 표와 같다.
- 크기는 계획서의 1–5M (추정) 보다 작게 시작했다(0.37M). A0/A1 에는 충분했다(`../ppo/README.md`).

## 커널 (`src/`)
| 파일 | 내용 |
|---|---|
| `gemm.cuh` | 손 GEMM(템플릿): 앞 `Y = X·Wᵀ`, `dX = dZ·W`(끝단에서 이전 층 ELU' 곱해 bf16 dZ), `dW = dZᵀ·X`(split-K 조각 FP32 → 고정 순서 합). **`gemm2_k`**(기본, G4 뒤): ldmatrix(.trans) 조각 읽기, cp.async 이중 버퍼, 모양별 타일(N ≥ 128: 128×128 워프 64×32, 출력 64 행 dW: 64×64, N ≤ 16: 128×16, 그 밖 128×64), 같은 모양 문제 둘(정책·가치 사슬)을 한 번에(`blockIdx.z`). 예전 `gemm_k`(128×64×32, 32 비트 읽기, XOR 섞기)는 `NET_GEMM_OLD=1` 로 비교용. 둘 다 출력 원소마다 k 를 16 씩 같은 차례로 mma 하므로 결과 비트가 같다 |
| `slot_fused.cuh` | 칸 MLP 묶음(G4 뒤): 앞 S1 → S2 → 집합 한 커널(s1o·s2o 를 다시 읽지 않음), 뒤 집합 뒤 → dW S2·dX S2 → dW S1 한 커널(dZ S2·dZ S1 을 전역에 쓰지 않음). 같은 순서·같은 식(비트 같음). 예전 길은 학습기 `NET_SLOT_OLD=1` |
| `net_kernels.cu` | GEMM 실행(모양별 타일 고르기, 짝 실행 `gemm_fwd2·gemm_dx_dact2·gemm_dw2`), 집합 앞·뒤(스레드당 8 칸 16 B), 칸 MLP 묶음 실행, PPO 손실(K5: 자르기 + 가치 자르기 + 엔트로피 + 자르기 밖 평균 벌 → dZ 와 log σ 기울기), dW 조각 합, Adam(K9: 기울기 노름 2 단계 → 자르기 → Adam → bf16 사본, 학습률·스텝은 장치 값) |
| `net_ref.cpp` | CPU 참조판: FP64(정답) 와 EMUL(GPU 정밀도 처방 흉내 = 바닥). 검증 전용 |

## 자르기 밖 평균 벌(G4, `LossHyper::bound_coef`)
손실에 `bound_coef · 행 평균 Σ_k max(0, |μ_k| − 1)²` 를 더한다(학습하는 행동 k < act_dims 만). 환경은 행동을 ±1 로 자르므로 |μ| > 1 이면
표본이 거의 모두 같은 행동(±1)이 되어 PPO 이득이 μ 를 안쪽으로 되돌릴 기울기를 주지 못한다. G3 A1 정책(결정적 평가)은 스텝의 64 %(vx)·38 %(wz)에서
|μ| > 1 이었고, 다시 보기한 충돌 646 건(모두 벽)의 평균 |μ_wz| 는 3.30 이었다(`../ppo/README.md` G4). 기본 `bound_coef` 0.5 **(가정)**, 0 이면 끔이고 그때 dZ 는
G3 와 비트가 같다(`d0 + scale·db` 를 db ≠ 0 일 때만). rl_games 의 bounds loss 와 같은 꼴.

결정성: 부동소수 원자 연산이 없다. 모든 합은 블록 안 고정 나무 + 블록 부분합 고정 순서(9절 V7).

## 검증 (9절 V4·V5) — `../ppo/tools/ppo_verify`
바닥(EMUL)은 GPU 처방을 흉내 낸 CPU 계산과 FP64 의 차이다. 기준은 **GPU 오차 ≤ 2 × 바닥**(상대 L2, 텐서마다).
- 텐서 코어 FP32 누산은 IEEE 가장 가까운 반올림이 아니다. EMUL 을 처음에 "float 를 차례로(가장 가까운 반올림)" 로 두었을 때 FP32 출력 연산(dW 10 개, dpool)의 비율이 2.02–2.55 로 9 개가 실패했다. EMUL 누산을 "k 16 개(mma 한 번) 곱을 정확히 더하고 0 쪽으로 잘라 FP32" 로 바꾸자 비율이 0.82–0.96 이 되었다 **(가정: 이 누산 모형. 잰 비율이 근거)**. bf16 출력 연산은 두 모형 모두 비율 1.00. 최종 수치는 FP32 출력 비율 0.64–0.94.
- G4: EMUL 의 log σ 기울기 합(행 2,048 개)을 FP32 로 누산하도록 바꿨다(GPU 처방이 FP32 누산이다. 전에는 double 로 더해 바닥이 GPU 처방보다 낮았음).
  이 검사는 FP32 합의 반올림(상대 1e-7) 수준이라 미니배치가 바뀌면 비율이 0.6–3.5 로 흔들렸다(G4 미니배치에서 3.45 로 실패 → 고친 뒤 0.59).
- 결과 숫자는 `../ppo/README.md`.

## G6 — FP8 GEMM (`src/gemm_fp8.cuh`, 계획서 2.2·7.2·7.3·9절 V3) — 잰 값, RTX 5070 Ti, CUDA 12.8
`mma.sync.aligned.kind::f8f6f4.m16n8k32.row.col.f32.<A>.<B>.f32`(FP32 누산). **sm_120a 전용**이라 이 헤더를 쓰는 대상만 `-gencode arch=compute_120a,code=sm_120a` 로 빌드한다(다른 대상은 sm_120 그대로 → 결과 비트 안 바뀜). sm_120 으로 빌드하면 FP8 커널은 `__trap()`.

| 커널 | 쓰임 | 입력 | 배율 |
|---|---|---|---|
| `tn_k<KIND>` | 얼린 인코더 앞(TN, 둘 다 K 연속) | 미리 양자화한 FP8 바이트(또는 FP16/BF16 — 같은 타일·ldmatrix·4 단 cp.async, mma 만 다름 → 공정한 속도 비교) | 끝단 함수가 곱함(인코더: 행마다 × 출력 채널마다) |
| `gemm8_k<FA,FB,AT,BT,EPI>` | 학습 신경망(네 배치, `gemm2_k` 와 같은 끝단·짝 문제·split-K) | bf16 그대로, 공유 메모리에 쓸 때 FP8 로("읽으며 양자화") | 텐서마다, amax 는 같은 그래프의 앞 커널(`amax_bf16_impl_k`, 정수 원자 최대 → 결정적) |

- 배율은 2 의 거듭제곱 `2^floor(log2(fmax/amax))`(E4M3 448, E5M2 57344) — 곱·되돌림이 정확해서 CPU 흉내가 GPU 와 비트로 맞는다.
- K 연속 FP8 은 값 둘을 16 비트 하나로 보면 bf16 판과 **같은 `ldmatrix.b16`·같은 주소**로 A·B 조각이 맞는다. M 연속(전치)은 8 비트 `ldmatrix.m16n16.x2.trans.b8`(sm_120a, 12절).
