# GPU 안에서 자라는 지도 — scenemap 근사 (계획서 G2 앞부분)

GPU_TRAINING.md 5.1 의 장치 지도. 판마다 장치 메모리에 작은 지도를 두고, scenemap(CPU)의 규칙과 기본값을 **흉내 낸다**(옮긴 것이 아님).
G1 환경(`../env`)과 같은 방식: CPU 참조판과 GPU 커널이 **같은 소스**(`include/map.h`)를 쓰고, `detmath.h` + `--fmad=false`/`-ffp-contract=off` 로 **비트 단위 동일**이다.

## 구성
- `include/map.h`: 상수(`MP`), 판마다 상태(`MapCore`), 광선, 시작 단계 `phase_begin` + 나머지 `map_rest`(CPU·GPU 공용). CPU 는 둘을 이어 부르는 `map_block`
- `include/map_api.h`, `src/map_kernel.cu`, `src/map_ref.cpp`: `DeviceMap`(장치), `CpuMap`(참조판, 판 단위 OpenMP)
- `tools/map_verify.cu`: G1 환경으로 몰면서 GPU == CPU 비트 동일 확인. `--negative` 는 반드시 실패해야 함. `--force-kf` 는 매 스텝 keyframe
- `tools/map_bench.cu`: 판 수별 keyframe 갱신/초. 같은 소스를 `-DMAP_PROF` 로 빌드한 `map_prof` 는 커널 안 구간별 clock64 시간도 찍는다(결과 비교에는 쓰지 않음)
- `map_verify` 는 끝에 CPU 지도 전체의 해시를 찍는다. 같은 씨앗·스텝이면 최적화 전후 의미가 같은지 이 값으로 본다
- `include/map_tok.h`: 지도 토큰(5.3, VLA_INPUT 3·4절) `MapTok` 1,280 B 와 `make_tokens`(CPU·GPU 공용), FP16 변환
- `tools/map_tokrec.cu`: 지도 토큰 기록(스텝마다 장치 기록 버퍼 [T][N] 에 바로, 끝에 파일로)
- `tools/map_realcheck.cpp`(선택 빌드 `-DMAP_REALCHECK=ON`): 같은 입력으로 **진짜 scenemap 코드**(서브모듈 소스를 읽기만 해 빌드)와 점유 문턱·격자·벽 선분·벽 벡터·들기 규칙·팔 끝 순기구학을 맞춘다
- `tools/map_drift.cpp`: 정해진 궤적(탐색 비슷 / gt_move 대본)을 G1 운동학으로 만들어 지도 단계에 넣고 slam 자세 오차 rms·max 와 가짜 검출·확정 물체 통계를 낸다(보정용). `-DDRIFT_CPU_ONLY` 로 g++ 빌드하면 같은 코드의 CPU 참조판으로 돌고, `-DKF_CORR_XY_V=…` 등으로 맞춤 값을 바꿔 볼 수 있다

G1 환경에는 선택 단계로 붙는다. 환경 쪽 변경은 `env_api.h` 의 읽기용 `DeviceEnv::soa()` 하나뿐이다.
```
env.step(act, obs, rew, done);            // G1 그대로
map.step(env.soa(), 0, 0, st, rec.at(t)); // 지도: 환경 상태를 읽기만 함. 이 스텝 지도 토큰을 롤아웃 버퍼 t 줄(장치)에 바로 씀
```

## 설계
GPU 한 스텝 = 커널 셋(`DeviceMap::step`):
1. `map_begin_kernel`: 판 하나 = 스레드 하나. 시작 단계(아래 1)와 들기 규칙을 돈다. keyframe·리셋·들기/놓기(벽 무시 영역이 바뀜)인 판은 장치 안 목록에 원자 덧셈으로 넣고, 아닌 판은 완성도만 쓰고 끝난다.
2. `map_kf_kernel`: 목록의 판 하나 = 블록 하나(64 스레드). 블록 수는 N 으로 고정하고 목록 길이 밖 블록은 바로 끝난다. 목록 길이는 스텝마다 `cudaMemsetAsync` 로 0 으로 한다. keyframe 갱신 뒤 벽 선분(아래 6)을 같은 블록이 한다.
3. `map_tok_kernel`: 모든 판, 판 하나 = 레인 16(블록 = 판 8). 지도 토큰(아래 7)을 `step` 에 준 장치 자리(롤아웃 버퍼의 t 줄)에 쓴다.

호스트 동기는 없다(nsys: 스텝마다 memset 1 + 커널 실행만). 상태는 제자리에서 갱신한다(그래프로 잡을 수 있음). 목록 순서는 실행마다 달라도 판끼리 독립이라 결과는 같다. 호스트 값은 커널 인자로 넘기지 않는다(`force_kf`·`bug` 는 검증·측정용 상수). CPU 참조판은 같은 `phase_begin` → `map_rest` 를 판마다 이어 부른다.

| 장치 지도(판마다) | 내용 | scenemap 원본 |
|---|---|---|
| 점유 격자 | int16 로그 오즈 Q=256(`l_hit 0.85 → +218`, `l_miss −0.4 → −102`, `±4 → ±1024`) + 본 칸 비트. **0.10 m 칸, 128×128 고정 창**(12.8 m, 원점 중심) | `grid.hpp` GridParams, `grid.cpp` insert |
| 물체 기억 | 16 칸: valid, id, cls, pos, ext, first_pos, n_obs, score, last_seen, last_kf, state(SEEN/GONE/MOVED), confirmed, moved, misses, first_miss. 후보 = valid && !confirmed | `scenemap.h` sm_object, `objmap.hpp` MapObject |
| slam 자세 | 믿는 자세 = 참 + 오차. 스텝마다 오도메트리 표류(판마다 배율 치우침 + 걸음마다 잡음), keyframe 마다 xy·yaw 를 따로 일부 되돌림 | `slam2d.hpp` |
| 완성도 | 과제 물체(컵) 확정, 장면 물체 확정 비율, 방 칸 중 본 비율, 자세 오차 xy·yaw, keyframe 표시 → `metrics()[k*N+i]` | 새로 |

한 스텝:
1. **시작(판마다 한 스레드)**: 환경 판 번호가 바뀌면 지도 리셋(격자·물체 비움, 장면 다시 만듦). 아니면 참 증분에 이 판의 배율 치우침(이동·회전·직진 중 yaw)과 걸음마다 잡음을 넣어 믿는 자세에 붙인다. 움직임 거르기는 slam2d `update_policy 0` 이다: 처음이거나, **참 자세**가 지난 keyframe 뒤 `mf_xy 0.05 m`·`mf_yaw 2°` 넘게 움직였거나, `mf_kf 50` 번째면 keyframe. 아니면 여기서 끝난다.
2. **광선(모든 스레드)**: 참 카메라에서 참 장면(방 벽·바닥·천장, 상자 9 개)으로 64 열 × (8 줄 + 빈칸 줄 1)을 쏜다. `scan.cpp` 규칙대로 열마다 높이 띠 [0.05, 0.50] 안 가장 가까운 점은 장애물, 띠 아래 가장 먼 바닥 점은 빈 광선 끝이다. 깊이 범위는 `zmin 0.3`~`zmax 3`, 가로 FOV 67.9°(Dabai 깊이). 한 열의 줄 8 개는 수평 방향이 같으므로 방 벽과 상자의 xy 판(slab)은 열마다 한 번 구하고, z 판만 줄마다 구한다. `1/d` 는 광선마다 한 번 구한다. max·min 은 정확한 연산이라 결과 비트는 줄마다 따로 쏜 것과 같다. 상자에 들어가는 t 가 모든 줄의 지금 값 이상이면 그 상자는 건너뛴다(결과 같음). 물체마다 시야로 자른 실루엣 안 5 점으로 가림 광선을 쏜다(위 "5.2 비교로 고친 것" 2). 단, 보이는 점과 무관한 검출 판정(모서리 깊이 범위, min_px, 다 보일 때의 넓이 ≥ min_points)을 못 넘는 물체는 어차피 검출될 수 없으므로 쏘지 않는다. 넓이는 보이는 점 수에 단조라 결과가 같다.
3. **자세 보정·검출·물체 기억**: 순서가 있는 일(난수, 새 칸 고르기)만 스레드 0 이 순서대로 한다. 나머지는 나눠 한다: 짝 열쇠(쌍마다), 탐욕 최솟값(GPU 는 워프 셔플, (열쇠, 번호) 순이라 원래 이중 고리의 첫 최소와 같음), 짝지은 관측의 갱신(관측마다 다른 칸), 부재 확인·버리기(칸마다), 완성도(참 물체마다).
   - 맞은 열이 `min_hits` 이상이고 제자리(`still_v/w 0.01`)가 아니면 xy 오차를 `kf_corr_xy`, yaw 오차를 `kf_corr_yaw` 만큼 되돌린다.
   - 검출: 보이는 점 비율 × 투영 넓이로 화소 수를 어림한다. `size_px = fx·최대변/z < min_px 6` 이나 `넓이 < min_points 20` 이면 안 보인 것이다. 그다음 거리별 놓침, 깊이·옆 잡음, 크기 잡음, 틀린 이름을 넣는다. 가짜 물체는 판마다 정해진 유령 자리가 시야에 들 때 검출된다. 위치는 **그 순간의 믿는 자세**로 지도에 놓는다(slam 오차를 물려받음).
   - 짝짓기·갱신은 `objmap.cpp` 를 따른다. 같은 이름끼리 `max(da_min 0.30, da_k 0.5·크기)` 또는 상자 틈 `da_gap 0.10` 안이면 짝 후보이고, (틈 + 1e-3·거리) 순으로 1:1 탐욕 짝짓기를 한다. 작은 것은 n_obs(최대 20) 가중 평균, 큰 것(`big 0.5`·고정 종류)은 `grow_max 0.25`·`max_ext 4` 한도 합집합이다. 서로 다른 keyframe 에서 `confirm 2` 번 보이면 확정이다. 안 맞은 관측이 같은 이름의 사라짐 물체와 이어지면 옮겨짐(`moved_d 0.15`)이다.
   - 부재 확인: 확정 물체를 믿는 자세로 화소에 투영하고, 그 화소의 참 깊이와 비교한다(`occl 0.10`). `gone_misses 3` 번 연속이고 `gone_min_s 2 s` 가 지나면 사라짐이다. 후보가 `prune_s 10 s` 동안 안 보이면 버린다.
4. **격자 표시(모든 스레드)**: 열 끝을 믿는 자세로 세계에 놓고, 정수 Bresenham(끝 칸 제외)으로 지나는 칸을 공유 메모리 비트표 miss 에, 장애물 끝 칸을 hit 에 `atomicOr` 한다. 빈 광선 끝 칸은 miss 다. 두 끝이 창 안이면 칸마다 창 검사를 하지 않는다. GPU 는 낱말이 바뀔 때 그 낱말의 로그 오즈를 L2 로 미리 당긴다.
5. **격자 갱신**: 맞음이 우선이고, 정수 덧셈 뒤 [−1024, 1024] 로 자르며, 본 칸 표시를 한다. 이것은 `grid.cpp` 의 "한 스캔에서 칸마다 한 번, 맞음 우선" 과 같고, OR 와 정수 덧셈이라 **스레드 순서와 무관**하다. GPU 는 워프가 낱말 32 개를 ballot 으로 훑어 표시된 낱말만 고르고, 그 낱말의 칸 32 개를 레인 32 개가 맡는다(로그 오즈 64 B 를 한 번에, 낱말 4 개씩 읽기를 먼저 냄). CPU 는 낱말마다 칸을 차례로 한다. 방 안 새로 본 칸 수는 정수 부분합이다.

6. **벽 선분(walls.cpp wallSegments, 판 하나 = 블록 하나)**: keyframe 갱신에서 점유 비트(`occ`, 로그 오즈 ≥ 153 = export8 ≥ 65 %)를 같이 고친다. 점유 비트가 바뀌었거나 무시 영역(확정·안 든·사라짐 아닌, 바닥이 0.4 m 아래·한 변 ≤ 5 m 물체 상자 + 0.1 m — capi.cpp refreshWalls)이 바뀌었을 때만 다시 한다(결과 같음). 무시 영역을 지우고, 가로 벽은 행마다·세로 벽은 열마다(워프 셔플 비트 전치) 길이 ≥ 5 칸 구간을 찾아(스레드가 나눔) 위 행 묶음과 겹침 ≥ 0.6·짧은 쪽(`5·ov ≥ 3·min`, 0.6·m 의 double 판정과 같음)이면 잇고, 두께 > 4 행(5 · double(0.10f) > 0.5)이면 버린다. 묶기는 구간이 있는 행만 차례로(가로 = 스레드 0, 세로 = 스레드 32). 행 순서·선분 순서는 walls.cpp 의 "파이썬 행"(위 → 아래) 그대로라 선분 목록이 진짜와 같다. 선분은 반 칸 정수 좌표로 판마다 장치 배열에 둔다(가로·세로 각 32 칸).
7. **지도 토큰(스텝마다, 모든 판)**: 믿는(slam) 자세 base_link 기준. 벽 56 = 광선 16(walls.cpp rayDistances 와 같은 DDA, 로봇 둘레 96 행을 공유 메모리로) + 가까운 선분 8 × (끝 둘 /4 m, 유효). 물체 칸 = 확정 칸, 목표 물체가 맨 앞, 나머지는 가까운 순. 칸 숫자 33 은 VLA_INPUT 3절 표 순서(`map_tok.h` TokSlot). 이름 뜻·생김새 벡터는 번호만(4.4): 이름 번호 = 지도 이름(틀린 이름 그대로), 생김새 번호 = 출처 참 물체의 종류(유령 = 6). 방 10 = 방 종류 6(VLA_INPUT 순서 + 모름) + 가까운 문 x·y·거리·있음. 완성도 4. FP16 은 GPU 하드웨어 `__float2half_rn`, CPU 는 정수 연산판 — float 2³² 개 전수로 같다(`map_verify` 가 시작 때 확인).
8. **들기(objmap.cpp updateHands, LIMO 값)**: 시작 커널에서 매 스텝. 팔 끝 = G1 순기구학 `omx_end_effector_link` + base_joint 0.15 m(관절이 그대로면 다시 계산하지 않음) → 믿는 자세로 map. `omx_gripper_joint_1 < 0.35` 가 되는 순간 팔 끝 0.12 m 안 가장 가까운 확정·안 든·사라짐 아닌 물체를 들고(팔 끝 기준 자리를 베이스 축으로 기억), 든 동안 매 스텝 따라가고, 열리는 순간 놓는다(잡은 자리에서 0.15 m 넘게 옮겼으면 옮겨짐). 든 물체는 짝짓기·옮겨짐 잇기·부재 확인·벽 무시 영역에서 빠진다. 검출 중심이 팔 끝 0.10 m 안이면 버리고(손에 든 것), 팔 끝 0.20 m 안 물체는 부재 확인을 하지 않는다(objmap hand_r).
9. **방(5.1 의 5 번 근사)**: G1 은 칸막이 없는 직사각형 방이라 판 리셋 때 긴 축을 1–2 번 잘라 방 1–3 개(긴 변 ≥ 4.5 m 면 2, ≥ 6 m 면 3)를 만든다. 자르는 선은 장면 상자(가구·작은 물건·컵)를 지나지 않게 고르고, 방 최소 폭 1.2 m, 문 = 자르는 선 위 한 점. 칸막이 벽은 넣지 않는다(G1 동역학·광선 그대로). 난수는 따로 된 값이라 기존 지도 결과는 그대로다. 방은 본 넓이 ≥ 2 m²(rooms.hpp min_room_m2) 이고 방 칸의 30 % 이상을 봤을 때 드러나고, 문은 양쪽 방이 다 드러났을 때만 토큰에 들어간다.

### 보정(커밋 101b36a 의 `map_calib` 적용)
값은 `calib.json` 그대로이고 출처 표시는 `MP` 주석에 있다. 모형을 바꾼 곳(모두 `map.h` 공용 경로라 CPU 참조판도 같이 바뀜):
1. **판마다 오도메트리 배율 치우침**: 판 리셋 때 이동 배율 σ 3.0 %, 회전 배율 σ 13 %, 직진 중 yaw σ 1.78 °/m 를 뽑아 판 안에서 고정한다(`odo_bt/br/bw`). 증분 = 참 증분 × (1 + 치우침) + 걸음마다 잡음(`odo_t/rr/rt` = 0.15/0.035/0.03). R1 은 회전을 늘 +13 % 더 셌지만 LIMO 는 부호를 모르므로 ± 대칭으로 뽑는다.
2. **keyframe 보정을 xy 와 yaw 따로**: `kf_corr_xy 0.025`, `kf_corr_yaw 0.7`(맞춤, `map_drift` 를 CPU 빌드에 -D 로 값을 바꿔 격자 탐색: xy {0.01…0.15} × yaw {0.05…0.8}, 판 256 개). calib 의 하나짜리 `kf_corr 0.02` 는 치우침이 없는 모형용이라 쓰지 않았다(이 모형에서 0.02/0.02 는 rms 약 24.5 cm / 9.7°).
3. **움직임 거르기를 참 운동으로**: keyframe 판단을 지난 keyframe 의 참 자세와 지금 참 자세의 차로 한다.
4. **가짜 물체 = 판마다 정해진 유령 자리**: 판 리셋 때 방 안 아무 데나 3 자리(높이 0.05–0.5 m, 크기 0.05–0.2 m, 아무 이름)를 정하고, 중심이 깊이 범위·시야 안이면 keyframe 마다 `p_ghost 1.0` 으로 검출한다(가림은 안 봄). 독립 가짜(맞은 열 위 상자, `p_fp`)는 없앴다.
5. **거리별 놓침**: 카메라–물체 중심 거리 < 1.5 m 0.15, 1.5–2.5 m 0.10, ≥ 2.5 m 0.79(계단, R1 기록의 거리별 값 그대로). calib 의 평균 0.21 은 이 계단의 평균이라 따로 쓰지 않는다.
6. **깊이 카메라(Dabai 데이터시트)**: 깊이 범위 0.3–3.0 m(`zmax`, 물체 `ozmax`), 깊이 가로 FOV 67.9°(`MP::depth_hfov`, env.h 의 71° 는 컬러 FOV 라 그대로 둠). 640×400 정사각 화소라 세로 FOV 는 45.6°(사양 45.3°).

바꾼 것(모두 `map.h` 공용 경로이거나 GPU 전용 경로가 같은 연산을 함. 결과 비트는 그대로):
1. 광선: xy 판을 열마다 한 번, `1/d` 를 광선마다 한 번 구하고, 못 줄이는 상자는 건너뛴다.
2. 스레드 0 혼자 하던 일을 나눴다: 짝 열쇠·짝지은 갱신·부재 확인·완성도는 스레드에, 탐욕 최솟값은 워프 셔플로. 검출 기하는 미리 공유 메모리에 두고, 난수 상태는 레지스터에 둔다. 지역 메모리 배열을 없애 202 → 56 레지스터.
3. 물체 보임 점: 보임과 무관한 판정을 못 넘는 물체는 쏘지 않는다. 보임은 물체마다 비트 하나로.
4. 격자 갱신: 워프 ballot 으로 표시된 낱말만, 칸마다 레인 하나, 낱말 4 개씩 읽기를 먼저 냄. 격자 표시 때 L2 미리 당김.
5. keyframe 이 아닌 판은 시작 커널(판마다 스레드)에서 끝내고, keyframe 판만 블록으로(장치 안 목록).
6. MapCore 를 한 물결 뒤 블록 몫까지 L2 로 미리 당기고, 환경 읽기를 MapCore 읽기와 겹친다.

N=32,768 매 스텝 keyframe 에서 각 단계 뒤 지도 ms: 5.65 → 1.49(1, 2) → 1.27(점유율) → 1.15(워프 탐욕) → 1.10(보임 점, 격자 갱신) → 1.03(표시 미리 당김, MapCore 미리 당김) → 1.00(커널 둘). 해 보고 되돌린 것: 여러 훑기에 걸친 낱말 8 개 묶음(1.19 ms, 레지스터 86), 상주 블록 8·11·12(10 이 가장 빠름).

구간 빼기 실험(결과는 틀리고 시간만 봄, 1.117 ms 일 때): 격자 갱신 빼면 −0.24 ms, 격자 표시 빼면 −0.36 ms(갱신도 빈 표를 봄), 보임 점 빼면 −0.31 ms(뒤 물체 일 −0.14 포함). 점유율 실험: 상주 블록 4 → 8 에서 1.75 배, 8 → 11 에서 1.13 배라 지금은 블록 지연보다 SM 처리량 쪽에 가깝다.

남은 병목(잰 것):
- keyframe 블록 안에서 격자 갱신(21 %, 표시된 낱말마다 DRAM/L2 대기), 스레드 0 검출(17 %, 난수 사슬과 나눗셈이 순서대로), 격자 표시(16 %, 가장 긴 광선의 Bresenham 이 워프를 붙잡음), 광선(13 %).
- 공유 메모리 8 KB(대부분 hit·miss 비트표 4 KB)가 SM 당 블록 수를 묶는다.
- 시작 커널 41 µs: 판마다 스레드가 AoS MapCore 머리를 따로 읽는다.
- 환경+제어+지도 처리량(N=32,768 에서 4.3e7 env-step/s)은 여전히 G1 환경만(7.3e8)보다 17 배 느리다.

## 흉내 내지 않은 것(단순화)
- 맞추기를 실제로 하지 않는다. 오차 비율(xy·yaw 따로)만 줄인다. 넣기 정책은 update_policy 1(사건 기반)이 아니라 0(움직임 거르기)이다.
- 스캔: dense 맞추기 점(띠 위 벽·탁자 뒤 벽), 몸 가리기, 붙은 것 거르기가 없다. 열 하나 = 방위 칸 하나다.
- 물체: 마스크·MAD 이상값, 손에 든 것 거르기, 들기·놓기(grasp_r 0.25, 팔을 안 쓰는 G1 단계라), 받침 붙이기, 중복 병합(merge), 점 구름이 없다. 부재 확인 깊이는 3×3 중앙값 대신 광선 하나다. 작은 물체의 상자는 pos ± ext/2 로만 둔다.
- 방은 참 방 표의 근사다(진짜 rooms.cpp 거리 변환·지속성 나누기를 하지 않음). 방 이름은 아무거나다(물체 이름 규칙 없음).
- 들기: 놓을 때 받침에 붙이기(parent)가 없다. 손에 든 것 거르기는 점의 절반 대신 검출 중심 하나로 본다. 손 하나(LIMO).
- 벽: 진짜는 격자를 넓혀 가며 창 밖도 쓰지만 여기는 128×128 고정 창 안만 본다. 선분은 가로·세로 각 32 칸까지(넘치면 버리고 센다 — 위 시험에서 0).
- 토큰: "지금 보는 중" 칸도 위치는 지도 자리다(이번 프레임 마스크 + 깊이로 다시 재지 않음). 이름 확신도 2 는 검출 점수로 대신한다.
- 격자는 넓어지지 않는 고정 창이다. 창 밖 칸은 버린다.

## 남은 일
- **5.2 진짜 scenemap 과 맞추기(V2, `map_verify --check` 의 진짜 판)**: 막혀 있다. scenemap 순기구학은 R1 Pro 전용(`fk.cpp`, `r1pro_fk_table.hpp`)이고 proprio 도 R1 Pro 61 개다. behavior-2026 저장소에 LIMO + OMX 순기구학과 proprio 형식을 먼저 넣어야 한다. 이 작업에서는 하지 않았다(submodule 을 건드리지 않음).
- LIMO 실기록으로 오도메트리 치우침·보정 비율·검출 실수를 다시 맞춘다(지금은 R1 시뮬 기록). 탐색 판 max 자세 오차(3 m 깊이에서 맞추기가 끊기는 구간)와 keyframe 당 가짜 수는 아직 실제와 다르다(위 결과).
- 지도 단계가 늘어난 시간(N=32,768 에서 0.65 → 1.14 ms): 토큰 커널(판 8 블록이 머리·칸 읽기 지연과 광선 DDA 에 묶임)과 벽 선분(64 스레드 블록, 동기 8 번). 다음 후보: 토큰을 시작 커널의 판마다 스레드 일과 합치기, 벽 선분을 바뀐 행만 다시(walls.cpp WallExtractor 처럼).
- 커리큘럼 처음 지도(5.5: 일부 확정·격자 공개), CUDA 그래프로 잡기(지도 단계는 memset + 커널 둘이라 잡을 수 있는 꼴), 위 남은 병목.
