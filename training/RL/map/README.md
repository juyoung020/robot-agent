# GPU 안에서 자라는 지도 — scenemap 근사 (계획서 G2 앞부분)

GPU_TRAINING.md 5.1 의 장치 지도. 판마다 장치 메모리에 작은 지도를 두고, scenemap(CPU)의 규칙과 기본값을 **흉내 낸다**(옮긴 것이 아님).
G1 환경(`../env`)과 같은 방식: CPU 참조판과 GPU 커널이 **같은 소스**(`include/map.h`)를 쓰고, `detmath.h` + `--fmad=false`/`-ffp-contract=off` 로 **비트 단위 동일**이다.

## 구성
- `include/map.h`: 상수(`MP`), 판마다 상태(`MapCore`), 광선, 한 판 한 스텝 `map_block`(CPU·GPU 공용)
- `include/map_api.h`, `src/map_kernel.cu`, `src/map_ref.cpp`: `DeviceMap`(장치), `CpuMap`(참조판, 판 단위 OpenMP)
- `tools/map_verify.cu`: G1 환경으로 몰면서 GPU == CPU 비트 동일 확인. `--negative` 는 반드시 실패해야 함. `--force-kf` 는 매 스텝 keyframe
- `tools/map_bench.cu`: 판 수별 keyframe 갱신/초

G1 환경에는 선택 단계로 붙는다. 환경 쪽 변경은 `env_api.h` 의 읽기용 `DeviceEnv::soa()` 하나뿐이다.
```
env.step(act, obs, rew, done);   // G1 그대로
map.step(env.soa());             // 지도: 환경 상태를 읽기만 함
```

## 빌드/실행
```
cmake -S . -B ~/ra_mapbuild && cmake --build ~/ra_mapbuild -j
~/ra_mapbuild/map_verify 2048 600              # GPU == CPU 비트 동일이어야 통과
~/ra_mapbuild/map_verify 2048 600 --negative   # 실패해야 정상(종료 코드 0)
~/ra_mapbuild/map_bench 200 32768
```

## 설계
판 하나 = 블록 하나(64 스레드). 상태는 제자리에서 갱신한다(그래프로 잡을 수 있음). 호스트 값은 커널 인자로 넘기지 않는다(`force_kf`·`bug` 는 검증·측정용 상수).

| 장치 지도(판마다) | 내용 | scenemap 원본 |
|---|---|---|
| 점유 격자 | int16 로그 오즈 Q=256(`l_hit 0.85 → +218`, `l_miss −0.4 → −102`, `±4 → ±1024`) + 본 칸 비트. **0.10 m 칸, 128×128 고정 창**(12.8 m, 원점 중심) | `grid.hpp` GridParams, `grid.cpp` insert |
| 물체 기억 | 16 칸: valid, id, cls, pos, ext, first_pos, n_obs, score, last_seen, last_kf, state(SEEN/GONE/MOVED), confirmed, moved, misses, first_miss. 후보 = valid && !confirmed | `scenemap.h` sm_object, `objmap.hpp` MapObject |
| slam 자세 | 믿는 자세 = 참 + 오차. 스텝마다 오도메트리 표류, keyframe 마다 일부 되돌림 | `slam2d.hpp` |
| 완성도 | 과제 물체(컵) 확정, 장면 물체 확정 비율, 방 칸 중 본 비율, 자세 오차 xy·yaw, keyframe 표시 → `metrics()[k*N+i]` | 새로 |

한 스텝(`map_block`):
1. **시작(스레드 0)**: 환경 판 번호가 바뀌면 지도 리셋(격자·물체 비움, 장면 다시 만듦). 아니면 참 증분에 잡음을 넣어 믿는 자세에 붙인다. 움직임 거르기는 slam2d `update_policy 0` 이다: 처음이거나, `mf_xy 0.05 m`·`mf_yaw 2°` 넘게 움직였거나, `mf_kf 50` 번째면 keyframe. 아니면 여기서 끝난다.
2. **광선(모든 스레드)**: 참 카메라에서 참 장면(방 벽·바닥·천장, 상자 9 개)으로 64 열 × 8 줄을 쏜다. `scan.cpp` 규칙대로 열마다 높이 띠 [0.10, 1.80] 안 가장 가까운 점은 장애물, 띠 아래 가장 먼 바닥 점은 빈 광선 끝이다. 깊이 범위는 `zmin 0.3`~`zmax 8`. 같은 단계에서 물체마다 점 9 개(중심 + 줄인 모서리 8)로 가림 광선을 쏜다.
3. **자세 보정·검출·물체 기억(스레드 0, 순서대로)**:
   - 맞은 열이 `min_hits` 이상이고 제자리(`still_v/w 0.01`)가 아니면 오차를 `kf_corr` 만큼 되돌린다.
   - 검출: 보이는 점 비율 × 투영 넓이로 화소 수를 어림한다. `size_px = fx·최대변/z < min_px 6` 이나 `넓이 < min_points 20` 이면 안 보인 것이다. 그다음 놓침, 깊이·옆 잡음, 크기 잡음, 틀린 이름, 가짜 물체를 넣는다. 위치는 **그 순간의 믿는 자세**로 지도에 놓는다(slam 오차를 물려받음).
   - 짝짓기·갱신은 `objmap.cpp` 를 따른다. 같은 이름끼리 `max(da_min 0.30, da_k 0.5·크기)` 또는 상자 틈 `da_gap 0.10` 안이면 짝 후보이고, (틈 + 1e-3·거리) 순으로 1:1 탐욕 짝짓기를 한다. 작은 것은 n_obs(최대 20) 가중 평균, 큰 것(`big 0.5`·고정 종류)은 `grow_max 0.25`·`max_ext 4` 한도 합집합이다. 서로 다른 keyframe 에서 `confirm 2` 번 보이면 확정이다. 안 맞은 관측이 같은 이름의 사라짐 물체와 이어지면 옮겨짐(`moved_d 0.15`)이다.
   - 부재 확인: 확정 물체를 믿는 자세로 화소에 투영하고, 그 화소의 참 깊이와 비교한다(`occl 0.10`). `gone_misses 3` 번 연속이고 `gone_min_s 2 s` 가 지나면 사라짐이다. 후보가 `prune_s 10 s` 동안 안 보이면 버린다.
4. **격자 표시(모든 스레드)**: 열 끝을 믿는 자세로 세계에 놓고, 정수 Bresenham(끝 칸 제외)으로 지나는 칸을 공유 메모리 비트표 miss 에, 장애물 끝 칸을 hit 에 `atomicOr` 한다. 빈 광선 끝 칸은 miss 다.
5. **격자 갱신**: 비트 낱말 하나 = 스레드 하나가 맡는다. 맞음이 우선이고, 정수 덧셈 뒤 [−1024, 1024] 로 자르며, 본 칸 표시를 한다. 이것은 `grid.cpp` 의 "한 스캔에서 칸마다 한 번, 맞음 우선" 과 같고, OR 와 정수 덧셈이라 **스레드 순서와 무관**하다. 방 안 새로 본 칸 수는 스레드별 부분합을 고정 순서로 더한다.

결정성: 난수(splitmix64)는 판마다 따로 두고, 스레드 0 만 고정 순서로 뽑는다. 가우스 잡음은 균등 4 개 합(Irwin–Hall)이라 초월함수가 없다. 시각은 정수 제어 스텝이다(10 s = 100 스텝).

장면: G1 은 빈 방 + 컵이라 지도용 상자를 더했다. 벽에 붙인 가구 5 개(의자·탁자·장·쓰레기통, 탁자·장은 고정 종류)와 바닥의 작은 물건 3 개다. **G1 동역학은 이 상자와 충돌하지 않는다**(G1 비트 동일을 지키려고 환경을 바꾸지 않음). 로봇 시작점·컵과 겹치지 않게 놓는다.

## 결과 (RTX 5070 Ti, sm_120, CUDA 12.8 — 잰 값)
- `map_verify 2048 600`: **GPU == CPU 비트 동일**이다. 매 스텝 환경 상태, MapCore 전체, 격자 로그 오즈, 본 칸 비트, 완성도를 비교했다. 1,228,800 스텝 중 keyframe 은 561,990(45.7 %), 가짜 검출은 26,442 였다. 끝난 판 13,842 개의 마지막 완성도 평균은 과제 물체 확정 0.708, 장면 물체 확정 0.437, 방 칸 본 비율 0.387 이다. 최대 자세 오차는 0.007 m / 0.015 rad 였다.
- `map_verify 2048 600 --force-kf`(매 스텝 keyframe): 비트 동일이다.
- `map_verify 2048 600 --negative`(GPU 만 확정 규칙 끔, confirm 1): 1,023,005 개 항목이 달라 **실패했다(정상)**. 첫 불일치는 0 스텝 MapCore 12 번 낱말(`n_obj_conf`)이다.
- G1 재검증(이 작업 뒤): `env_verify 2048 600` 은 비트 동일이고 성공 8,879 / 충돌 3,420 / 시간초과 1,543 으로 전과 같다. `--negative` 는 49,581,848 불일치로 실패했다(정상).
- 처리량(`map_bench 200`, 접근 제어 + 넷 중 하나는 돌며 달림). 판당 지도 36,528 B 다.

| N | keyframe 비율 | 지도 커널 ms/스텝 | keyframe 갱신/s | 환경+제어+지도 env-step/s |
|---|---|---|---|---|
| 1,024 | 69.2 % | 0.186 | 3.81e6 | 4.79e6 |
| 4,096 | 69.2 % | 0.582 | 4.88e6 | 6.71e6 |
| 16,384 | 69.2 % | 2.296 | 4.94e6 | 7.01e6 |
| 32,768 | 69.2 % | 4.502 | 5.04e6 | 7.17e6 |

- 참고: G1 환경만이면 N=262,144 에서 7.3e8 env-step/s 다(`../env/README.md`). 지도 단계가 붙으면 지도가 대부분을 차지한다. 커널 안 구간별 시간은 아직 재지 않았다.
- GPU 메모리: N=32,768 에서 지도 약 1.2 GB 다. 65,536 은 재지 않았다(다른 GPU 작업과 같이 돌아서).

## 흉내 내지 않은 것(단순화)
- 맞추기를 실제로 하지 않는다. 오차 비율만 줄인다. 넣기 정책은 update_policy 1(사건 기반)이 아니라 0(움직임 거르기)이다.
- 스캔: dense 맞추기 점(띠 위 벽·탁자 뒤 벽), 몸 가리기, 붙은 것 거르기가 없다. 열 하나 = 방위 칸 하나다.
- 물체: 마스크·MAD 이상값, 손에 든 것 거르기, 들기·놓기(grasp_r 0.25, 팔을 안 쓰는 G1 단계라), 받침 붙이기, 중복 병합(merge), 점 구름이 없다. 부재 확인 깊이는 3×3 중앙값 대신 광선 하나다. 작은 물체의 상자는 pos ± ext/2 로만 둔다.
- 방(rooms), 벽 벡터 56, 지도 토큰은 아직 없다(4.4, 5.1 의 5 번).
- 격자는 넓어지지 않는 고정 창이다. 창 밖 칸은 버린다.

## 남은 일
- **5.2 진짜 scenemap 과 맞추기(V2, `map_verify --check` 의 진짜 판)**: 막혀 있다. scenemap 순기구학은 R1 Pro 전용(`fk.cpp`, `r1pro_fk_table.hpp`)이고 proprio 도 R1 Pro 61 개다. behavior-2026 저장소에 LIMO + OMX 순기구학과 proprio 형식을 먼저 넣어야 한다. 이 작업에서는 하지 않았다(submodule 을 건드리지 않음).
- 그 비교 결과로 위 (가정) 값을 맞춘다: 검출 실수 확률, slam 오차 크기, 보정 비율.
- 벽 벡터 56·방 근사·지도 토큰(K2 에 합침), 들기 규칙(팔 쓰는 단계), 커리큘럼 처음 지도(5.5: 일부 확정·격자 공개), 커널 구간별 시간과 최적화, CUDA 그래프로 잡기.
