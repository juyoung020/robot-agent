# BC — 모방학습 (VLA 증류)

RL 전문가가 시뮬에서 성공한 궤적(영상, state, 지도 토큰, 행동)과 자연어 단계 지시로 작은 VLA 를 학습한다. 지금 학생 = 얼린 SigLIP 2 B/32-256 영상 탑(우리 C++/CUDA, 패치 토큰) + 토큰마다 트랜스포머 6 층(변수 9.2M, `arch: 1`) + flow matching 행동 전문가. Qwen 몸통을 쓰는 큰 모델(G7)은 아직 없고 사양은 [MAPVLA_SPEC.md](../../docs/map_vla/MAPVLA_SPEC.md). C++/CUDA/Rust 네이티브만 쓴다(PyTorch·JAX 등 프레임워크와 Python 학습·추론 코드 금지. 층별 정확성 검증용 오프라인 기준값 덤프만 예외).

### 3. 인코더 출력 캐시(G5 남은 일 1) — 재고 따져서 **안 함**
표본마다 렌더 잡음 씨앗을 묶으면 같은 표본 = 같은 패치 토큰이라 두 번째부터는 렌더·인코더(99.5 ms/스텝)를 건너뛸 수 있다. 막는 것은 크기다.
- 토큰 = 128 × 784 bf16 = 200,704 B/표본. 본 실험 자료 1.05M(BC)–1.1M(DAgger) 표본이면 **약 210 GB**(FP8 로 줄여도 105 GB). 장치는 16 GB(학습기 4–6 GB 사용), 호스트 RAM 60 GB(빈 것 약 53 GB) → 담을 수 있는 것은 많아야 약 22 만 표본(21 %).
- 다시 쓰임: 미니배치는 균등 복원 추출이라 BC 4,000 스텝 × 256 = 1.02M 뽑기(자료 1.05M)에서 같은 표본을 두 번째 이상 뽑는 몫이 1 − (P/n)(1 − e^(−n/P)) ≈ **36 %**(계산). 캐시가 21 % 만 담으면 맞음 ≈ 7.6 % → 스텝당 약 7.5 ms 절약(계산).
- 맞았을 때 비용은 작다: 고정 호스트 → 장치 51.4 MB(표본 256 개 토큰) 1.09 ms, **47.0 GB/s**(잰 값).
- 그래서 지금 일정(약 1 에포크)에서는 FP16 누산(스텝당 20.4 ms, 잰 값)이 캐시(약 7.5 ms, 계산)보다 크다. lite 예산(약 48 에포크)이면 캐시가 거의 다 맞지만 210 GB 를 둘 곳이 없다 → 토큰을 P1 앞에서 줄이는 모델 변경(남은 일)과 같이 다시 본다. 잡음 씨앗을 묶으면 지금의 "자리마다 다른 그림자 잡음"(증강처럼 작용) 효과도 사라진다.

## G5 본판 — 영상 학생(카메라 2 장 + 지도 토큰 + 지시 문장, flow matching 행동 청크)

student-lite(아래 절) 위에 VLA_INPUT 1·5절의 나머지 입력·출력을 붙였다: **카메라 2 장 → 렌더(학습 때 다시) → 얼린 SigLIP 2 B/32-256 패치 토큰 → 학생**, 지시 문장 글 벡터, flow matching 행동 청크.
모두 C++/CUDA(+ Rust 실행기). Python 은 오프라인 한 번 쓰는 기준값 덤프(`tools/siglip_ref.py`)와 지시 문장 표 만들기(`tools/text_table.py`)뿐이고 학습·추론 경로에 없다.
**내려받은 것 없음**: SigLIP 2 가중치는 이미 HF 캐시에 있던 open_clip `ViT-B-32-SigLIP2-256`(webli) safetensors(1.5 GB, 영상 탑만 읽음)를 C++ 가 직접 읽는다. π0.5 가중치는 쓰지 않았다.

### 1. 렌더를 CUDA 그래프로 — 잡힌다(서브모듈 그대로, 감싸기 없음)
`RenderBatch::render` 안은 커널 실행뿐(kBuild, kRigs, 카메라마다 kShade → kAtrous × 잡음 제거 → kCompose)이고 판 수·잡음 제거 횟수·frame 은 잡을 때 고정되는 호스트 값이다.
걸림돌은 하나: `render_cam` → `Scratch::ensure` 가 **처음 부를 때 `cudaMalloc`** 을 한다. 그래서
- 작업 공간 없이 바로 잡기: `cudaMalloc ... operation not permitted when stream is capturing` 로 실패(`vit_verify render-graph` 의 (a), 자식 과정에서 확인).
- `bcr::create` 가 잡기 전에 기본 장면으로 **한 번 그려 작업 공간을 잡아 두면** 그 뒤 `render` 는 그대로 잡힌다. 복사·수정·별도 그래프 필요 없음 — 학습·롤아웃 그래프 안에 다른 커널과 함께 들어간다.

| 256², 카메라 2, 판 256 | 그래프 노드 | 그래프 == 즉시 실행 | 즉시 | 그래프 | 판·프레임/s |
|---|---|---|---|---|---|
| 싼 설정(spp 1, 튕김 0, 반사 0, 잡음 제거 0) | 7 | **0 바이트 다름** | 15.70 ms | 15.89 ms | **16,114** (62 µs/표본) |
| 팀 기본(튕김 1, 반사 1, 잡음 제거 4) | 15 | 0 바이트 다름 | 116.37 ms | 116.53 ms | 2,197 (450 µs/표본) |

- 큰 커널 몇 개라 그래프로 얻는 시간은 없다(실행 비용이 작음). 이득은 학습·롤아웃 그래프 하나에 같이 들어가 호스트 동기가 없다는 것.
- 작업 공간이 화소당 72 B(잡음 제거 G 버퍼 + 조도 핑퐁 — 싼 설정도 잡음)라 판 256 × 256² × 2 카메라 묶음이 약 1.45 GB. 그래서 판 1,024 는 256 씩 4 번 나눠 그린다(같은 그래프 안).
- 224² 가 아니라 **256²** 로 그린다: 인코더가 B/32-**256**(위치 임베딩 8 × 8)이라 크기 조정·위치 임베딩 보간이 없다. 224² 때(48 µs)보다 렌더가 1.3 배.

**싼 설정 대 팀 기본(품질)**: 같은 상태 128 개(`vit_verify quality 128`): 화소 차 평균 19.2 / 255, 패치 토큰 코사인 평균 **0.72**(하위 1 % 0.21) — 같은 설정의 다른 상태끼리가 0.55 라, 간접광·반사가 인코더 특징을 크게 바꾼다. 싼 설정은 7.3 배 빠르고 이번 실험은 모두 싼 설정이다. 싼 설정으로 학습한 정책을 팀 기본 영상(또는 실제 카메라)에 쓰면 이만큼 분포가 어긋난다 → 색·조명 흔들기나 팀 기본 섞기가 필요(남은 일).

### 2. 영상 인코더 — 얼린 SigLIP 2 B/32-256 패치 토큰, 팀 엔진은 그대로 못 씀
- 팀에 있는 것: `src/scene_graph/clip`(sgclip) 의 TensorRT 엔진(`training/model/siglip2_b32/*.plan`)은 **MAP 풀링 + 마스크 뒤 768-d 하나**만 내고, 자기 스트림·고리·`sgc_poll` 구조라 우리 그래프에 넣기 어렵다(`training/model/README.md` 도 "VLA 비전 인코더로는 못 씀"). 엔진을 다시 만들려면 Python(TensorRT 빌더)이 든다.
- 그래서 같은 모델(open_clip `ViT-B-32-SigLIP2-256`, timm `vit_base_patch32_siglip_256`: 패치 32, 768 폭, 12 층 × 12 머리, GELU tanh, LN ε 1e-6, CLS 없음)의 영상 탑을 **C++/CUDA 로 직접** 짰다. 가중치는 디스크의 open_clip safetensors 를 C++ 손 파서로 읽음(내려받기 없음). 출력 = 끝 LN 뒤 패치 토큰 64 개/장(MAP 머리는 안 씀). 학습 중 얼림(앞만).
- 정밀도: GEMM 피연산자·중간 저장 **FP16**, 누산·잔차 흐름·LN 통계·softmax FP32. BF16 피연산자는 바닥(EMUL)과 오차가 같은데도(비율 1.00) 기준에 못 미쳤다 → FP16 으로(팀 TensorRT 도 FP16 + LN FP32). 학생에게 주는 토큰만 bf16.

| 검사(A2 장면 16 판 × 카메라 2 = 영상 32 장, 패치 토큰 2,048 개) | 결과 |
|---|---|
| CPU FP64 참조판 대 PyTorch FP32(open_clip, `tools/siglip_ref.py`) — 구조 확인 | 코사인 평균 1.00000000, 최저 0.99999999, 상대 L2 2.5e-5 |
| **GPU(FP16) 대 PyTorch FP32** | **코사인 평균 0.999605, 하위 1 % 0.999016** (기준 ≥ 0.999 / ≥ 0.99 통과). 최저 0.43 — 2,048 개 중 0.99 아래 5 개, 0.9 아래 1 개 |
| 같은 비교, BF16 피연산자 | 평균 0.998975, 하위 1 % 0.994, 최저 0.61 — 평균 기준 미달 |
| GPU 대 FP64(2 층 / 12 층 뒤) | 상대 오차 2.25e-3 / 9.24e-3, 바닥 2.25e-3 / 9.25e-3, **비율 1.00 / 1.00** |
| 결정성·묶음 무관 | 같은 입력 두 번 0 값 다름, 앞 6 장 따로 == 32 장 묶음 안 |
| 음성 대조(GPU 오차가 바닥의 2 배를 넘어야) | 어텐션 1/8 배율 빠뜨림 1.14, LN 평균 빼기 빠뜨림 1.16, 위치 임베딩 빠뜨림 1.32 (바닥 0.0056) — 3/3 잡힘 |
| 속도(영상 1,024 장, 그래프) | **0.199 ms/장, 5,016 장/s, 56.8 TFLOPS**(11.32 GFLOP/장). 블록 하나 16.6 ms, 패치 자르기 256 판 0.42 ms. 가중치 175 MB, 작업 공간 영상당 약 1 MB |

### 3. 학생 신경망(가정 표시)
| 부분 | 모양 |
|---|---|
| 칸 MLP·집합·X0(288) | student-lite 와 같음(지도 토큰, 몸 상태, 목표 칸 0 — 교사 특권 없음) |
| 영상 | 카메라 2 × 패치 64 = 토큰 128 × 768(얼림) → **P1: 784(768 + 편향 칸) → 16, ELU, 토큰마다 같은 가중치** → 자리 순서 그대로 펼침 2,048 (작은 공간 병목 — 평균·최댓값 집합은 컵이 영상 어디 있는지를 잃으므로 쓰지 않음, **가정**) |
| 글(지시 문장) | 문장 8 개(영 5·한 3, "go to the cup" … "머그잔 앞으로 가줘")의 얼린 SigLIP 2 글 벡터(L2 정규화 × √768) 표. 에피소드마다 에피소드 번호 해시로 하나 → 768 칸 그대로 A1 에. A2 는 과제가 하나라 지시는 뜻이 같은 바꿔 말하기(VLA_INPUT 6절 "지시 바꾸기")일 뿐 — **가정**, 여러 과제가 되면 의미가 생긴다 |
| 몸통 | A1 3,104(= 288 + 2,048 + 768) → 256 → A2 256 → A3 128 (ELU) |
| 머리 | **flow matching 행동 전문가**(VLA_INPUT 5절): E1 [몸통 128 · 1 · x_τ 32 · 시간 sin/cos 32(주기 0.004–4, π0 방식)] → 256 → 256 → 32 = **청크 16 스텝 × (vx, wz)**. 학습: τ ~ U(0,1)(가정 — π0 는 베타), x_τ = τε + (1−τ)a, 목표 u = ε − a, 손실 (1/M) Σ 가림 × (v − u)². 추론: x = ε 에서 오일러 10 스텝(τ 1 → 0), 청크 첫 행동만 실행하고 다음 스텝에 다시(가정) |
| 청크 라벨 | 같은 판의 h 스텝 뒤 표본 = 자료 고리 자리 (idx + h·N) % cap. 에피소드 번호(새로 기록하는 `d_epi`, 4 B)가 같고 에피소드 스텝이 h 만큼 뒤일 때만, 아니면 가림 0. 교사 라벨의 앞날 16 개 — DAgger 자료는 학생이 간 상태들의 교사 라벨 |
| 변수 | 1,051,392 (P1 12.5k, A1 795k, E1–E3 132k) |
| 초기화 | S1·S2·A1(X0 칸)·A2·A3 는 student-lite 와 같은 차례·규칙. 영상·글 칸은 그 칸 수를 fan-in 으로 따로 |

영상 학생도 학습 중 **얼린 인코더 앞 계산이 표본마다** 돈다(캐시 없음 — 계획서 4.6 (a)). 저장은 렌더 상태 144 B 뿐.

- 영상 학생은 **인코더가 거의 전부**다. 학생 신경망은 0.5 %. 다음 이득은 인코더(FP8, 층 줄이기·토큰 줄이기) 또는 얼린 인코더 출력의 캐시(표본마다 같은 영상 — 다만 잡음 씨앗이 묶음 자리마다 달라 지금은 완전히 같지 않음)다.
- 호스트 동기: 그래프 구조·실행 방식은 student-lite 와 같다(롤아웃·갱신 그래프를 이벤트 확인만 하며 연달아 띄움). 렌더·인코더가 그래프 안에 들어가 단계 안 동기가 늘지 않았다. 다만 이번 판에서 nsys 로 다시 재지는 않았다(구조로 판단).

### 6. 폐루프 평가 — A2, C0/C1/C2 (잰 값)
평가 틀(모든 줄 같음): 결정적 교사 / 학생(flow 는 판·스텝마다 장치 난수 ε 에서 오일러 10 스텝), 평가 씨앗 777, **판 1,024 × 12 롤아웃(앞 2 버림)**, 에피소드 약 4.3–7.3k → 성공률 표준오차 약 0.003(0.94 근처)–0.006(0.74 근처). 자료는 모두 교사 기록 16 롤아웃(1.05M 표본, 판 1,024) 뒤 DAgger 롤아웃 1 번씩(65,536 표본).
학습량 둘: "작은 예산" = BC 4,000 스텝 × mb 256(약 1 에포크) + DAgger i 마다 1,000 스텝 (영상 학생이 2–3 시간 GPU 안에 들어가는 양), "lite 예산" = student-lite 그대로(BC 6,000 × 8,192 + DAgger 2,000 스텝). 학습률 3e-4 고정(이어서 판은 1e-4). 씨앗 하나.

- **학습량이 결과를 정한다**: 영상 학생 BC 만으로는 0.740(시간초과 21 %)로 student-lite BC(0.932, 같은 자료, 학습 표본 수 48 배)보다 한참 낮다. 학생이 느리게·머뭇거리며 움직여 시간이 다 된다. lite 예산을 영상으로 하면 표본 4,900 만 × 0.47 ms ≈ 6.4 시간이라 이번 2–3 시간 GPU 안에 못 넣었다. DAgger 가 이 차이를 거의 다 메운다.
- **flow matching 대 MSE**(영상 없이 lite 예산): BC 0.885 대 0.932 — 한 스텝 결정적 회귀보다 확률적 청크 표본(ε 에서 오일러 10 스텝)이 BC 만으로는 낮고 시간초과가 많다(0.067 대 0.030). DAgger 뒤에는 0.940–0.945 로 같아진다. A2 의 교사 행동은 단봉(결정적 교사)이라 flow 의 이점(여러 봉우리)이 드러나지 않는다.
- **흔들림**: 학습률 3e-4·mb 256 에서 평가 사이 성공률이 0.03–0.3 출렁였다(영상 0.922 → 0.875 → 0.934, 대조 0.837 → 0.540). 학습률 1e-4 로 이어서는 0.934–0.946 으로 줄었다. EMA 변수(계획서 K9) 또는 학습률 줄이기가 필요(가정, 남은 일).

### 한계·가정(영상 학생)
- 씨앗 하나(학생 초기화 1, 자료 씨앗 1000/2000), 평가 판 1,024 × 10 롤아웃. 학습률·mb·스텝 수·DAgger 일정·이어서 학습률 1e-4 는 모두 **가정**. "이어서" 판은 자료 고리를 새로 채웠다(교사 기록 16 롤아웃 + DAgger 4 번, 앞 판 DAgger 자료는 없음).
- 장면은 상자(벽·가구·컵)뿐, 색·조명·카메라 FOV(손목 87°)·256² 정사각은 **가정**. 싼 설정만 썼다(spp 1 그림자 잡음 있음). 실제 카메라와의 차이(색·질감·노출)는 다루지 않았다.
- 렌더 화소 난수 씨앗이 묶음 안 자리에 달려, 같은 표본도 미니배치 자리마다 그림자 잡음이 다르다(증강처럼 작용, 같은 자리면 비트 같음 — 검증 "기록 = 본 것(영상)").
- 영상 토큰 처리는 P1(토큰마다 16) + 펼침 + MLP 다. 계획서 3절의 "트랜스포머 6–8 층 100–200M" 이 아니다. 지시 문장은 뜻이 같은 8 개뿐(과제 하나).
- 인코더 FP16 의 최저 토큰 코사인 0.43(2,048 개 중 하나) — 평균·하위 1 % 기준은 통과.
- 이번 판에서는 nsys 로 호스트 동기를 다시 재지 않았다(그래프 구조와 실행기는 student-lite 판과 같다).

## G5 첫 판 — student-lite: 작은 학생 BC 학습기(BF16)·자료 경로·DAgger (계획서 GPU_TRAINING.md 4.5·4.6·5.3·5.4·9·11절)

영상 없이 몸 상태 + 지도 토큰만 보는 학생으로 기록 → BC → DAgger → 폐루프 평가의 배관을 전부 GPU 안에서 증명한 판(커밋 31dc3f5·44b409c). 위 영상 학생은 이 위에 쌓았고, 이 절의 숫자는 그때 잰 값(판 4,096 평가 틀)이다.
지금 코드에서 영상·글·flow 를 다 끄면(`--lite`, `config/bc_a2.json`) 같은 학생·같은 V5 손실(0.905802)이다. 바뀐 것: 교사가 움직이는 롤아웃은 학생 앞 계산을 하지 않는다(그때 어긋남 기록 0, 롤아웃 50.1 → 44 ms), 표본마다 에피소드 번호 4 B 를 더 저장(1,600 B/표본).

| 몸 상태 53 + 벽 광선 16(G1 관측) | 그대로 | 그대로 |

- 신경망은 교사의 정책 사슬과 같은 모양(칸 MLP 48→64→64, 집합 128, A1 288→256 → 256 → 128 → 8)이다. 학습 변수 187,520 개. 학생은 무작위 초기화(교사 가중치를 쓰지 않음).
- 손실: MSE `(1/M) Σ_r Σ_{k<2} (μ − 라벨)²`. 계획서의 flow matching 액션 전문가·행동 청크(VLA_INPUT 5절)는 아직 아니다 — 한 스텝 결정적 회귀로 배관부터 **(가정, 남은 일 2)**.
- `student_goal: 1` 이면 학생이 교사와 같은 입력을 본다(정보 차이 없이 모방 오차만 남기는 대조).

### 자료(5.3) — 스텝마다 정책이 실제로 본 것
| 칸 | 크기 | 내용 |
|---|---|---|
| obs | 80 × bf16 = 160 B | bf16(clamp10(G1 관측)). 정책 입력이 이 값을 그대로 bf16 로 쓰므로 무손실 |
| tok | 1,280 B | 그 스텝 지도 토큰 `MapTok` 그대로(물체 칸 16 × 33 FP16, 이름·생김새 번호, 벽 56, 방, 완성도, 안 본 곳 광선) |
| lab | 2 × f32 | 교사 라벨 |
| meta | u32 | 에피소드 스텝, 처음 지도 부호, 움직인 쪽(교사/학생) |

- 장치 안 고리 버퍼(`cap` 표본, 넘치면 오래된 것부터 덮어씀). 쓰기 자리·표본 수는 장치 값(`Data`)이고 롤아웃 그래프 끝 커널이 옮긴다. 미니배치는 장치 열쇠(씨앗, 갱신 스텝, 행) 해시로 균등 복원 추출.
- 롤아웃이 교사 앞 계산(라벨)을 **같은 그래프 안에서** 늘 한다. 누가 움직이나(교사/학생)·기록하나는 장치 값 `Mode`(고정 호스트 링 → 비동기 복사)라 그래프를 다시 잡지 않는다 → 교사 기록, DAgger(학생이 움직이고 교사가 라벨), 평가가 한 그래프.
- 렌더 상태는 지도 토큰과 같은 순간(환경 스텝 뒤 = 리셋된 판은 새 판)이다. G1 관측은 "끝난 스텝" 값을 돌려주므로 리셋 직후 첫 스텝만 관측(이전 판 끝)과 토큰·렌더 상태(새 판)가 어긋난다 — 교사 PPO 와 같은 알려진 어긋남(`../RL/ppo/README.md`).
