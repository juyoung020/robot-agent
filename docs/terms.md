# 용어 정리 (물체 기억·인지)

설계를 이야기할 때 쓰는 표준 용어와 우리 코드에서 해당하는 곳이다. 임시 이름(비교 때 붙인 A/B/C, "A′")은 쓰지 않고, 이 용어와 폴더·파일 이름으로 부른다(2026-10-05).

## 장면을 나누는 말

| 용어 | 뜻 | 우리 코드 |
|---|---|---|
| **things** | 셀 수 있는 개별 물체(의자·컵·문·창·계단). 판옵틱 분할(Kirillov 외 2019)·COCO-Stuff(Caesar 외 2018)의 구분 | 물체 노드. 문·창·계단은 구조물 표시를 단 물체 노드로 남긴다 |
| **stuff** | 모양이 정해지지 않은 배경 영역(벽·천장·바닥·하늘). ConceptGraphs 는 `bg_classes`, 방 구조 추정에서는 room layout 이라 부른다 | 지도에 물체로 넣지 않는다 |
| **stuff 제거** | 분할 결과에서 벽·천장·바닥을 빼는 일 | `scenemap/src/objprob.cpp` 조각 평면 판정(아래 랜색) + `training/fastsam/`(벽·천장·바닥을 아예 자르지 않게 재학습한 FastSAM-s) |
| **things 전용 분할** | 물체만 자르고 stuff 는 배경으로 두는 분할 | 재학습 FastSAM-s `FastSAM-s-416-obj.plan` |

## 물체 지도를 만드는 말

| 용어 | 뜻 | 우리 코드 |
|---|---|---|
| **확률론적 물체 수준 매핑** (probabilistic object-level mapping) | 점·격자가 아니라 물체 하나하나를 지도 단위로 두고, 같은 물체인지·이름·특징·위치를 확률로 추정 | scenemap 확률 모드: `scenemap/src/objmap.cpp`(흐름) + `scenemap/src/objprob.cpp`(확률 모형) |
| **데이터 연관** (data association, DA) | 이번 관측(조각)이 지도의 어느 물체인지 고르기, 없으면 새 물체 | `objmap.cpp` 연결 단계. 확률 모드는 이름 없이 3D 맞닿음(가우시안) + 벡터 일치(vMF)의 베이지안 가설 검정. 옛 방식(같은 이름끼리 위치)은 `da/src/merge.cpp` 와 옛 모드 |
| **과분할 병합** (over-segmentation merging, instance fusion) | 한 물체가 여러 조각으로 잘린 것을 하나로 합치기 | `objmap.cpp` 조각 합치기·물체끼리 병합 |
| **베이지안 라벨 융합** (Bayesian label fusion) | 여러 시점의 이름 점수를 확률로 누적(SemanticFusion, McCormac 외 2017) | `objprob.cpp` 이름 사후(SigLIP 점수 + 크기 + 방), 외부 확인 `sm_observe_object_name` |
| **특징 융합** (feature fusion) | 여러 시점의 영상 벡터를 하나로 누적(ConceptGraphs 의 CLIP 특징 평균) | `objprob.cpp` vMF 누적 r ← r + κ·z, 대표 μ = r/‖r‖ |
| **vMF** (von Mises–Fisher) | 길이 1 벡터(구 위)의 가우시안 같은 분포. κ 가 클수록 한 방향에 모임 | 물체 벡터 확신 ‖r‖, 시점 신뢰 κ(`scenemap/src/bestview.cpp`) |
| **칼만 필터** | 가우시안 평균·공분산을 관측마다 갱신 | 물체 위치·크기와 그 불확실도(`pos_sd`) |
| **변화 탐지** | 물체가 사라짐·옮겨짐·생김을 판정 | `objmap.cpp` 상태(보임·옮겨짐·사라짐·들림) |

## 평면 맞추기: PCA 와 랜색

stuff 제거에서 "이 조각이 벽·천장·바닥 평면인가" 를 정할 때 조각의 3D 점에 평면 하나를 맞춘다.

| | PCA (피씨에이, 주성분 분석) | **랜색** (RANSAC, RANdom SAmple Consensus, Fischler & Bolles 1981) |
|---|---|---|
| 방법 | 점들이 가장 넓게 퍼진 두 방향 = 평면, 가장 덜 퍼진 방향 = 법선. 모든 점을 한 번에 씀 | 점 3 개를 무작위로 뽑아 평면 → 그 평면 근처(문턱 거리 안) 점 수를 셈 → 여러 번 반복해 가장 많은 점이 동의하는 평면을 고르고, 그 점들로 다시 맞춤 |
| 잡음·섞인 점 | 다 반영돼 평면이 틀어짐 | 안 맞는 점은 무시(이상치에 강함) |
| 덤 | – | **평면 비율**(점 중 몇 % 가 평면에 있나) → 굽은 물체(소파·화분)를 평면으로 착각하지 않게 거름 |
| 계산 | 한 번 | 반복 수백 번. 조각 하나는 점 수백–수천 개라 작음 |
| 비유 | 키 평균 — 농구 선수 몇 명이 섞이면 확 바뀜 | 사람이 가장 많이 몰린 키 구간 — 농구 선수는 무시 |

- **우리 결정(2026-10-05)**: `scenemap/src/objprob.cpp` 의 조각 평면 맞춤 `apPlaneFit` 을 PCA 에서 **랜색으로 교체**(추가가 아니라 바꿈). 이유: BEHAVIOR 소파 집 기록에서 비스듬히 보인 천장 조각이 PCA 로는 수평 평면으로 안 잡혀 물체 노드로 샜다(2.8 × 3.9 m "fixture" 등). 같은 입력이면 같은 결과가 나오게 난수 씨앗을 고정한다. 결과 수치는 [model_selection.md](model_selection.md) 물체 인식 절.
- **랜색을 안 쓰는 곳**: `scenemap/src/walls.cpp` 의 지도 벽선은 여러 프레임을 쌓은 2D 점유 격자에서 길고 곧은 줄을 찾는 다른 방법이다(용도: 지도·정책 벽 토큰). 그대로 둔다.
- **한 프레임 전체에 랜색을 돌려 큰 평면을 지우는 방식**(물체 SLAM·탁자 위 물체 인식에서 흔함)은 쓰지 않는다: 매 프레임 계산이 늘고, 문·창·액자가 벽과 같은 평면이라 같이 지워진다. 우리는 이미 잘린 조각마다 평면을 맞춘다.
- **랜색을 더 쓸 만한 곳(후보)**: SLAM 스캔 맞추기의 이상치 거르기(`scenemap/src/slam2d.cpp`), 실제 bag 의 카메라 높이·기울기(바닥 평면) 추정, 놓을 면(책상 윗면) 높이 찾기.
- 랜색이 흔히 쓰이는 곳(참고): 영상 특징점 짝 맞추기(호모그래피·기본 행렬, SLAM·파노라마), 점구름 정합의 초기 맞춤, 라이다 선·원 찾기, PnP 자세 추정.
