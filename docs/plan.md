# 계획 (plan)

동적 3D scene graph + AI agent + VLA(π0.5) 결합.
참고 논문·코드는 [`refs/README.md`](../refs/README.md) 참고.

## 코드 원칙

> **우리가 작성하는 모든 코드는 C++ · CUDA · Rust 로 한다.**

| 언어 | 어디에 |
|---|---|
| **C++** | ROS 2 노드(rclcpp), 3D 위치 계산, DA·맵 업데이트, Spark-DSG 연동, 추론 실행 (TensorRT 등) |
| **CUDA** | GPU 로 빠르게 해야 하는 부분 — 깊이→점구름 변환, 마스크 처리, π0.5 추론 커널 |
| **Rust** | 통신·실행 흐름 — 앱 ↔ 리모 WebSocket, agent 실행 흐름 (Qwen API 호출), 로봇 관리 |

| 예외 | 이유 |
|---|---|
| 휴대폰 앱: Swift (iOS) · Kotlin (Android) | 네이티브 앱은 각 플랫폼 언어로만 만들 수 있음 |
| 학습 (π0.5 파인튜닝, YOLO 학습) | 학습 도구(openpi, Ultralytics)가 Python. 학습 결과(모델 파일)만 가져와 C++/CUDA 로 실행 |
| 가져다 쓰는 외부 도구 | 남이 만든 도구는 원래 언어 그대로 쓴다. 가능하면 C++ 쪽을 고른다 (예: Qwen 은 llama.cpp, SLAM 은 Cartographer) |

## 전제

**기본 리모(AgileX LIMO)로 가정.**

| 항목 | 기본 LIMO (가정) |
|---|---|
| 컴퓨터 | NVIDIA Jetson Nano (4GB) |
| 라이다 | EAI X2L |
| 카메라 | Orbbec DaBai (RGB-D) |
| 로봇 팔 | 없음 |
| 매니퓰레이터 | 추가로 달 예정 — **아직 모델 모름** |
| π0.5 실행 | **웬만하면 리모에서.** 안 되면 리모에 라즈베리파이 5 + NPU(AI HAT+ 2) 포팅을 달아서 |

**학습·LLM 서버: 학교 컴퓨터 사용 가능.**

| 항목 | 사양 |
|---|---|
| GPU | NVIDIA RTX 4090 (24GB) |
| 용도 | **Qwen3.5-9B API 서버** (agent 가 호출), π0.5 파인튜닝(LoRA, 22.5GB 이상 필요). 로봇 코드는 여기서 돌리지 않음 |

## 한눈에 보기

| 어디서 | 무엇을 |
|---|---|
| 리모 (Jetson Nano) | **우리 코드 전부** — 센서 드라이버, 2D SLAM (Cartographer), YOLO-seg (TensorRT), 3D 위치 계산, DA·맵 업데이트, Spark-DSG, agent 실행, 이동, π0.5 (안 되면 라즈베리파이 5 + NPU) |
| 학교 4090 서버 | **Qwen3.5-9B API** 만 (agent 가 인터넷으로 호출) + π0.5 학습 |

| 휴대폰 앱 (iOS·Android) | 카카오톡처럼 채팅으로 로봇에게 명령 → 리모의 agent 로 전달 |

부품별 선택 이유는 [`model_selection.md`](model_selection.md).

## 1. Scene graph (로봇의 기억) — `src/scene_graph/`

| 할 일 | 내용 | 담당 |
|---|---|---|
| SLAM | 리모에서 **2D 라이다 SLAM (Cartographer)** 으로 지도 한 번 만들고, 평소엔 위치만 추정 | |
| 물체 인식 (YOLO-seg) | **리모(Jetson Nano)에서 실행.** 가장 작은 모델(nano)을 TensorRT FP16 엔진으로 바꿔 C++ 로 돌리기. 카메라 영상에서 물체 영역(mask)과 이름을 한 번에 얻기 | |
| 3D 위치 계산 | 리모에서. 마스크 픽셀 + depth → 카메라 좌표 → 로봇 좌표 → 월드 좌표 (tf2). 마스크를 살짝 줄이고 **중앙값**으로 물체 위치 하나 뽑기 | |
| DA (data association) | 새로 본 물체가 그래프에 이미 있는 물체인지 판단. **자체 제작**, 같은 이름끼리 위치로 비교 | |
| 맵 업데이트 | 옮겨짐·사라짐·생김을 찾아 바뀐 부분만 고치기. **자체 제작**, 변화 탐지 P/R/F1 로 평가 | |
| 저장·보기 | **Spark-DSG** 로 저장, `spark-dsg visualize` 뷰어로 확인. agent 에는 JSON 으로 넘기기 | |

## 2. 로봇

| 할 일 | 내용 | 담당 |
|---|---|---|
| 리모 ROS 2 포팅 찾기 | 기본 리모는 Ubuntu 18.04 (ROS 1). **이미 ROS 2 로 포팅된 것을 찾아 쓴다** — 후보는 [`refs/README.md`](../refs/README.md) 의 "리모 ROS 2" (공식 agilexrobotics/limo_ros2 의 foxy·humble 브랜치, Docker 판 등). 우리 리모(Jetson Nano)에서 되는지 확인 | |
| 캘리브레이션 | 카메라 내부 값(intrinsic), 카메라가 로봇 몸체 어디에 달렸는지(extrinsic) → 3D 위치 계산에 필요. 팔이 정해지면 hand-eye 도 | |
| 좌표 사슬 (tf) | `map → base_link → camera` 가 제대로 나오는지 확인. depth 를 컬러에 맞춰 정렬(align) | |
| 네트워크 | 리모 → 4090 은 Qwen API 호출(글자)만. 영상은 보내지 않음 | |
| 이동 | 저장한 2D 지도 위에서 목표 위치로 이동 (내비게이션) | |
| 조작 | 매니퓰레이터 모델이 정해지면 ROS 2 로 움직이기, 집기·놓기 확인 | |
| pose 토픽 따두기 | 로봇·팔 끝(end-effector)·카메라 pose 토픽 이름, 메시지 타입, 주기 정리 | |
| ros2 bag 녹화 | 카메라(RGB·depth)·pose·관절 상태 녹화 → 오프라인으로 scene graph·VLA 실험. 녹화 스크립트는 `scripts/` | |
| 사양 문서 | 로봇·센서 사양, 토픽 목록 → `docs/` | |

## 3. VLA (π0.5) — `src/vla/`

| 할 일 | 내용 | 담당 |
|---|---|---|
| 리모에서 실행 | **웬만하면 리모(Jetson Nano)에서** π0.5 돌리기. 양자화 + C++/CUDA 로 | |
| (안 되면) 라즈베리파이 5 + NPU | 리모에 라즈베리파이 5 + AI HAT+ 2 (Hailo-10H) 를 달고 π0.5 포팅 | |
| 시뮬레이션 평가 | **2025 BEHAVIOR Challenge 벤치마크** (BEHAVIOR-1K, OmniGibson) 로 평가, 대회 상위 팀 점수와 비교 | |
| 파인튜닝 (시뮬) | BEHAVIOR 대회 데이터(축소판 약 260GB) + 공개 체크포인트(1·2위 팀)에서 시작해 4090 LoRA 학습 | |
| 파인튜닝 (실제) | 리모로 모은 시연 데이터로 따로 학습 (BEHAVIOR 로봇과 몸이 달라서) | |
| 양자화 | 리모(또는 라즈베리파이 5·NPU)에 올라가게 메모리·속도 줄이기 | |
| 지시 형식 맞추기 | agent 가 주는 단계 지시(subtask) 형식에 맞추기 | |

## 4. Agent (계획·실패 복구) — `src/agent/`

| 할 일 | 내용 | 담당 |
|---|---|---|
| LLM 서버 | 학교 4090 에 **Qwen3.5-9B** API 서버 띄우기. 리모의 agent 가 호출 | |
| 작업 나누기 | scene graph(JSON)를 읽고 "컵을 식탁에" → 이동·집기·이동·놓기 로 나누기 | |
| 실행·복구 | 단계마다 이동(로봇) 또는 VLA 호출 → 성공 여부 확인 → 실패하면 재계획 (참고: BEHAVIOR 3위 SimpleAI 논문) | |
| 평가 세트 | 명령 10~20개로 계획 성공률·응답 시간 재기 | |

## 5. 앱 (채팅으로 로봇 부리기) — `src/app/`

카카오톡처럼 채팅 목록에 로봇이 친구처럼 보이고, 채팅방에서 말로 명령한다. **지금은 로봇1 만** 있다 (나중에 로봇2, 로봇3 … 을 추가할 수 있게 구조만 열어 둔다).

```
┌ 채팅 ─────────────┐     ┌ 로봇1 ──────────────────────┐
│ 🤖 로봇1          │ ──▶ │            컵 식탁에 갖다 놔 │  ← 나
│   컵을 식탁에 놨어요│     │ 컵 위치로 이동 중이에요        │  ← 로봇1
└──────────────────┘     │ 컵을 집었어요                 │
                          │ 컵을 식탁에 놨어요 ✅          │
                          └─────────────────────────────┘
```

| 할 일 | 내용 | 담당 |
|---|---|---|
| iOS 앱 | 네이티브 (Swift / SwiftUI) | |
| Android 앱 | 네이티브 (Kotlin / Jetpack Compose) | |
| 채팅 목록 | 카카오톡 형식. 로봇1 한 명만 표시, 로봇 목록을 따로 관리해서 나중에 추가 쉽게 | |
| 채팅방 | 명령 보내기, 로봇의 진행 상황(단계별 메시지)·성공/실패 받기. "컵 어디 있었지?" 같은 질문도 | |
| 로봇 연결 | 앱 ↔ 리모의 agent 를 WebSocket 등으로 연결. 학교 밖에서 접속하려면 VPN 등 접속 방법 정하기 | |
