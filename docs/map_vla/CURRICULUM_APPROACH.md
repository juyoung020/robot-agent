# 커리큘럼 1: 이동 — "컵으로 가" (approach)

작성 2026-10-03. **설계 문서**다. 코드는 아직 없다. 집기·놓기(pick & place)까지 가르칠 것이고, 그 첫 단계로 **물체 앞까지 가서 카메라로 정면에 두는 것**부터 학습한다.
정책 전체 구조는 [POLICY.md](POLICY.md), 입력은 [VLA_INPUT.md](VLA_INPUT.md), GPU 학습 고리는 [GPU_TRAINING.md](GPU_TRAINING.md), 지표를 보는 화면은 [TRAIN_VIEWER.md](TRAIN_VIEWER.md).

## 0. 과제

- 지시: "컵으로 가"(교사: 목표 물체 표시 + 스킬 `approach`, 학생: 단계 문장).
- 해야 할 것: 목표 물체 **근처까지 가서**, 리모 앞 카메라가 물체를 **정면으로** 보게 서고, 멈춘다.
- **중간에 무엇이든 부딪히면 실패**(바닥 말고 모든 접촉 — 벽·가구·다른 물체·목표 물체 자체).
- 이 단계는 **몸통(바퀴)만** 움직인다. 팔은 접은 자세로 고정(행동의 팔 5 + 그리퍼 1 = 고정값). 다음 커리큘럼(집기)에서 팔을 연다.

## 1. 성공·실패

| 판정 | 조건 | 비고 |
|---|---|---|
| **성공** | 아래를 **1 s 동안 함께** 지킴 → 판 끝 | |
| ├ 가까움 | 몸통 앞(카메라)에서 물체 겉면까지 수평 거리 0.4–0.8 m (추정) | 너무 붙어도 안 됨(다음 단계 집기 자세) |
| ├ 정면 | 앞 카메라 광축과 물체 중심 방향의 수평 각도 ≤ 10° (추정) | "에임" |
| ├ 보임 | 물체 중심이 카메라 영상 안 + 깊이로 가리지 않음 | 등지고 서면 실패 |
| └ 멈춤 | 몸통 속도 ≤ 0.05 m/s, 회전 ≤ 5 °/s | |
| **실패: 충돌** | 로봇 링크가 바닥 말고 무엇이든 닿음 → **즉시 판 끝** | 시뮬 접촉 정보(`RigidContactAPI` 같은 것) |
| **실패: 시간 초과** | 시간 예산 = 최단 경로 길이 / 0.3 m/s + 10 s (추정) | |
| **실패: 놓침** | 목표가 지도에서 사라짐(사라짐 판정) 또는 판정 불가 | 드묾 |

## 2. 보상 (POLICY 3.3.1 원칙: 줄어든 양, 성공 한 번, 벌점 작게)

| 항 | 식 | 무게 (추정) |
|---|---|---|
| 다가가기 | (이전 **경로 거리** − 지금 경로 거리) | × 5 |
| 에임 | (이전 에임 각도 − 지금 에임 각도), **경로 거리 1.5 m 안에서만** | × 2 (rad 단위) |
| 보임 | 처음으로 카메라에 들어온 순간 한 번 | +1 |
| **성공** | 1절 성공 | **+10 + 5 × 정면 정도**(cos 에임) |
| **충돌** | 닿는 순간 | **−10, 판 끝** |
| 장애물 가까움 | 몸통 둘레 가장 가까운 장애물 < 0.15 m 일 때, (0.15 − 거리) × 속도 | × −1 |
| 덜컥임 | ‖이번 행동 − 직전 행동‖² | × −0.01 |
| 시간 | 매 스텝 | −0.01 |

- **경로 거리**(점유 격자 위 최단 경로 길이, 몸통 반지름만큼 부풀린 장애물 기준)를 쓴다. 직선 거리를 쓰면 벽 너머 물체 쪽으로 붙어서 멈춘다(지역 최소).
  - 경로 거리는 **정책이 아는 지도**(그 순간 자란 지도)로 계산한다. 아직 지도에 없는 길은 모른다.
- 에임은 가까워진 뒤에만 준다. 멀리서부터 물체만 바라보면 길을 못 찾는다.
- 충돌은 무겁게, 장애물 가까움은 가볍게 → 피하되 좁은 문은 지나가게.

## 3. 관측·행동 (이 단계)

- 관측: [VLA_INPUT.md](VLA_INPUT.md) 그대로(교사는 영상 없이). 이 단계에서 특히 쓰는 것: 목표 물체 칸(로봇 기준 xyz·거리·방향·보임/기억·불확실도), 벽 상태 56(16 방향 거리), 다음 경유 지점(경로의 다음 점, 로봇 기준), 몸통 속도.
- 행동: 몸통(vx, wz) 2 만 학습. 팔·그리퍼는 고정. 10 Hz.
- 안전: `move_robot` 속도 한도(베이스 0.5 m/s, 50 °/s — go_to 와 같은 한도)를 넘는 값은 잘린다.

## 4. 커리큘럼 단계

| 단계 | 장면 | 시작 | 지도 | 넘어가는 기준 |
|---|---|---|---|---|
| **A0** | 빈 방(가구 없음), 목표 하나 | 목표까지 1–2 m, **정면 근처**(±45°) | 다 앎 | 성공률 ≥ 90 % |
| **A1** | 빈 방 | 1–3 m, **방향 무작위**(등진 채 시작 포함) | 다 앎 | ≥ 90 % |
| **A2** | 가구 몇 개(목표와 로봇 사이 장애물) | 2–4 m | 다 앎 | ≥ 85 %, 충돌률 ≤ 5 % |
| **A3** | BEHAVIOR 집 한 방, 실제 배치 | 같은 방 아무 데 | 다 앎 + `slam` 잡음 | ≥ 85 % |
| **A4** | 집 전체, 문 지나기 | 다른 방(4–10 m) | **반쯤** 앎(목표는 지도에 있음) | ≥ 80 % |
| **A5** | 집 전체 | 다른 방 | **오래된 지도**(물체 몇 개 옮겨짐) + 센서 잡음 + 물리 무작위화 | ≥ 80 % |

- 넘어가는 기준은 그 단계 **최근 1,000 판** 기준. 다음 단계에서도 앞 단계 판을 **20 %** 섞어 잊지 않게 한다 (추정).
- 목표가 지도에 아직 없으면(빈 지도) 이 스킬이 아니라 **탐색**(`explore` 스킬·`move_robot` `probe`)이 먼저다. 목표가 지도에 들어온 뒤 approach 가 맡는다([POLICY.md](POLICY.md) 1.2 역할 나누기).
- 멀리 가기(A4·A5)를 VLA 가 할지, `move_robot` `go_to` 로 근처까지 가고 VLA 는 마지막 1.5 m 만 할지는 A3 결과를 보고 정한다(POLICY 1.2 는 후자를 제안).

## 5. 지표 (학습 뷰어에 띄울 것)

행동 학습에서 "끝까지 해냈나" 는 F1 이 아니라 아래로 잰다. F1 은 지도 변화 맞히기(동적 물체 벤치마크) 같은 **분류**에 쓰는 지표다.

| 지표 | 식 | 뜻 |
|---|---|---|
| **성공률 (SR)** | 성공 판 / 전체 판 | 끝까지 해냈나 |
| **충돌 없는 성공률** | 충돌 0 인 성공 / 전체 | 이 과제는 충돌 = 실패라 SR 과 같아야 한다(다르면 판정 버그) |
| **SPL** (Success weighted by Path Length) | 평균 S × L* / max(L, L*) — S 성공 0/1, L* 최단 경로, L 실제 간 길이 | 성공했어도 돌아가면 깎인다. 내비게이션 표준 지표(Anderson et al. 2018) |
| **Soft SPL** | 실패도 얼마나 다가갔나로 부분 점수 | 초반 학습 진행을 보기 좋음 |
| 충돌률 | 충돌로 끝난 판 / 전체 | |
| 시간 초과율 | | |
| 끝 자세 오차 | 성공 판의 마지막 거리·에임 각도 분포 | 다음 단계(집기) 시작 자세 품질 |
| 걸린 시간 | 성공 판의 시간, 최단 경로 대비 | |

- 표로: **단계(A0–A5) × 집(학습 집 / 안 쓴 집) × 지도 완성도**마다 SR·SPL·충돌률, 최근 N 판 슬라이더([TRAIN_VIEWER.md](TRAIN_VIEWER.md) 6.2 표와 같은 방식).
- 집기·놓기까지 이어지면: **과제 전체 성공률**(가기 → 집기 → 놓기 끝까지) + **단계별 성공률**(어디서 실패했나) + **부분 점수**(BEHAVIOR 의 q_score 처럼 몇 단계까지 했나).

## 6. 다음 커리큘럼

1. **이동(이 문서)** → 2. **집기**(이 단계 성공 자세에서 시작, 팔 열기) → 3. **들고 이동**(물체를 든 채 approach, 충돌 기준에 든 물체 포함) → 4. **놓기** → 5. **이어서 하기**("컵을 식탁에 갖다 놔" — LLM 이 단계를 이어 줌).
