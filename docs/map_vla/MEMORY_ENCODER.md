# 기억 인코더 — 물체가 몇 개든 로봇 두뇌에는 늘 같은 개수로

처음 보는 사람을 위한 설명이다. 자세한 사양은 [MAPVLA_SPEC](MAPVLA_SPEC.md) 2.8절, 물체 정보는 [VLA_INPUT](VLA_INPUT.md) 3절.

## 1. 왜 필요한가

로봇은 집을 돌아다니며 본 물체를 기억한다(scenemap 물체 기억 — 실제 로봇 데이터 한 판에 약 120 개). 이 기억을 보고 "펜 집어" 같은 일을 해야 한다.

문제: 로봇 두뇌(RecallVLA 의 언어 몸통 Qwen3.5-0.8B, RL 교사의 MLP)는 **입력 칸 수가 정해져 있다**. 물체가 3 개일 때와 300 개일 때 입력 길이가 달라지면 안 된다.

그래서 **물체가 몇 개든 늘 32 개의 요약 토큰으로 줄이는 장치**를 둔다. 이것이 기억 인코더다.

```
기억의 물체 N 개 ──▶ [기억 인코더] ──▶ 기억 토큰 32 개 + 정밀 칸 8 개 ──▶ 로봇 두뇌
(N = 3, 120, 256 …)                     (N 과 상관없이 늘 같은 개수)
```

## 2. 물체 하나에 들어가는 정보 (289 개 값)

| 묶음 | 예 |
|---|---|
| 나와의 상대 위치 | 물체 − 로봇 xyz 차이(로봇 앞이 x), 거리·방향, 손끝과의 xyz 차이·거리, 팔이 닿는지 |
| 물체 상태 | 크기, 옮겨진 양, 속도, 보임/사라짐/옮겨짐/들고 있음, 마지막으로 본 뒤 시간, 위치 불확실도, 같은 방인지, 목표인지 |
| 무엇인가 | 이름 뜻 벡터 128(이름을 SigLIP 2 글 인코더로), 생김새 벡터 128(물체 사진을 SigLIP 2 영상 인코더로), 이름 확신도 |

지도 좌표나 물체 번호는 넣지 않는다 — 어느 집에서든 같은 뜻이 되게.

## 3. 어떻게 줄이나 — 작은 예

물체 3 개, 질문 2 개로 줄여서 본다(실제는 질문 32 개).

**① 물체마다 벡터 하나로** — 모든 물체에 같은 작은 신경망 φ(물체 인코더)를 쓴다.
```
펜  (앞 1 m)  → φ → a
컵  (앞 3 m)  → φ → b
소파(옆 2 m)  → φ → c
```

**② 학습된 "질문" 이 물체 전부를 본다** — 질문은 신경망이 아니라 학습된 숫자 벡터다. 지시("펜 집어")의 뜻을 질문에 더해 지금 과제에 맞춘다.
```
질문 1 ("집어야 할 것은?")   점수:  펜 0.90  컵 0.08  소파 0.02
질문 2 ("부딪힐 큰 것은?")   점수:  펜 0.05  컵 0.15  소파 0.80
```

**③ 점수대로 섞은 것이 요약 토큰**
```
토큰 1 = 0.90·a + 0.08·b + 0.02·c   ≈ "앞 1 m 에 펜"
토큰 2 = 0.05·a + 0.15·b + 0.80·c   ≈ "옆 2 m 에 소파"
```

물체를 버리거나 32 개를 뽑는 게 아니다. **질문마다 물체 전부를 보고, 관련 있는 것을 많이 섞는다.** 질문이 32 개라 토큰도 늘 32 개. (이 계산을 교차 어텐션이라 부른다. 실제로는 "교차 어텐션 → 토큰끼리 섞기(자기 어텐션) → 작은 MLP" 묶음을 2 번 거친다.)

**④ 정밀 칸 8 개** — 요약은 섞인 값이라 흐리다. "집을 것"·"놓을 곳" 질문의 점수가 높은 물체와 들고 있는 것·목표, 합해서 8 개는 섞지 않은 그 물체 값을 그대로 한 번 더 넣는다. 위 예에서는 펜.

## 4. 질문은 누가 정하나 — 학습

사람이 "펜이 중요하다"고 정하지 않는다. φ, 질문, 점수 매기는 법 모두 학습된다.
- 교사의 행동을 따라 하려면 펜 위치가 필요하다 → 질문이 펜 같은 것에 높은 점수를 주도록 저절로 바뀐다.
- "집을 것"·"놓을 곳" 질문은 따로 "정답 물체에 1 등 점수를 줘라"(검색 손실)로 더 확실히 가르친다.
- 기억에 정답이 없으면 "기억에 없음" 칸이 1 등이 되게 가르친다 → 그때 로봇은 탐사하러 간다.

## 5. 크기와 계산

| | RecallVLA(학생) | RL 교사 |
|---|---|---|
| 기억 인코더 개수 | 1 개(모든 물체가 같은 φ 를 반복해서 씀) | 1 개 |
| 학습 변수(파라미터) | 약 42M(φ 1.4M + 잠재 시작 0.17M + 블록 2 개, 계산값 — TRAINING_DESIGN 2.1) — 전체 약 0.985B 의 약 4 % | 폭 64 라 훨씬 작음 |
| 스텝마다 계산 | φ 를 물체 수(N)만큼 + 점수 32 × N 개 | 같음 |
| 구현 | `training/vla`(`VCfg::mem`)에 구현·검증됨 | 구현 예정 |

물체가 늘면 **계산이 물체 수에 비례해 는다**(점수를 전부 매겨야 1 등을 안다). 그래서 상한을 둔다.

## 6. 상한 256 과 고르는 규칙 (결정 2026-10-06)

- 인코더에 넣는 물체는 **최대 256 개** — 교사·학생·실제 로봇 모두 같다(학습과 실행이 같게).
- 넘으면 인코더 **앞에서** 정해진 규칙으로 256 개를 고른다(학습된 점수는 인코더 안에서만 쓸 수 있으므로):
  1. 목표 물체, 들고 있는 물체 — 늘 넣음
  2. 로봇과 같은 방
  3. 로봇에서 가까운 순
  4. 최근에 본 순
- 집 한 채는 수십~수백 개라 이 안에 든다. 훨씬 많아지면(건물 전체) 검색 색인(`sgsearch`)으로 지시와 가까운 후보만 꺼내 넣거나, 방마다 먼저 요약하는 2 단 구조로 바꾼다.

## 7. 교사와 학생이 같은 틀 (결정 2026-10-06)

- RL 교사(시뮬에서 먼저 과제를 배우는 정책)와 RecallVLA(교사를 모방학습하는 학생)가 **같은 기억 인코더 틀**로 같은 기억을 본다. 다른 것은 크기(폭)뿐이다.
- 이유: 교사가 일부 물체만 보면, 학생이 기억으로 아는 먼 물체를 교사는 몰라 교사의 시연을 학생이 흉내 내기 어렵다.
- 지금 교사는 기억 중 16 개(목표 + 가까운 순)만 보는 옛 구조이고, 같은 틀로 바꾸는 작업은 [training/curriculum](../../training/curriculum/README.md) "교사 기억 인코더" 에 계획이 있다.

## 8. 기술 상세 (표준 용어)

구현 기준: `training/vla/src/model.cu`(`VCfg::mem`), 검증 `tools/vla_verify.cu --mem`, 설계 [TRAINING_DESIGN](TRAINING_DESIGN.md) 2–3절.

### 8.1 구조 — Perceiver 류 잠재 교차 어텐션

입력 집합 X = {x_1 … x_N}(N ≤ 256, 물체 칸 304 = 289 + 표시·편향)을 고정 크기 잠재 배열 Z ∈ R^{M×H}(M = 32, H = 1024)로 요약한다. Perceiver(Jaegle 외 2021)·Set Transformer 의 PMA(Lee 외 2019)와 같은 꼴이다.

| 단계 | 식 | 크기(학생) |
|---|---|---|
| 물체 인코더 φ(공유 MLP, per-element) | e_j = W₂·GELU(W₁ x_j) | 304 → 1024 → 1024 |
| 잠재 초기화 + 지시 조건 | Z⁰ = Z_learned + 1·(W_i u)ᵀ, u = 지시 벡터 | Z_learned 32 × 1024, W_i 136 → 1024 |
| 블록 ℓ = 1, 2 (pre-norm) | ① 교차 어텐션 Z ← Z + MHA(Q = RMSNorm(Z)W_q, K, V = RMSNorm(E)W_k, W_v ∪ {k_∅, v_∅}) ② 자기 어텐션 Z ← Z + MHA(Z, Z, Z) ③ 피드포워드 Z ← Z + SwiGLU(RMSNorm(Z)) | 머리 16 × 64, FFN 4096 |
| 출력 | 기억 토큰 = RMSNorm(Z) — 몸통 입력 열 32 개 | 32 × 1024 |

- **어텐션 모양**: 교차 어텐션의 점수 행렬은 머리마다 M × (N + 1) = 32 × 257 — 질의(잠재)가 열쇠(물체)를 본다. 물체끼리의 자기 어텐션(N × N)은 하지 않는다. 자기 어텐션은 잠재끼리 32 × 32.
- **가림(mask)**: 판마다 유효 물체 수 n_b 까지만 열쇠로(빈 줄은 가림). 끝에 **null 열쇠·값(k_∅, v_∅, 블록마다 학습)** 하나를 늘 붙여 n_b = 0 이어도 softmax 가 정의된다.
- **순서 불변(permutation invariance)**: 물체에 위치 부호가 없고 어텐션 합은 순서와 무관 → 물체 순서를 바꿔도 출력이 같다. 잠재 32 개는 순서가 고정이다.
- **복잡도**: 블록당 O(M·N·H)(교차) + O(M²·H)(자기). N 에 선형. φ 는 O(N·304·H).

### 8.2 정밀 칸 — 이산 top-k 선택

잠재 0·1 을 검색 질의(q_pick, q_place)로 정해 두고, 그 교차 어텐션 로짓으로 물체를 고른다. 판마다 순서대로 min(8, n):
1. 들고 있는 물체 → 2. 목표 칸 물체 → 3. 에이전트 힌트 → 4. (학습 일정) 정답 끼워 넣기 →
5. q_pick·q_place 로짓 상위를 번갈아, **null 로짓보다 클 때만** → 6. 가까운 순(경로 거리).
고른 물체는 같은 φ 로 다시 토큰(정확한 값). 고르기 자체는 미분 불가(top-k)라 기울기는 φ·검색 손실·몸통 경유로 흐른다.

### 8.3 학습 신호

| 손실 | 무엇을 | 식 |
|---|---|---|
| 단계 문장 CE | 몸통 → 기억 토큰으로 역전파 | 다음 단계 문장 토큰의 교차 엔트로피 |
| 검색 InfoNCE | q_pick·q_place 가 정답 물체를 1 등으로 | −log softmax_j(ℓ_j)[정답], 후보 = 유효 물체 + null(못 봤으면 정답 = null) |
| 있음 BCE | 정답이 기억에 있는지 | q_pick·q_place 토큰 → 선형 → 로짓, 이진 교차 엔트로피 |

flow matching 행동 손실은 KI(knowledge insulation)로 몸통 K·V 에서 끊겨 기억 인코더에 가지 않는다.

### 8.4 교사(PPO) 판 — 계획

같은 구조, H = 64 · 머리 4 · FFN 256(작게), φ = 지금 칸 MLP(304 → 64 → 64, ELU). 출력 32 × 64 + 정밀 8 × 64 를 펴서 MLP 몸통 입력에. 행동자·가치 망이 같은 인코더를 쓸지(공유) 따로 둘지는 구현 때 정한다.

### 8.5 상한·앞 거름망

N ≤ 256 은 메모리·학습 = 실행을 위한 상한이다(계산은 N 에 선형이라 1000 도 가능). 넘으면 인코더 앞에서 규칙으로 고른다(6절). 기억이 훨씬 커지면(10⁵ 이상) 근사 최근접 검색(ANN, `sgsearch` 색인)으로 후보를 뽑거나 방·구역별 계층 요약으로 바꾼다 — 그때도 인코더 안 계산은 후보 수에만 비례한다.

## 9. 자주 묻는 것 (2026-10-06 질의응답)

| 물음 | 답 |
|---|---|
| 1000 개 중 32 개를 뽑나? | 아니다. 32 는 물체가 아니라 잠재(질의) 수다. 질의마다 물체 **전부**에 점수를 매겨 가중합한 것이 기억 토큰. 실제로 물체를 고르는 것은 정밀 칸 8 개뿐(8.2). |
| 기억 인코더가 몇 개인가? | 1 개. 질의 32 개는 신경망이 아니라 학습된 벡터(32 × 1024). φ 하나를 물체마다 반복해 쓴다. |
| 물체가 늘면 입력이 늘어나나? | 몸통 입력은 늘 32 + 8. 늘어나는 것은 φ 반복 횟수와 어텐션 점수 수(N 에 선형). |
| 상위 8 개를 고르려면 전부 계산해야 하나? | 그렇다. 점수는 N 개 전부 매긴다. 그래서 상한 256 과 앞 거름망(6절)을 둔다. 10⁸ 같은 규모면 ANN 색인·계층 요약(8.5). |
| 256 × 256 어텐션인가? | 아니다. 32 × (N + 1) 교차 + 32 × 32 자기. 물체끼리는 서로 보지 않는다. |
| 이름만 들어가나? 나와의 거리는? | 물체 칸에 나와의 xyz 차이(로봇 기준 위치)·거리·방향·손끝 기준 위치까지 들어간다(2절). |
| 중요한 것은 누가 정하나? | 인코더 안: 학습된 어텐션(8.3 손실로). 인코더 앞 256 거름망: 정해진 규칙(6절). |
