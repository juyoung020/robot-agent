# 정책 설계 — RL 교사와 VLA 학생 (리모 + OMX-F)

작성 2026-10-03. **설계 문서**다. 구현된 것: 교사 PPO(approach A0–A2, `training/RL/ppo`)·대본 특권 교사(B4–B6, 4.8)·작은 학생 BC/DAgger(`training/BC`)·RecallVLA 학습기(`training/vla`), 실행기 접점(1.2·1.3)과 안전 거르개·끝 조건(7.1·7.2, 10-04) — 1.4 "구현 상태". 남은 일은 [TODO_TRACKER.md](TODO_TRACKER.md) 2절.
입력·출력은 [VLA_INPUT.md](VLA_INPUT.md) 에서 정했다. 이 문서는 그 입력·출력을 쓰는 **정책 두 개**(RL 교사, VLA 학생)와 학습 순서를 정한다.
GPU 학습 시스템(커널 합치기, FP8, GPU 환경 안에서 지도 만들기)은 [GPU_TRAINING.md](GPU_TRAINING.md)(작성 중)에 둔다. 여기서는 되풀이하지 않는다.

- 재지 않은 숫자는 **(추정)** 이라고 적었다. 사용자가 정할 것은 9절에 모았다.
- 지금 있는 코드에 대한 말은 직접 읽고 확인한 것만 적었다(파일 경로를 붙임).

## 0. 한눈에

| 층 | 누가 | 주기 | 하는 일 |
|---|---|---|---|
| 큰 계획 | LLM(Qwen3.5-9B, KAU API) + Rust 상태 기계 | 명령마다 1–3 번 | 단계 계획(`set_plan`), 확인·복구 한도 넘으면 다시 계획 |
| 단계 실행 | **VLA 학생**(조작 단계) 또는 `move_robot`(이동·탐사) | 10 Hz, 묶음 | 단계 문장 하나를 끝까지 한다 |
| 안전 | `move_robot` 닫힌 고리 | 매 스텝 | 관절 한계·속도·충돌 정지·막힘 판정 |

학습 순서(최종):

```
① RL 교사(시뮬, 작은 망, 특권 정보, 영상 없음)
      │  교사 궤적 + 학생 관측 렌더
      ▼
② 학생 VLA 모방학습(BC) → DAgger(교사가 다시 정답 붙임) + 다른 데이터 섞기
      ▼
③ 학생 VLA RL 미세조정(시뮬, 잊지 않게 묶어서)
      ▼
④ 실제 로봇 미세조정(텔레옵 시연)
```

## 1. 정책이 놓이는 자리

### 1.1 지금 있는 것 (확인함)

- 에이전트 계획([src/agent/plan.md](../../src/agent/plan.md) 2.4·3.3): LLM 은 이동·스킬 도구를 직접 쓰지 않고 `set_plan` 으로 단계 목록을 넘긴다. 단계 문장은 Rust `skillspec::render()` 한 곳에서 만든다(숫자 거리·각도 금지).
  같은 문서 2.4 표 D(리모): `move to` 는 **Nav2 제어기**, `pick up`·`place` 는 VLA.
- `move_robot`([src/agent/tools/README.md](../../src/agent/tools/README.md)): 베이스 `go_to`(아는 빈칸 Dijkstra + DWA), `probe`, `delta`, 관절 `absolute`/`delta`. 안전 한계는 `Safety::default`.
  **지금 부분(part)과 한계는 R1 Pro 기준**이다(`left_arm` 7 관절, `r1pro.urdf` 한계). 리모 + OMX-F 용 부분은 아직 없다. **(10-04 바뀜)** 리모 + OMX-F 몸·한계·순기구학은 `limo.rs`(`d4e8bd7`) — VLA 실행기·거르개가 씀(1.4). LLM 도구 `move_robot` 의 리모 팔·그리퍼 부분은 아직 없다(1.4 끝).
- 탐사 스킬([skills/explore](../../src/agent/skills/explore/README.md)): LLM 이 `move_robot` 의 `go_to`·`probe` 만 써서 두 집에서 접촉 0, 덮음 0.94–0.95(시뮬, `SGRT_POSE=gt`). 닫힌 문 뒤 방은 "VLA 실행기 몫" 으로 남겼다.
- 실행기 전환 접점(`src/behavior-2026/src/sim/explore/run_explore.py`, [decision_log.md](../../src/agent/decision_log.md)):
  도구 호출 `{"executor":"vla","skill":"<문장>","max_s":20}` 이 오면 `act()` 를 π0.5 엔진으로 넘긴다. **(10-04 바뀜)** 이것은 서브모듈의 R1 경로만이다 — 우리 VLA 는 π0.5 를 쓰지 않고, 리모 경로는 1.3·1.4 의 `libmove_robot` 실행기다.
  - 끝 조건은 **스텝 수뿐**이다(`max_s × 30` 스텝 뒤 `{"status":"done"}`). 성공·실패 판정은 없다.
  - VLA 가 도는 동안 `move_robot` 은 `tick` 으로 관측만 하고, **VLA 행동은 `move_robot` 을 거치지 않고** 시뮬로 바로 간다.
  - 끝나면 `move_robot` 을 `reset` 한다. 가중치가 없으면 `{"status":"unavailable"}`.

### 1.2 단계 종류 → 실행기 (제안)

> **결정 2026-10-05 (사용자)**: **탐사·먼 이동·찾기도 VLA 가 스스로 한다.** VLA 학습·설계는 에이전트를 전제로 하지 않는다(에이전트와는 양방향 보완 — 있으면 힌트·대화, 없어도 VLA 혼자 완수). 아래 표의 "탐사·먼 이동 = `move_robot`" 는 대체 실행기로만 남고, B1(집 안 이동)·B2(찾기)·기억 능력 판 A–D(CURRICULUM 3.3)는 VLA 학습 범위다. 탐사할 곳은 코드가 정해 주지 않는다 — VLA 가 상태(탑뷰의 미탐사, 방 항목의 탐사 비율, 탐사 경계 후보)를 보고 고른다(VLA_INPUT 4 절).

> **결정 2026-10-04 (RecallVLA, π0.5 꼴 — [MAPVLA_SPEC.md](MAPVLA_SPEC.md) 결정 기록·2.6절)**: 에이전트는 사람과 대화하고 **전체 목표 + 물체 id** 를 VLA 에 넘기며 결과를 사람에게 알린다. 단계로 쪼개지 않는다. RecallVLA 가 한 모델 안에서 추론마다 다음 단계 문장(이동·찾기·다가가기·집기·놓기)을 고르고 그 단계로 행동을 낸다 — 지도 기억이 입력이라 다른 방·안 보이는 물체로 가는 단계도 VLA 가 고른다. 아래 표(단계마다 실행기를 나눔)는 그 전 설계이고, `move_robot` `go_to`·`probe` 는 대체 실행기·RL 교사 쪽 기준으로 남는다. 바꾸는 구현은 후속 작업(MAPVLA_SPEC 9절).


| 단계(skillspec) | 실행기 | 이유 |
|---|---|---|
| 탐사, 방·프런티어로 가기 | `move_robot` `go_to`·`probe` | 이미 접촉 0 으로 돈다. 지도 전체가 필요한 긴 경로는 VLA 가 잘하는 일이 아니다 |
| `move to {물체/가구}`(먼 거리) | `move_robot` `go_to`(리모: Nav2 같은 층) | plan.md 2.4 D 와 같다. 물체 앞 **약 1–1.5 m** 의 아는 빈칸까지(추정) |
| 마지막 다가가기(물체 1.5 m 안) | **VLA** (`approach` 를 `pick` 등의 앞부분으로 포함) | 팔이 닿는 자리·방향은 물체 생김새·받침에 달림. 베이스 2 + 팔 5 를 같이 써야 한다 |
| `pick up {obj} from {support}` | **VLA** | 접촉·미끄러짐·다시 잡기. 눈앞 실패 복구는 VLA 몫([plan.md](../plan.md) 4절 "실패 복구") |
| `place {obj} on/in {target}` | **VLA** | 같은 이유 |
| `open/close drawer`, `open/close door of {furniture}` | **VLA** | 관절 물체. 손잡이 위치는 지도에 없다 |
| `press`, `turn on/off {switch}` | **VLA**(닿는 높이일 때만) | 9절 작업 공간 |
| 방문(사람이 지나는 문) 열기 | 미정 | 손잡이 높이가 OMX-F 작업 공간 밖일 가능성이 크다(추정, 9절) |

- 원칙: **"어디로 가나" 는 지도 기반 고전 제어, "어떻게 손대나" 는 VLA.** 결정 기록(`decisions.jsonl`)의 `executor`·`label.vla_better` 로 이 나눔이 맞는지 나중에 데이터로 본다.
- VLA 단계 시작 조건: 대상 물체가 지도에 있고, 로봇이 그 물체에서 1.5 m 안(추정), 지금 카메라에 보이거나 기억 불확실도가 작을 때. 아니면 상태 기계가 먼저 `go_to` 를 넣는다(plan.md 3.3 "`pick up` 앞에 `move to` 자동 삽입" 과 같은 규칙).

### 1.3 실행기 접점에 더할 것 (10-04 구현, 리모 + OMX-F)

> **바뀔 접점(결정 2026-10-04, 아직 구현 안 함 — MAPVLA_SPEC 9절 후속 작업)**: 호출 `{"executor":"vla","goal":"<전체 목표>","objects":[id…],"max_s"}`(단계 문장 `skill` 대신 전체 목표), 결과에 **단계 기록** `subtasks:[{text,t0,t1,status}]` 를 더한다. `src/agent`(프롬프트·`set_plan`)와 VLA 실행기(`move_robot` 의 `vla_*`)를 나중에 바꾼다. 아래 표는 지금(10-04) 구현된 접점이다.


| 무엇 | 전(10-03) | 지금 |
|---|---|---|
| 호출 | `{"executor":"vla","skill","max_s"}` | + `objects:[id…]`(set_plan 의 물체 id, scenemap `O<id>`). 이 id 로 물체 칸의 **목표인지** 값을 켠다(문장만으로 고르지 않게). 선택 `policy`(대역 고르기) |
| 끝 | `max_s` 스텝 수만 | 정책의 **끝 신호**(5.3, 7.2) + 자동 확인(`verify.rs`, 계획기 `Core::evidence` 와 같은 증거) + 예산 |
| 결과 | `{"status":"done"}` | `{"status":"done|failed|timeout|handback","reason","evidence","steps","min_clear_m","contacts"}` (+ `policy`·`time_s`·`filter`) |
| 안전 | VLA 행동이 `move_robot` 을 거치지 않음 | VLA 행동도 `move_robot` 안전 거르개를 지남(7.1) |
| 몸 | R1 Pro 부분 | 리모 + OMX-F 부분 `base`(vx, wz)·`arm`(5)·`gripper`, 한계는 `src/robot/real_limits.json`(URDF 의 ±2π 자리표시 대신 실제 범위), 순기구학은 `map_vla_description` URDF |

(10-03 판의 "6.1·6.2" 는 절 번호가 바뀌기 전 표기다. 안전 거르개는 7.1, 끝 조건은 7.2.)

**통합 목표 지정(2026-10-05 구현, 앱 지도 두드리기 — 물체를 누르면 id, 바닥·면을 누르면 지점)**: 호출에 `goal` 을 넣을 수 있다(옛 `objects` 그대로 됨 — `objects[0]` = 집을 것, `[1]` = 놓을 곳 id).
- `{"executor":"vla","skill":"put the cup here","goal":{"pick":{"id":"O12"},"place":{"point":[x,y(,z)]}},"max_s":40}` — 놓을 곳 = map 지점. `place` 는 `{"id":"O3"}` 도 됨. 지점은 놓을 곳만(집을 것은 id).
- `{"executor":"vla","skill":"go here","goal":{"place":{"point":[x,y]}}}` — 지점이 있으면 `go here`·`move to …`·`approach …` 문장은 그 지점까지의 **마지막 다가가기**(종류 approach, 집을 것 없음)로 VLA 에 간다. 1.5 m 밖이면 지금처럼 `handback(too_far)` → `move_robot go_to`. 지점 없는 `move to` 는 그대로 move_robot 몫.
- 시작 때 지점 검사(`goal.rs check_point`): **바닥**(지도의 아는 빈칸, 둘레 0.05 m 빈칸, 다른 물체 바닥 자국 밖, 몸통이 서는 칸에서 0.38 m 안) 또는 **면 위**(기억 물체 윗면 높이 0.05–0.52 m — CURRICULUM_BEHAVIOR2026 3.1 `place_top`, 윗면 사각형을 0.03 m 줄인 안쪽, 서는 칸에서 낮은 면 0.38 m·높은(> 0.25 m) 면 0.31 m 안). z 를 안 주면 xy 가 면 위면 그 윗면, 아니면 바닥(z 0, 한 층 가정). 맞지 않으면 **1.0 m 안 가장 가까운 맞는 자리로 옮기고** 결과 `point:{asked,point,on,support,snap_m,validated}` 에 적는다. 없으면 `status:"error", reason:"invalid_point"`. 지도가 없으면 바닥 점은 검사 없이 받음(`validated:false`).
- 매 스텝 **목표 칸**(PICK·PLACE 두 칸 × 16, VLA_INPUT "목표 칸"과 같은 정의)을 지금 기억에서 id 로 풀어 만든다(물체가 `gone` 이거나 기억에서 빠지면 마지막으로 안 자리 + 잃음 1). 정책은 `VlaObs::goal`(원값·정규화 32), 밖의 엔진은 C ABI `mr_vla_goal_entries(r, raw32, norm32)`(정규화는 `tok_norm.h` 를 그대로 읽음).
- 지점 놓기 확인: 그리퍼 열림 + 놓인 물체 가운데가 지점에서 수평 **0.05 m** 안 + 바닥이 지점 높이 **± 0.02 m** + 손끝 0.05 m 물러남 → done, 열고 물러났는데 밖이면 `failed(place_missed)`. 지점 다가가기 확인: 팔 받침에서 지점까지 0.38 m 안 + 멈춤.
- 물체 간 관계(on/in/next to/near)는 어디에도 쓰지 않는다 — 숫자와 종류(물체/지점)뿐.

코드: `src/agent/tools/move_robot` 의 `limo.rs`(몸·한계·순기구학) · `verify.rs`(자동 확인) · `vla.rs`(호출·나눔·물체 칸·정책 접점·거르개·끝 판정) ·

`src/sim/move_robot/move_robot_limo.py`(`vla_start`·`vla_act`)·`src/sim/explore/run_explore.py`(LIMO 면 libmove_robot 실행기, 물체는 keyframe 마다 scenemap 스냅숏 `sm_snap_objects` 포인터 그대로).

| 항목 | 상태 |
|---|---|
| 1.2 나눔 | `vla::route`: `move to`·탐사 → 거절 + `route:"move_robot"`, 다가가기·집기·놓기·서랍/가구 문·스위치 → VLA, 방문 → 미정(거절) |
| 1.2 시작 조건 | 대상(놓기는 받침)이 기억에 없음 → `handback(not_in_map)`(아는 id 목록), 1.5 m 밖 → `handback(too_far)`(`next: move_robot go_to`), 사라짐·못 봄 + 불확실도 > 0.3 m → `handback(not_visible)`. 불확실도 = 마지막 본 뒤 이동 × 10 % + 회전 × 거리 × 5 % + 2 cm(추정) |
| 목표인지 | `build_slots`: set_plan id 칸만 `is_goal`, 목표는 멀어도 항상 넣고 나머지는 가까운 순 16 칸. 칸 값은 VLA_INPUT 3절 중 위치·거리·방향·크기·상태·출처·불확실도·나이까지(이름 뜻·생김새 벡터 256 은 아직) |
| 끝(7.2) | 순서: 몸통 접촉 → `failed(unsafe)`, 거르개 정지·팔 막힘 2 s → `failed(unsafe)`, 대상 사라짐 2 s → `handback(not_visible)`, 끝 신호 > 0.8 이 0.5 s + 확인 done(집기는 1 s 유지) → `done(verified)` / 확인 failed → `failed(grasp_missed·place_missed)` / 확인 못 하는 스킬 → `handback(unverified)`, 확신 낮음 1 s → `handback(unsure)`, 진척 없음 예산/3 → `handback(stalled)`, 예산 → `timeout(budget)` |
| 확인 | 집기: 그리퍼가 빈손 문턱(벌림 0.03, 추정) 위에서 닫히는 중 + 0.1 m 들림 또는 `held`. 놓기: 벌림 ≥ 0.6 + 받침 0.6 m 안 + 손끝 0.05 m 물러남. 다가가기: 팔 받침에서 0.38 m 안 + 멈춤. 서랍·문·스위치: unknown(영상 몫) |
| 예산 | `max_s`(없으면 스킬별 기본 20–45 s, 추정 — 교사 p90 × 1.5 가 생기면 바꿈) |
| 거르개(7.1) | 관절: 실제 한계 − 2°, 60 °/s(추정), 막힘(지령–실제 > 20° 6 스텝) → 측정 자리. 그리퍼 0..1, 1 /s, 닫다 막히면 유지. 베이스: 0.3 m/s · 35 °/s, 가감속, 앞은 지도 장애물 + 깊이 정지(`go_to`/`delta` 와 같은 `free_ahead`), 뒤는 지도. NaN → 유지. 단독 `mr_filter` 도 있음 |
| 정책 | **학습된 VLA 없음.** 대역: `scripted`(목표 칸만 보고 다가가기 → 수치 역기구학 → 잡기/놓기 → 들기/물러나기 → 끝 신호), `replay:<jsonl>`, `external`(`mr_vla_tick_ext` 로 엔진 행동·끝 신호·확신을 넣음 — 학습된 엔진 자리) |
| 접촉 | 시뮬이 몸통(차체·바퀴)/팔(`omx_*`) 접촉을 나눠 줌(`mr_vla_contacts`). 몸통만 unsafe — 집기는 팔이 물체에 닿아야 하므로 |
| 시험 | `cargo test`: 기존 31 + VLA 19(가짜 LIMO 에서 집기·놓기 done, 헛집기 failed, too_far·not_in_map·not_visible·stalled·unsure·unverified handback, timeout, 몸통 접촉·지도 벽 앞 정지 unsafe, 거르개 한계, real_limits.json 일치, 영점 순기구학 = rviz TF). `move-robot vla-mock` 으로 손으로 볼 수 있음. 파이썬 접착부 자체 시험(`move_robot_limo.py`). OG 시뮬 한 판(리모, turning_on_radio, slam, 약 6 분): `move to` 거절(route move_robot) → 없는 id `handback(not_in_map)`(아는 id O1·O3·O4) → 1.97 m `handback(too_far)`(rel_m) → `go_to` → 다가가기 `done(verified)`(팔 받침 0.34 m, 거르개 베이스 정지 181 스텝, min_clear 0.01 m, 접촉 0) → 집기(대상이 탁자라 대역이 못 잡음) `failed(grasp_missed)` 5.7 s, 팔(omx_link5)–탁자 접촉 3(몸통 0 이라 unsafe 아님) → 그 뒤 move_robot 정상 |

남은 것:
- 학습된 VLA 연결(`external` 로 넣는 엔진, 10 Hz 묶음 실행·미리 추론), 확신 낮음 값(묶음 4 개 퍼짐)은 엔진이 내야 함.
- 물체 칸의 이름 뜻·생김새 벡터(256)·손끝 기준 값·"팔이 닿는지"(작업 공간 표), 벽·방 토큰. 지금 칸은 정책 대역용 일부.
- 확인 문턱의 OMX-F 실측(빈손 벌림, 들림 판정의 scenemap 높이 오차), 놓기의 "1 s 정지".
- 상태 기계(`task/machine.rs`)·`set_plan`·`skillspec` 은 아직 코드가 없다(plan.md 설계). 지금 호출은 사람·시험 스크립트가 만든다. `handback` 뒤 `go_to` 자동 삽입, `stalled` 1 번 다시 보내기도 상태 기계 몫.
- `move_robot` LLM 도구의 LIMO 팔·그리퍼 부분(`part: arm/gripper`)은 아직 없다(리모 탐사는 베이스만). VLA 실행기와 거르개만 LIMO 부분을 쓴다.
- R1 경로(π0.5 엔진, `--vla-weights`)는 그대로: 끝은 `max_s` 뿐, 결과 `done`, 거르개 안 지남.
- 대상 물체와의 팔 접촉 vs 다른 물체와의 팔 접촉을 아직 안 나눔(지금 팔 접촉은 세기만).
- 시뮬 한 판에서 팔이 탁자 앞을 가리자 scenemap 이 탁자를 `held`·0.49 m 옮겨짐으로 표시했다. 집기 확인이 `held` 를 들림 대신 받으므로, 확인에 그리퍼 쥠(벌림)을 꼭 같이 보는 지금 규칙을 유지하고 scenemap 쪽 `held` 판정(팔 가림)을 고쳐야 한다.

## 2. 왜 교사와 학생을 나누나

사용자의 처음 생각은 "모방학습 먼저, 그다음 같은 모델로 RL" 이었다. 걱정은 "RL 다음에 모방학습을 하면 가중치가 망가지지 않나" 였다. 답은 다음과 같다.

- **교사(RL)와 학생(VLA)은 서로 다른 신경망이다.** 교사는 작은 MLP·집합 인코더(수백만 변수, 추정)이고, 학생은 영상·글을 받는 큰 망이다.
  학생을 BC 로 학습해도 **교사 가중치는 건드리지 않는다.** 교사는 데이터를 만들고 정답을 붙이는 도구로 끝까지 남는다(DAgger 에서도 씀).
- **처음부터 VLA 에 RL 을 하지 않는 이유**
  - RL 은 시행 수억 스텝이 필요하다(추정). 스텝마다 카메라 2장 렌더 + 큰 망 추론·역전파를 하면 RTX 5070 Ti 한 장(16 GB)으로는 너무 느리다.
    팀 엔진 렌더는 판 64 × 카메라 3(720², 480²) 에서 56 판·프레임/초였다([BEHAVIOR_ENGINE_REVIEW.md](BEHAVIOR_ENGINE_REVIEW.md) 2절). 영상 없는 교사는 렌더가 필요 없다.
  - 무작위로 시작한 행동 전문가는 탐색만으로 집기 같은 성공을 거의 못 본다. 보상이 드물면 학습이 시작되지 않는다.
  - 큰 망에 RL 기울기를 바로 넣으면 사전학습 지식(말 따르기, 처음 보는 물체)이 잘 망가진다([PI05_TRAINING.md](PI05_TRAINING.md) 4절 지식 격리의 이유와 같다).
- **BC 전에 시연이 있어야 하는 이유**: BC 는 (관측, 행동) 짝이 있어야 한다. 리모 + OMX 시연은 지금 0 이다. 사람 텔레옵으로 수천 판을 모으기는 어렵다. 그래서 교사가 시뮬에서 시연을 대량으로 만든다.
- **사용자 생각(같은 모델에 RL)은 3단계로 들어간다**: BC 로 이미 쓸 만한 학생에 RL 을 조금 더한다(5.4). 이때는 잊지 않게 묶는다.

## 3. 스킬 나누기 (교사)

교사는 스킬마다 하나(공통 몸통 + 스킬별 머리, 4.3)다. 학생은 하나로 모든 스킬을 하고 단계 문장으로 고른다.

### 3.1 스킬 표

| 스킬 | 시작 상태 | 성공 | 끝(실패) |
|---|---|---|---|
| `approach`(앞부분) | 대상 1–2.5 m, 방향 무작위 | 대상 칸 "팔이 닿는지" = 1, 손목 카메라 시야 안, 베이스 정지 | 시간 초과, 접촉, 대상이 칸에서 빠짐 |
| `pick` | approach 끝 상태 또는 바로 닿는 자리 | 그리퍼가 물체에 닫힘(폭 > 0.005 m) + 물체 0.1 m 이상 들림 1 s 유지 | 물체 떨어짐, 다른 물체 넘어뜨림, 시간 초과 |
| `place on/in` | 물체를 든 채 받침 1.5 m 안 | 그리퍼 열림 + 물체가 받침 윗면 위(또는 그릇 상자 안)에서 1 s 정지 + 손끝 0.05 m 이상 물러남 | 받침 밖에 떨어짐, 시간 초과 |
| `open/close drawer` | 서랍 앞 1 m 안 | 열림 비율 ≥ 0.6(닫기는 ≤ 0.05) (추정) | 손잡이 놓침 3 번, 시간 초과 |
| `open/close door`(가구) | 가구 문 앞 | 문 각도 ≥ 60°(닫기는 ≤ 5°) (추정) | 같음 |
| `press`/`turn on` | 스위치 1 m 안 | 스위치 상태 바뀜 | 시간 초과 |

- 성공 판정은 [에이전트_설계.md](../../src/behavior-2026/docs/에이전트_설계.md) 1.7 의 자동 증거 임계값(집기 = 0.1 m 들림, 0.005 m 아래로 닫히면 실패)과 맞춘다. 같은 판정을 실행 때 확인에도 쓴다.
- 시간 예산: 스킬마다 교사 성공 판 길이 p90 × 1.5(plan.md 3.4 와 같은 규칙).
- `approach` 의 자세한 성공 조건·보상·커리큘럼 단계(A0–A5)·지표는 [CURRICULUM_APPROACH.md](CURRICULUM_APPROACH.md). 이것이 첫 커리큘럼이다.

### 3.2 관측·행동

- **행동**: VLA 와 같은 8 = 베이스(vx, wz) + 팔 joint1–5 + 그리퍼, 10 Hz([VLA_INPUT.md](VLA_INPUT.md) 5절). 학생이 교사 행동을 그대로 따라 하게 공간을 같게 둔다.
  - 제안: 팔 = 관절 **목표 위치**(정규화), 그리퍼 = 목표 벌림, 베이스 = 속도. 아래는 `move_robot` 이 보간·한계 처리(9절에 대안).
  - 물리 시뮬은 더 잘게 돈다. 정책만 10 Hz.
- **관측**: 4.2 의 세 단계(학생과 같은 값 / 교사 행동 망 특권 / 가치 망 특권).
- 스킬별로 더하는 것은 없다. 스킬 종류는 목표 토큰에 넣는다(교사: 스킬 one-hot, 학생: 단계 문장).

### 3.3 보상 (스킬마다, 숫자 무게는 (추정))

| 항 | approach | pick | place | open/close | 모두 |
|---|---|---|---|---|---|
| 밀집(진행) | 대상까지 거리 줄어든 양, 손목 카메라 쪽 방향 | 손끝 ↔ 겉면 거리 줄어든 양, 그리퍼 정렬, 들린 높이 | 손끝·물체 ↔ 놓을 곳 거리, 낮게 내려놓기 | 손잡이 거리, 관절(서랍·문) 진행량 | |
| 드묾(성공) | +10 | +20 | +20 | +20 | |
| 벌점 | | 물체 미끄러짐·떨어짐 −5 | 떨어뜨려 놓기(높이 > 5 cm) −5 | 손잡이 놓침 | 대상 아닌 물체·벽 접촉, 관절 한계 근처, 행동 변화량(덜컥임), 베이스 빠르기 × 장애물 가까움, 시간 |

- 밀집 항은 **차이(줄어든 양)** 로 준다. 가만히 있어도 받는 보상을 없앤다.
- 접촉 벌점은 `move_robot` 안전 층이 막을 일을 정책이 먼저 피하게 한다(6.1).

#### 3.3.1 기본 구조와 원칙

`보상 = 진행 보상(밀집) + 성공 보상(드묾) − 벌점`

- **진행 보상은 줄어든 양**: `r = (이전 거리 − 지금 거리) × w`. "가까우면 +" 로 주면 목표 근처에서 멈춰 점수를 쌓는다. 줄어든 양은 판 전체 합이 "처음 거리 − 마지막 거리" 라 꼼수가 안 된다(potential-based shaping).
- **성공 보상은 크게, 판마다 한 번**. 판정은 실행 때 확인과 같은 식(3.1 표)으로 둔다 → 학습 때 성공과 실제 성공이 같은 뜻.
- **벌점은 작게, 많이**. 벌점 합이 성공 보상보다 훨씬 작아야 한다. 처음엔 작게 시작해 키운다.
- **정책이 아는 정보 기준**: 진행 보상의 거리는 그 순간 지도에 들어간 물체로만 계산한다. 아직 지도에 없는 물체는 거리 보상 없음(자라는 지도, 4.4).

#### 3.3.2 예: `pick` (무게는 (추정))

| 항 | 식 | 무게 |
|---|---|---|
| 손 다가가기 | 이전 손끝 ↔ 물체 겉면 거리 − 지금 | × 10 |
| 그리퍼 정렬 | 이전 정렬 오차 − 지금(손끝 방향 ↔ 물체로 가는 방향 각도) | × 2 |
| 들어올리기 | 지금 물체 높이 − 이전, 쥐고 있을 때만 | × 20 |
| 성공 | 그리퍼 닫힘(폭 > 0.005 m) + 0.1 m 이상 들림 + 1 s 유지 | +20, 판 끝 |
| 떨어뜨림 | 쥐었다가 놓침 | −5 |
| 다른 물체·벽 접촉 | 접촉마다 | −1 |
| 관절 한계 근처 | 한계 5° 안 | −0.1 / 스텝 |
| 덜컥임 | ‖이번 행동 − 직전 행동‖² | × −0.01 |
| 시간 | 매 스텝 | −0.01 |

다른 스킬도 같은 틀이다(진행 항만 3.3 표처럼 바뀐다): `approach` 성공 +10, `place`·`open/close`·`press` 성공 +20.

#### 3.3.3 함정과 막는 법

| 함정 | 막는 법 |
|---|---|
| 목표 근처에서 흔들며 진행 점수 쌓기 | 줄어든 양 방식 — 멀어지면 같은 만큼 깎임 |
| 물체를 밀어서 거리 줄이기 | 들어올리기 보상은 쥐었을 때만, 대상 물체가 밀리면 벌점 |
| 성공 직전에 떨어뜨리고 다시 집기 | 성공은 판마다 한 번, 떨어뜨림 벌점 |
| 지도에 없는 물체를 정답으로 찾아감 | 진행 보상은 정책이 아는 정보(지도에 들어간 물체) 기준 |
| 벌점이 커서 안 움직임 | 벌점 합 ≪ 성공 보상, 벌점은 작게 시작해 키움 |

#### 3.3.4 확인하는 법

- 판마다 **보상 항목별 합계를 따로** 기록한다(어떤 항이 학습을 끌고 가는지).
- 성공률·판 길이·접촉 수를 같이 본다. 보상은 오르는데 성공률이 안 오르면 꼼수를 찾은 것.
- 학습된 판을 영상으로 몇 개씩 직접 본다.

## 4. 교사 RL

### 4.1 알고리즘

- **PPO + 비대칭 행동자–가치(asymmetric actor-critic)**. 행동자는 4.2 의 (가)+(나), 가치 망은 (가)+(나)+(다).
- 병렬 판 수천 개, 판당 10 Hz. 가우스 정책. 데이터 만들 때는 평균 행동을 쓴다.
- 구현은 C++/CUDA/Rust 네이티브([training/RL/README.md](../../training/RL/README.md)). 판 묶음·커널 설계는 [GPU_TRAINING.md](GPU_TRAINING.md).

### 4.2 관측 세 단계

> **2026-10-06**: RL 교사 행위자는 학생과 같은 관측(C2 자라는 지도·같은 관측 코드), 특권은 비평자에만(비대칭 행위자-비평자, Pinto 외 2017). 까닭: 모방 차이(Warrington 외 2021, Swamy 외 2022) — 교사 행동이 학생이 못 보는 값에 기대면 학생이 따라 못 함(CURRICULUM_BEHAVIOR2026 5.6.2 의 DAgger 떨어짐). 아래 특권 표는 비평자 입력으로 읽는다.

| 단계 | 내용 | 누가 봄 |
|---|---|---|
| (가) 학생과 같은 값 | 몸 상태 56, 물체 칸 ≤ 16 × 289, 벽·방 토큰, 목표(스킬 종류 + 목표 칸 표시) — **영상만 없음**. 10-05 더함: 통합 목표 칸 2, 탑뷰 줄인 격자 16 × 16 × 2, **방 항목 ≤ 8·탐사 경계 후보 ≤ 8**(탐사를 교사도 같은 정보로 배움), 물체 칸의 방 종류 6 | 행동자·가치 |
| (나) 본 물체의 특권 정보 | **이미 지도에 있는 물체만**: 정확한 자세(회전 포함), 잡을 자리, 질량·마찰, 서랍·문 관절 축·각도, 손잡이 위치 | 행동자·가치 |
| (다) 모든 정답 | 정답 로봇 자세, 아직 안 본 물체 전부, 접촉 힘, 무작위화 값 | 가치만 |

- [training/RL/README.md](../../training/RL/README.md) 의 관측 칸에 적힌 "물체 id·방 id" 는 VLA_INPUT 0절 원칙(지도마다 다른 값 금지)에 맞춰 **목표인지 표시 + 방 종류 확률**로 바꾼다(제안).
- **교사도 학생과 같은 자라는 지도를 본다.** 안 본 물체를 아는 교사는 학생이 흉내 낼 수 없는 행동(안 보고도 바로 가기)을 한다. 그래서 특권은 "이미 본 것의 정확한 물리·상태" 로만 준다.
- (나)가 크면 교사–학생 차이가 커진다. 학습 뒤쪽에서 (나)를 점점 잡음으로 바꾸는 판(교사 2판)을 두고, 학생 성능으로 고른다(9절).

### 4.3 신경망

```
물체 칸 k (289 + 특권) ─ 같은 MLP(2층, 256) ─▶ e_k (128)          ┐
벽 56 · 방 · 몸 56 · 목표 ─ 각자 MLP ─▶ 토큰 4 개                  ├─ 셀프 어텐션 1–2 층(칸 위치 번호 없음, 빈 칸 마스크)
                                                                  ┘
                     질의 = 목표·몸 토큰 ─ 어텐션 풀링 ─▶ 256 ─ (선택) GRU 256 ─▶ 스킬 머리: 행동 평균 8 + 로그 표준편차 / 가치 1
```

- 칸 순서를 바꿔도 출력이 같다(위치 번호 없음 + 풀링). 칸 0 개여도 돈다(마스크 + 목표·몸 토큰만).
- 크기 1–3 M 변수(추정). 가치 망은 같은 모양에 (다)를 더한다(따로 학습).
- 스킬 머리를 나누는 이유: 보상 크기가 스킬마다 달라 한 머리로 섞으면 한 스킬이 다른 스킬을 누른다. 몸통은 함께 쓴다.

### 4.4 자라는 지도·기억

- 판은 지도가 **비었거나 일부만** 있는 상태로 시작할 수 있다. 판 동안 카메라가 본 것이 지도에 들어온다(시뮬도 실제와 같은 지도 만들기 — [GPU_TRAINING.md](GPU_TRAINING.md)).
- 기억은 1차로 **지도 토큰 자체**다. 칸에 `출처`(지금 보는 중 / 기억), `위치 불확실도`, `마지막 본 뒤 시간` 이 있으므로 정책은 "안 보이는 것" 을 따로 외울 필요가 적다.
- GRU 는 **선택**이다. 지도에 없는 짧은 기억(방금 미끄러졌다, 손잡이를 한 번 놓쳤다)에 쓴다. GRU 없는 판과 비교해서 차이가 없으면 뺀다.
  학생은 순환망이 없으므로(5절), 교사가 GRU 에 크게 기대면 학생이 따라 하기 어렵다. 이것도 비교 대상이다.
- 대상이 안 보일 때 해야 할 행동(돌아보기, 조금 물러나기)도 학습한다. 시작 때 대상 칸을 기억(불확실도 큼)으로만 주는 판을 섞는다.

### 4.6 목표 점 — 보상·성공·감추기 (결정 2026-10-05, 구현 `training/RL/env/include/env_beh.h`)

목표는 물체 id 또는 지도 점이다(VLA_INPUT 2.1 목표 칸). 점 목표 판:

| 판 | 하는 것 | 성공 | 보상 |
|---|---|---|---|

- **학생 목표 감추기와의 관계**: `p_goal_drop` 은 물체 목표(칸 "목표인지" + 물체 목표 칸 + 물체 쪽 몸 상태 목표 값·경유 지점)만 감춘다 — 지시문의 물체 이름으로 칸을 찾게. **점 목표 칸은 절대 감추지 않는다**(점은 글에서 알 수 없음, "여기·저기" 지시문이 붙는 판은 늘 점 칸이 있음). 점으로 가기 판은 몸 상태의 목표 값·경유 지점도 점 쪽이라 남긴다. 교사(`goal_mode` 1)는 점을 늘 안다(사용자가 준 값 — 특권 아님).
- 점 고르기: 호스트가 짝마다 미리(`bscene_host place point`): 바닥 = 고른 0.4 m 자리 가운데, 면 = 윗면 0.05 m 격자를 해시 차례로 — 물체 바닥 자국 반지름 + 0.02 m 안쪽, 그 면 위 다른 물체와 안 겹침, 같은 성분의 닿는 칸에서 0.38 m(낮은 면)·0.31 m(높은 면 = 0.21 + 가장자리 안 0.10) 안. 용기는 점 없음(누를 물체가 있음). 독립 확인 `pnp_check`(위반 0).

### 4.7 교사의 위에서 본 지도 격자 (결정 2026-10-05, VLA_INPUT 1.1)

- 교사 특권(4.2 (나))은 아직 관측에 안 넣었다: 잡을 자리·무게는 **대본 교사**(env `teacher.h`)만 쓴다. 대본 교사도 B6 에서 목표가 지도에 확정되기 전에는 물체 자리를 쓰지 않고 탐사한다(창 격자점). 학생·PPO 교사 관측은 그대로(VLA_INPUT 의 칸 상태 "들고 있음" = 지도 근사의 믿음 규칙, 그리퍼 각 = 몸 상태). 닿음 표시는 VLA_INPUT 에 없어 넣지 않고 제안만(VLA_INPUT 8절 제안).

### 5.3 행동 전문가와 묶음

- flow matching 행동 전문가(π0.5 와 같은 방식): 작은 트랜스포머 4–6 층(추정)이 몸통 토큰을 보면서 잡음 묶음 → 행동 묶음.
- 묶음 길이 H = 16(1.6 s, VLA_INPUT 5절 범위 16–32 의 짧은 쪽). 앞 5 스텝(0.5 s)만 실행하고 다시 추론(추정).
  - 다음 추론은 실행 중에 미리 돌리고, 겹치는 스텝은 앞 묶음과 이어지게 맞춘다(real-time chunking 류, VLA_QnA Q6).
- 잡음 제거 단계 5–10(추정). 적게 할수록 빠르다. 성공률과 같이 잰다.
- 끝 신호: 묶음과 함께 **"이 단계 끝" 확률 1 개**를 내는 작은 머리(교사 판의 성공 시점을 정답으로). 6.2 에서 쓴다.

### 5.4 지연 예산 (10 Hz, 0.5 s 마다 추론, 전부 추정)

| 부분 | 안 B, 리모(Orin Nano) | 안 A, PC(5070 Ti) 원격 |
|---|---|---|

- 리모 기본형(Jetson Nano 4GB)에서는 안 B 도 빠듯하다(추정, [plan.md](../plan.md) "아직 모르는 것").

### 5.5 단계 문장이 행동을 바꾸게

- 문장은 skillspec 이 만든 정확한 틀을 쓴다(학습·실행 같은 글자, plan.md 2.3).
- 문장만으로는 같은 이름 물체 둘을 못 가린다. 그래서 **목표인지 표시**(set_plan 의 물체 id → 칸)를 같이 준다. 문장은 스킬 종류·받침·전치사를, 표시는 어느 물체인지를 맡는다.
- 확인: 같은 관측에 문장만 바꿨을 때 행동 변화가 잡음의 3 배 이상(plan.md 2.4 게이트와 같은 시험).

### 6.1 BC 데이터 섞기 (PI05_TRAINING 6절 교훈)

| 데이터 | 몫(추정) | 어떻게 |
|---|---|---|
| 우리 교사 시연 + DAgger | 50–60 % | 전부 |
| BEHAVIOR R1 Pro 시연(약 1만 판, plan.md) | 15–20 % | 몸이 달라 **행동 칸이 다르다**. 몸통·비전·지도 토큰만 함께 배우고 행동 머리는 몸마다 따로(또는 안 쓰는 칸 마스크) |

### 6.2 DAgger 세부

- 학생이 간 상태에서 교사 관측((가)+(나))은 시뮬이 바로 준다. 정답은 교사 평균 행동 16 스텝을 이어 묶음으로 만든다(교사를 그 상태에서 16 스텝 굴림, 학생 행동은 무시).
- 학생이 실패로 간 상태(물체를 밀어 떨어뜨림 등)가 데이터에 들어가므로 **복구 행동**을 배운다. 교사도 이런 상태를 무작위 시작으로 학습해 둔다(4.4).

### 6.3 학생 RL 미세조정 — 잊지 않게

사용자 생각("모방 다음 같은 모델로 RL")을 여기서 한다. 망가짐을 막는 장치를 같이 둔다.

| 장치 | 내용 |
|---|---|
| 몸통 얼림 | 비전·몸통·글 인코더는 얼린다. **행동 전문가만**, 또는 그 위의 **작은 잔차 머리**만 학습 |
| 잔차 정책 | 얼린 BC 학생 묶음 위에 한 스텝 보정만 더하는 작은 망(교사 망 크기). 보정 크기 상한. 잔차 RL 로 BC 정책을 미세조정한 연구가 있다(ResiP arXiv 2407.16677, 잔차 off-policy RL arXiv 2509.19301) |
| BC 정책에 KL 벌점 | 미세조정 정책이 BC 정책 행동 분포에서 멀어지면 벌점 |
| 작은 학습률·짧은 학습 | BC 의 1/10 쯤(추정), 몇 시간 단위로 끊고 매번 지킴 평가 |
| BC 데이터 계속 섞기 | RL 손실과 BC 손실을 같이(BC 무게는 줄여 가며) |
| 지킴 평가(guard rail) | 처음 보는 이름·안 쓴 집·문장 바꿈 반응(8절)이 BC 판보다 떨어지면 그 체크포인트는 버린다 |

- flow matching 정책은 행동 확률을 바로 계산하기 어려워 PPO 를 그대로 못 쓴다. 맞는 방법:
  - **잔차 정책 RL**(위). 잔차 머리는 보통 가우스 정책이라 PPO 를 그대로 쓴다. 가장 단순해서 1순위 제안.
  - **DPPO**(Diffusion Policy Policy Optimization, arXiv 2409.00588): 잡음 제거 과정을 여러 단계 결정으로 보고 정책 기울기.
  - **ReinFlow**(arXiv 2505.22094): flow 경로에 학습되는 잡음을 넣어 확률을 계산, 적은 잡음 제거 단계에서도 로봇 제어 미세조정.
  - (참고) **Flow-GRPO**(arXiv 2505.05470)는 ODE → SDE 바꾸기로 flow 모델에 온라인 RL 을 한다. 다만 글 → 이미지 생성 대상이라 로봇 제어에는 직접 검증되지 않았다.
- 이 단계는 영상 렌더 + 학생 추론이 스텝마다 든다. 판 수를 줄이고(수백, 추정) 성공률이 낮은 스킬·장면에만 쓴다.

### 6.4 실제 로봇 미세조정

- 텔레옵: OMX-F 리더 팔 + 베이스 조이스틱(추정 — ROBOTIS physical_ai_tools 에 OMX-F 설정 `omx_f_config.yaml` 이 있다는 것만 [SIM_PORTING.md](SIM_PORTING.md) 2.4.1 에 적혀 있고, 리더 팔 구성은 확인 안 함).

## 7. 안전과 실패 처리

### 7.1 단단한 층: `move_robot`

- VLA 행동은 매 스텝 `move_robot` 안전 거르개를 지난다(리모 + OMX-F 는 10-04 구현 — 1.4. R1 π0.5 경로는 아직 안 지남).
  - 관절: URDF 한계 안쪽으로 자르기, 속도·가속 상한(지금 R1 Pro 기본 45 °/s 를 OMX-F 에 맞게 다시 정함), 막힘 판정(지령–실제 차이) → 더 밀지 않음.
  - 그리퍼: 닫다가 막히면 그대로 유지(지금 규칙과 같음).
  - 베이스: 속도 상한(VLA 는 `delta` 수준 0.3 m/s 이하 제안), 몸통 원 + 깊이 프레임 얇은 안전 정지, 지도 장애물 정지(지금 `delta` 의 진행 방향 정지와 같은 코드).
  - 거르개가 행동을 크게 바꾸면(잘림이 N 스텝 넘게 계속) 정책이 같은 실수를 되풀이하는 것으로 보고 넘김(7.2).
- C ABI "행동 거르기": `mr_filter(r, proprio, n, action8, out8)`(10-04). 단계 전체는 `mr_vla_tick`/`mr_vla_tick_ext` 가 거르기까지 한다.

### 7.2 VLA 가 단계를 끝내거나 돌려주는 조건

| 조건 | 판정 | 결과 |
|---|---|---|
| 성공 | 끝 신호 확률 > 0.8 이 0.5 s 유지 + 자동 확인(들림·놓임) | `done` |
| 시간 | 스킬 예산(p90 × 1.5) 넘음 | `timeout` → 상태 기계 |
| 진척 없음 | 예산 1/3 동안 손끝·물체·관절 변화 없음(plan.md `VlaStalled`) | 문장 다시 보내고 1 번 더, 그다음 `handback` |
| 확신 낮음 | 같은 관측에서 잡음 다르게 묶음 4 개를 뽑아 퍼짐이 큼(추정 기준) 또는 목표 칸 불확실도 큼 | 잠깐 멈추고 둘러보기 1 번 → 그래도 크면 `handback("unsure")` |
| 대상 사라짐 | 목표 칸이 `사라짐`, 또는 2 s 동안 출처가 `기억` 이고 불확실도 큼 | `handback("not_visible")` → 상태 기계 `NotVisible` 복구 |
| 안전 | 거르개 정지 되풀이, 접촉 | `failed("unsafe")` |

- 돌려준 뒤 복구는 지금 계획(plan.md 3.4 표)을 그대로 쓴다: 다시 다가가기, 같은 문장 재시도 2 번, 그다음 LLM 재계획.
- 눈앞 실패(놓침 → 다시 잡기)는 VLA 안에서 한다. DAgger 데이터에 이런 상태가 들어가서 배운다(6.2).

## 8. 평가

| 평가 | 나눔 | 통과 기준(제안) |
|---|---|---|
| 처음 보는 이름 | 학습에 안 나온 물체 이름만(이름 뜻 벡터·문장 둘 다) | 본 이름 대비 −10 %p 안 |
| 처음 보는 집 | BEHAVIOR 학습에 안 쓴 집 | 같은 집 대비 −10 %p 안 |
| 지도 완성도 | 전부 / 일부(칸 50 % 지움) / 빈 지도 / 지도 없음 | 전부 ≥ 일부 ≥ 빈 지도 ≥ 지도 없음. 지도가 도움이 되는지 |
| 위치 출처 | `gt` 지도 대 `slam` 지도 | 차이 −5 %p 안 |
| 문장 반응 | 같은 관측, 문장만 바꿈 | 행동 변화 ≥ 잡음 × 3 |
| 교사 대비 | 같은 시작 상태 | 학생 / 교사 성공률 ≥ 0.8 |
| 단계 잇기 | `go_to → approach → pick → go_to → place` 한 명령 | 과제 성공률(plan.md `cmd_sim`·`cmd_limo`) |
| 실제 로봇 | 리모 10 명령 × 3 | plan.md 5.1 `cmd_limo` ≥ 50 % |

재는 것(판마다): 성공, 걸린 시간, 접촉 수(0 이어야), 떨어뜨림, 안전 거르개 개입 수, `handback` 비율과 이유, 실제 로봇은 사람 개입 수.
점수는 `slam` 판에서 잰다. `gt` 판은 확인용이다([plan.md](../plan.md) 코드 규칙).
