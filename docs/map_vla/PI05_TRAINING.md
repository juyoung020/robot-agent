# π0.5 는 어떻게 학습됐나 (참고)

작성 2026-10-03. **조사 문서**다. 우리 VLA([VLA_INPUT.md](VLA_INPUT.md))를 설계·학습할 때 따라 할 것과 바꿀 것을 고르려고 정리했다.
출처는 끝에 모았다(논문 PDF 받기: `bash refs/download.sh` → `refs/papers/pi05.pdf`, `FAST.pdf`, `knowledge-insulating.pdf`).

## 1. 모델

| 부분 | 내용 |
|---|---|
| 몸통(VLM) | 웹 데이터로 학습된 VLM 에서 시작(PaliGemma 계열). openpi 판: SigLIP So400m/14(이미지 224² → 카메라당 256 토큰) + Gemma 2B |
| 행동 전문가 | 따로 작은 가중치(openpi 판 Gemma 300M). 몸통과 어텐션을 함께 쓰며, 연속 행동을 **flow matching** 으로 한 번에(비자기회귀) 낸다 |
| 상태 입력 | 로봇 상태를 정규화한 뒤 **256 구간으로 나눠 글 토큰으로** 넣는다(openpi `discrete_state_input`) |
| 행동 표현 | 두 가지를 같이 쓴다. 사전학습은 **FAST 이산 토큰**(DCT + BPE 로 행동 묶음을 압축한 토큰), 후학습부터 **flow matching** 행동 전문가 |
| 출력 | 행동 묶음(chunk). 논문: 50 Hz 제어, 잡음 제거 10 단계. 팔·그리퍼·몸통 리프트 목표 자세 + 베이스 목표 속도를 내고, 아래는 단순 PD 제어기(경로 계획·충돌 검사 없음) |

openpi 의 BEHAVIOR 설정(`pi05_b1k`, 팀 behavior-2026 `docs/π05_네이티브엔진.md` 1절): 행동 32 스텝 × 32 차원(앞 23 사용), 문장 토큰 ≤ 200, 카메라 3장, 상태 23 차원, z-score 정규화.

## 2. 학습 두 단계

### 2.1 사전학습 — 28만 스텝, 이산 토큰만

| 데이터 | 뜻 | 양·특징 |
|---|---|---|
| **MM** | 이동 매니퓰레이터, 실제 집 | 약 **400 시간, 약 100 집** |
| **ME** | 이동 안 하는 로봇, 여러 환경 | 가벼운 로봇이라 더 많은 집에서 모음 |
| **CE** | 다른 로봇(몸이 다름) 실험실 데이터 + OXE | 탁자 위 작업 위주 |
| **HL** | 높은 수준 단계 예측 | 로봇 데이터에 "지금 할 단계" 를 사람이 글로 붙임 |
| **WD** | 웹 데이터 | 이미지 설명, VQA, 물체 위치 찾기 |

- 손실: 글·물체 위치·**FAST 행동 토큰**의 다음 토큰 예측만(flow matching 끔, α = 0).
- 28만 스텝 중 첫 단계 데이터의 **97.6 % 가 MM 이 아닌 곳**(ME·CE·HL·WD)에서 왔다. 목표 로봇(MM) 데이터는 아주 작은 몫이다.

### 2.2 후학습 — 8만 스텝, 행동 전문가 추가

- **행동 전문가를 붙이고** flow matching 손실을 켠다(α = 10). 이산 토큰 손실도 계속.
- 데이터: MM·ME(성공한 판만, 길이로 거름) + WD(말 능력 유지) + HL(이동 환경 부분) + **VI(말로 한 지시 시연)**.
  - VI: 숙련자가 로봇에게 **단계 지시를 말로** 주며 시킨 시연. 높은 수준 예시의 약 11 %.

### 2.3 추론 — 두 층

1. 먼저 **글로 다음 단계**를 예측한다(예: "pick up the pillow").
2. 그 단계 글을 조건으로 **행동 묶음**을 flow matching 10 단계로 낸다.

같은 모델이 두 층을 다 한다(높은 수준 계획 + 낮은 수준 행동).

## 3. 무엇이 중요했나 (논문 제거 실험)

| 뺀 것 | 결과 |
|---|---|
| ME 또는 CE(다른 로봇·다른 환경 데이터) | **크게 나빠짐**. 둘 다 있어야 한다 |
| WD(웹 데이터) | 전체 과제 성공률 차이는 통계적으로 뚜렷하지 않음. 그러나 **말 따르기·처음 보는 물체**에서 크게 나빠짐 |
| VI(말 지시 시연) | 크게 나빠짐 |
| 높은 수준 예측(대신 HL 데이터만 학습에 넣음) | 두 번째로 좋음 → HL 데이터를 섞는 것만으로 이득의 상당 부분 |
| (비교) 사람이 단계를 직접 준 경우 | 전체 모델이 사람 단계 지시(오라클)보다도 나았다 |

## 4. 지식 격리 (Knowledge Insulation, 후속 논문)

π0.5 의 두 단계 학습을 한 단계로 묶은 방법(같은 회사, arXiv 2505.23705).

- 행동 전문가(flow matching)의 기울기가 **몸통으로 흘러가지 않게 막는다**(stop-gradient). 처음엔 무작위인 행동 전문가가 VLM 지식을 망치는 것을 막는다.
- 몸통은 대신 **FAST 이산 행동 토큰** + 웹 데이터 + 계획 데이터로 배운다.
- π0 대비 학습 스텝 7.5 배 적게, 추론은 빠르게(10 Hz 수준), LIBERO 일부 최고 성능.
- openpi 공개판에서 KI 로 학습된 것은 `pi05_droid`. openpi 학습 코드는 π0.5 를 **flow matching 머리로만** 지원한다.

## 6. 우리 VLA 에 가져올 것

| π0.5 에서 | 우리([VLA_INPUT.md](VLA_INPUT.md))에 |
|---|---|
| 목표 로봇 데이터는 작은 몫, **다른 로봇·환경·웹 데이터가 대부분** | 리모 + OMX 시뮬 데이터만으로 학습하지 않는다. BEHAVIOR(R1 Pro)·다른 팔 데이터, 물체 이름·위치 VQA 같은 비로봇 데이터를 섞는다 |
| **HL(단계 글) 데이터**가 큰 이득 | 우리 LLM 이 주는 단계 문장과 같은 형식의 단계 글을 시연에 붙인다. RL 전문가 궤적에도 단계 경계·문장을 기록 |
| **VI(말 지시 시연)** | 같은 단계를 여러 말로 지시하는 시연(이름 흔들기·지시 바꾸기 규칙과 같은 방향) |
| 웹 데이터가 **말 따르기·처음 보는 물체**를 지킴 | 이름 뜻 벡터를 얼린 글 인코더로 넣는 것과 같은 목적. 몸통을 바꾼다면 VLM 데이터를 같이 섞는다 |
| **FAST 이산 토큰 + flow matching**, 지식 격리 | 몸통이 사전학습 VLM(Qwen3.5-2B 등)이면 KI 처럼 행동 전문가 기울기를 막고 FAST 토큰으로 몸통을 가르친다. 작은 몸통을 새로 학습하면 flow matching 만으로 시작 |
| 상태를 **글 토큰(256 구간)** 으로 | 우리는 지도·몸 상태를 **연속값 → MLP 토큰**으로 넣는다(숫자 수가 많아 글로 풀면 토큰이 너무 많음). 다른 점으로 기록 |
| 50 Hz, 묶음 출력, 아래는 PD 제어 | 리모·OMX 는 10 Hz 수준 묶음 + 아래는 `move_robot` 닫힌 고리(관절 보간, 베이스 속도 제어) |
