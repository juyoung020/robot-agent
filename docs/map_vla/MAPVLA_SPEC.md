## 0. 한눈에

1. **무엇이 새로운가(1.3절에 정확한 정의)**: 따로 도는 SLAM + 열린 어휘 검출 실행기(scenemap)가 **실시간으로 키우는 물체 중심 3D 장면 그래프 기억**(물체마다 상태 보임·옮겨짐·사라짐·들림, 출처 지금 봄/기억, 위치 불확실도, 방·벽 구조)을 **구조화된 칸 토큰**(조밀 복셀 특징도, 글도 아님)으로 받아 **이동 조작**을 하고 **단계 문장**도 내는 VLA. 온라인 장면 그래프 기억 + 언어 조건 VLA + 이동 조작 + 글 출력 + 자라는 지도 학습의 **조합**으로는 2026-10-04 까지 찾은 문헌(1.2절, 17 편)에 같은 것이 없다. 가장 가까운 것은 Qian 외(arXiv 2606.01072, 장면 그래프 노드 토큰 → 확산 정책, 언어·상태 없음)다.
2. **결정된 구성**: Qwen3.5-0.8B 글 몸통(752.4M) + SigLIP 2 B/32-256 영상 탑(87.5M, 256² → 카메라당 토큰 64) + 사영 768 → 1024(0.8M) + 지도·몸 인코더(약 3M (계산)) + π0.5 꼴 행동 전문가(약 95–107M (계산)) = **약 0.95B (계산), 전부 학습**. 옵티마이저 = GPU 위 8 비트 블록 Adam + BF16 원본(확률 반올림).
3. **잰 속도 기준**: 우리 손 BF16 GEMM 이 Qwen 모양에서 **64–87 TFLOPS**(LM 머리 포함)(4.5절 표). 이것과 FLOP 계산으로 추천 구성의 BC 갱신은 **약 30 표본/s (추정)**, 2B + 호스트 옵티마이저는 **약 9 표본/s (추정)**.
4. **라이선스(6절)**: BEHAVIOR 데이터 묶음 약관은 "비상업 학술 연구만"·"OmniGibson 안에서만"·"어떤 요소도 재배포 금지" 다. 결정(결정 기록): 비상업 연구로 BEHAVIOR 를 계속 쓰고, 가중치는 연구용, 코드는 Apache-2.0, BEHAVIOR 자산은 재배포하지 않는다.

5. **역할(결정 기록, π0.5 꼴)**: 에이전트 = 대화 + 전체 목표·물체 id 넘기기 + 결과 알리기. RecallVLA = 다음 단계 문장 예측 → 그 단계로 행동 청크(한 모델). 지도 기억 덕분에 안 보이는 물체·다른 방까지 단계 선택에 쓴다.

### 1.3 우리 주장(논문 기여 후보)

0. **정확한 새로움 주장(조합)**: "**언어 조건 VLA 파운데이션 모델**로서, 따로 도는 **SLAM + 열린 어휘 검출 실행기(scenemap)가 온라인으로 만드는 물체 중심 3D 장면 그래프 기억** — 물체마다 명시 변화 상태(보임·옮겨짐·사라짐·들림), 출처(지금 봄 / 기억), 위치 불확실도, 방·벽 구조 — 를 **구조화된 토큰**으로 받아 **이동 집기·놓기**를 하고, **단계 문장 + 행동**을 내며, **자라는 지도 아래에서 학습**한 첫 모델(우리가 아는 한)." 2026-10-04 까지 찾은 것 중 이 조합을 다 갖춘 것은 없다.
   - 가장 가까운 Qian 외(2606.01072)와의 차이: 물체 변화 상태·출처·불확실도·방·벽 없음, 언어 조건·글 출력 없음, 과제별 모방 정책(시연 300–400)이지 VLA 가 아님.
   - POT-VLA: 과제 역할 물체 8 칸만(장면 기억 아님), 상태는 보임·확신뿐, 방·벽·글 없음, 사람형. EchoVLA·AtlasVLA: 조밀 복셀 특징(물체 단위 아님). Ledger: 2D·글로 계획기에, 탁상. AnywhereVLA·CodeGraphVLP: 지도·그래프가 VLA 입력이 아님. MEM: 영상 + 글 요약.
   - 논문에는 "to our knowledge" 로 쓰고 위 표를 싣는다. 제출 직전에 다시 검색한다.
1. **지도 토큰 계약**: 실제 SLAM·장면 그래프 출력(scenemap `sm_object`: `pos`, `extent`, `first_pos`, `n_obs`, `score`, `last_seen`, `state`)을 로봇 기준 상대 좌표, 출처(지금 봄 / 기억), 위치 불확실도, 나이, 이름 뜻·생김새 벡터(얼린 128-d 공간)로 바꾼 **고정 형식 토큰 19 개**(VLA_INPUT 1·3·4절). 다른 지도기도 같은 필드를 채우면 쓴다(3절).
2. **자라는 지도 아래 학습 + 검증**: 학습 중 지도를 GPU 근사로 에피소드 안에서 키우고(GPU_TRAINING 5.1), 진짜 scenemap 과 keyframe 마다 맞춘다(5.2 표, 음성 대조 포함). 지도 완성도(0 / 0–30 / 30–70 / 70–100 / 100 %)로 나눈 결과를 낸다.
3. **소비자 GPU 한 장 학습**: 시뮬·지도·렌더·모델·옵티마이저가 GPU 안(CUDA 그래프, 호스트 동기 없음)에서 돈다. 데이터는 GPU 시뮬이 무한히·라벨째 만든다(NVDEC·디스크 없음 — BC README G5: 학습 때 다시 렌더). SmolVLA(GPU 4 장 사전학습)보다 작은 자원에서의 레시피가 기여가 된다.
4. **지도에 근거한 단계 문장 + 행동**: 같은 모델이 "컵이 지도에 없음 — 거실을 탐색" 같은 단계 문장을 먼저 내고, 그 문장을 포함한 prefix 로 행동 청크를 낸다(π0.5 의 고수준·저수준 꼴).
- 주장하지 않는 것: "첫 지도·기억 VLA"(넓은 뜻으로는 EchoVLA 등이 먼저), 실제 집 일반화(실제 실험 규모가 작음), 대규모 사전학습 모델 수준의 말 능력.

### 1.4 이름

**RecallVLA**(결정 2026-10-04): "-VLA" 관례를 따르고, 물체를 기억하는 로봇이라는 저장소 주제와 맞는다. 이미 쓰인 이름: MAP-VLA(기억 보강 프롬프트), SG-VLA(arXiv 2603.22760), MemoryVLA(arXiv 2508.19236), ObjectVLA. 이름 충돌 검색(2026-10-04, 웹 `"RecallVLA"`, GitHub·HF 포함 검색): 같은 이름 없음. 소리가 비슷한 ReconVLA(재구성 시선 VLA, GitHub OpenHelix-Team/ReconVLA)가 있어 논문에서 헷갈리지 않게 적는다. 공개 직전에 다시 확인한다.

- 지도·몸 토큰은 지시보다 앞(인과적이라 지시 토큰과 단계 문장이 지도를 본다). POLICY 5.2 의 "얼린 LLM 이면 지도는 전문가로 바로" 는 몸통을 학습하므로 바꾼다 — 단계 문장이 지도를 근거로 해야 하기 때문(1.3절 4).
- 지도 토큰 위치 부호: 몸통의 RoPE 위치는 열 번호 그대로(1 차원). 비전 토큰에 Qwen 의 3D(mrope) 위치를 쓸지는 구현 때 HF 와 맞춰 정한다(같게 하는 것이 기본).

### 2.4 어텐션 가림

- 몸통: 인과(풀 어텐션 6 층) + 재귀(DeltaNet 18 층). 패딩은 열 끝에 둔다(인과라 앞 토큰에 영향 없음).
- 전문가: 행동 토큰 16 개 끼리 양방향, 몸통 prefix 0..L−1 전부(빈 물체 칸 키는 가림), 몸통은 행동을 보지 않는다.
- 지식 격리(KI, 스위치, 기본 켬): 전문가가 읽는 prefix 키·값에서 기울기를 끊는다. 몸통은 글 손실(+ 선택 이산 행동 토큰)로만 배운다(arXiv 2505.23705).
- 추론(π0.5 꼴 계층, 결정 기록): 추론마다(0.5 s, 앞 5 스텝 실행 — POLICY 5.3) ① prefix(영상·지도·몸·전체 목표 지시)를 앞으로 돌리고 ② **다음 단계 문장**을 탐욕 디코딩(≤ 16 토큰, KV 캐시·DeltaNet 상태 이어서) ③ 그 단계 문장까지 든 prefix 의 풀 층 K·V 로 행동 전문가가 청크를 낸다. 단계 문장이 바뀌면 실행기 결과의 단계 기록(subtask trace)에 남긴다.

### 2.5 행동 공간과 몸 무관 설계(공개용)

- 우리 로봇: 행동 8 = 몸통(vx, wz) + OMX-F joint1–5 + 그리퍼(VLA_INPUT 5절). 청크 16 × 8.
- 공개판: 행동·몸 벡터를 **최대 폭 32 로 채우고 가림**(π0 방식)과 **몸 종류 토큰** 하나. 칸 배치표(몸통 3, 팔 관절 ≤ 7, 그리퍼 1, 손끝 자세 9 …)를 고정해 다른 로봇이 같은 칸을 쓴다 (추정 — 다른 로봇 데이터로 확인 전).
- 지도·물체 토큰은 처음부터 몸 무관(로봇 기준 미터·라디안, 이름은 뜻 벡터)이다.

| 행동 | RecallVLA 행동 전문가 | 그 단계 문장을 든 prefix 를 보고 청크 16 × 8 |

### 2.8 기억 요약 인코더 — 기억 전체를 입력으로 (설계 2026-10-05, 신경망 구현 `e57acd7`)

> 쉬운 설명: [MEMORY_ENCODER.md](MEMORY_ENCODER.md).

> **갱신(10-05)**: 최종 설계·구현은 [TRAINING_DESIGN.md](TRAINING_DESIGN.md) — 신경망 쪽 구현·검증함(`training/vla` `VCfg::mem`). 바뀐 점: 열쇠 = 물체 + "기억에 없음" 하나(탐사 경계 후보는 검색 후보 아님), 물체 줄에 살펴본 정도 3, 따로 "있음" 머리, 탐사 방향은 따로 머리 없이 교사 행동·단계 문장에서, 탐사 경계 후보 토큰 → 방향 구역 8. 머리 16 × 64(텐서 코어 어텐션).

**왜**: 물체 칸 16 개(목표 + 가까운 순)로는 실시간으로 쌓이는 기억(수백 물체)의 일부만 본다. 멀리·다른 방 물체는 에이전트 힌트 없이는 모른다. RecallVLA 는 **갱신되는 기억 전체**를 매 스텝 받아 학습·추론해야 한다. → 기억 전체를 고정 개수 토큰으로 요약하는 인코더(Perceiver Resampler 방식 — Flamingo, Alayrac 외 2022)를 지도 인코더 자리에 둔다. 2.3 절의 "물체 16" 줄을 바꾼다.

**전체 구조 (추론 한 번)**

```
[입력]                                  [인코더]                          [몸통 입력 토큰]
리모 앞 카메라 RGB 256² ─┐
손목 카메라 RGB 256² ────┼─ SigLIP 2 B/32 (학습) ─ 사영 768→1024 ─── 영상 64 × 3
탑뷰 지도 그림 256² ─────┘

기억의 물체 전부 N 개 ── 물체 인코더 φ (공유 MLP 2 층, 304→1024) ──┐
 (N ≤ 256, 매 스텝 실시간 지도에서,                                ├─ 기억 요약 인코더 ── 기억 토큰 M = 32
  칸 형식 = 숫자 33 + 이름 128 + 생김새 128 + 1)                  │   (잠재 질의 32 가 물체 N 개를
지시 벡터 128 (training/embed 글 공간) ─── 선형 → 잠재 질의에 더함 ┘    교차 어텐션으로 읽음)
                                                   └ 주목 점수로 고른 물체 K = 8 ── φ ── 정밀 칸 8
벽 상태 56 + 안 본 곳 8 ─ 선형 ─────────────────────────────────────────────────── 벽 1
방 10 ─ 선형 ──────────────────────────────────────────────────────────────────── 방 1
몸: 팔·몸통·목표 칸(통합 목표) ─ 선형 ─────────────────────────────────────────── 몸 3
지시 문장 ─ Qwen 토크나이저 ─────────────────────────────────────────────────────── 글 ≤ 40

[몸통] Qwen3.5-0.8B 24 층 (DeltaNet 18 + 풀 어텐션 6, 인과)
   → 단계 문장 ≤ 16 토큰 (글 머리, 탐욕 디코딩)
   → 행동 전문가 6 블록(풀 어텐션 층 K·V 공유, flow matching) → 행동 청크 16 × 8
```

**기억 요약 인코더 세부**

| 부분 | 사양 | 변수 (계산) |
|---|---|---|
| 물체 인코더 φ | 304 → 1024 → 1024, **GELU**(구현 `training/vla`, 트랜스포머 표준·SigLIP 2 와 같음 — 교사 PPO 망도 10-06 결정으로 GELU 로 통일 예정). 기억의 모든 물체와 정밀 칸이 같은 φ 를 쓴다 | 약 1.4M |
| 잠재 질의 | 학습되는 1024 × 32. 그중 **2 개는 검색 질의**(집기용 q_pick, 놓기용 q_place), 30 개는 자유 요약. 지시 벡터(128 → 1024 선형)를 모든 잠재에 더해 지시에 맞게 요약 | 33K + 0.13M |
| 블록 × 2 | ① 교차 어텐션(잠재 → 물체 N 개, 머리 **16 × 64**(구현값 — 폭 1024 는 같고, 머리 폭 64 는 텐서 코어 어텐션 커널·표준값), 빈 물체 키 가림) ② 잠재끼리 자기 어텐션 ③ SwiGLU MLP 4096. 앞 RMSNorm | 블록당 약 21M → 약 42M |
| 출력 | 잠재 32 개 → 몸통 토큰 32 개(1024, 몸통 폭 그대로) | 0 |
| 정밀 칸 고르기 | 들고 있는 물체 + 목표(힌트·목표 칸이 있으면) + **q_pick·q_place 의 교차 어텐션 점수 상위** + 남으면 가까운 순, 합 K = 8. 고른 물체는 φ 로 다시 토큰(정확한 로봇·손끝 기준 좌표 그대로) | 0 |
| "없음" 열쇠 | q_pick·q_place 의 어텐션 열쇠에 학습되는 null 열쇠 하나를 붙인다. null 이 이기면 "기억에 없음" → 단계 문장이 탐사로 | 1K |

- 계산: 교차 어텐션 N × 32 (N ≤ 256) — 몸통 대비 무시할 만함. 몸통 열은 물체 16 → 기억 32 + 정밀 8 = 40 으로 **+24**(L ≤ 298 → 322, 4.5 절 표로 속도 다시 잴 것, (추정) 학습 속도 −8 %).
- 순서 없음: 물체에 자리 번호를 주지 않는다(집합). 기억 토큰 32 개는 잠재 순서가 고정이라 위치 부호를 그대로 쓴다.
- 지도 좌표·물체 id 없음(VLA_INPUT 원칙): φ 입력이 이미 로봇 기준 값뿐이다.
- 탑뷰 그림(공간 배치)과 기억 토큰(무엇이 어디에, 상태)은 역할이 겹치지 않게 둔다: 그림은 막힘·빈칸·미탐사·목표 자리, 기억 토큰은 물체의 정체·상태·불확실도.

### 4.2 손실
- L = λ_txt · CE(단계 문장) + λ_fm · flow matching(가림 있는 행동 차원만, BC README 와 같은 식) + λ_tok · CE(이산 행동 토큰, 스위치).
- 이산 행동 토큰: π0.5 는 FAST(DCT + BPE, arXiv 2501.09747). 첫 판은 차원마다 256 칸 나누기 토큰(어휘 끝 256 개 재사용)으로 하고 FAST 는 비교 (추정 — 어느 쪽이 나은지 재야 함).
- KI(기본 켬): 전문가 손실은 전문가·지도·몸 인코더로만 흐르고 몸통은 글·이산 토큰 손실로 배운다. 끈 판과 비교한다.
- 시작 값(추정): λ_txt 1, λ_fm 1, λ_tok 0.5. 지금 BC 처럼 τ ~ U(0,1)(π0 는 베타).

- 다른 로봇 자료(ME·CE) ↔ Open X-Embodiment·DROID 일부(몸 칸 가림, 필수). 비율이 π0.5 보다 훨씬 작다(5 % (추정)).
- 웹 자료(WD) ↔ VQAv2·RefCOCO·PixMo-Points·GQA(이해·접지만, 4.3b).
- 높은 수준 단계(HL) ↔ 단계 문장 출력(같은 모델이 단계 문장 → 행동, 결정 기록). 라벨은 시뮬이 자동으로 만든다(사람 주석 없음).
- 말 지시(VI) ↔ 없음. 대신 지시 바꿔 말하기·대화 맥락 흔들기(4.3b). 사람의 단계별 말 지시 자료는 모으지 않는다.
- π0.5 에 없는 것: 지도 기억 토큰(안 보이는 물체·다른 방) — 우리 주장(1.3절).

## 5. 평가 계획 (공개용)

### 5.1 시뮬 묶음
- 장면: 학습 집 / 안 쓴 집(CURRICULUM_BEHAVIOR2026 3절: 학습 4·평가 3 제안), 물체: 안 쓴 synset·처음 보는 이름(`aug_eval_unseen` 7 개 이상으로 늘림), 지시: heldout 바꿔 말하기.
- 과제: B1 집 안 이동, B2 찾기, B3 다가가기, B4 집기, B5 놓기, B2→B5 이어 하기.
- **지도 대조**: 지도 없음 / 정답 지도 / slam 근사 지도 / 낡은 지도(지도 만든 뒤 물체 옮김) / 잡음 지도. 지도 완성도 칸(0, 0–30, 30–70, 70–100, 100 %)마다 결과.
- 단계 문장 평가: 정답 단계와 정확히 같음 비율, 지도 상황("지도에 없음 → 탐색") 맞춤 비율.
- 접지 평가: 물체 칸의 "목표" 표시를 끈 채로(4.8절 목표 표시 떨굼). 평가 단계: GPU 시뮬 → OmniGibson(E7) → 실제 LIMO, 단계마다 떨어짐(4.8절).

### 5.2 지표와 통계

## 공용 물체 찾기 (10-05)

결정과 이유는 맨 앞 결정 기록 2026-10-05 "검색도 RecallVLA 가 한다 + 에이전트도 한다(같은 색인)" 줄. 여기는 만든 것의 세부만.

**한 색인, 두 사용자** — behavior-2026 `src/scene_graph/clip/include/sgsearch.h`(C++, `libsgclip_c.so`, 커밋 `5b969e7`)

| 사용자 | 질의 | 받는 것 |
|---|---|---|
| 에이전트 도구 [`search_objects`·`confirm_object`](../../src/agent/tools/search_objects/README.md) | 글(영·한) → 라벨 표 이름 또는 SigLIP 2 글 인코더(TensorRT, 0.8 ms) | `sgs_search_json` → 도구가 방·기준물·상태·경과·거리를 붙여 **글** |
| RecallVLA 실행기(9절 실행기 접점 뒤) | 몸통이 낸 질의 벡터 q(768, SigLIP 2 글 공간) | `sgs_search_vec(q, K)` → 상위 K `{id, score = P_app(q\|물체), cos}` → 물체 칸 |

**색인 형식**(기억 폴더 안, 상세 [clip README "물체 찾기"](../../src/scene_graph/clip/README.md))
- 물체 벡터(원본): 확률 모드(`objprob`) `objects/O<id>_views.f16`(n × 768 FP16) · `objects/O<id>_emb.f16`(μ). 확률 모드 전 기억은 best view 사진을 영상 엔진으로 뽑아 `cache/objsearch/O<id>_view.f16`.
- 이름: view.json `name`(등록), 확률 모드 `name_post`(들어오면). 확인 `confirmations.jsonl`(원본, 보정 데이터). `cache/objsearch/names.json` 은 다시 셀 수 있는 캐시.
- 물체 안 상대 확률 `P_app(c|o) = softmax_c 평균_v log softmax_c(t · cos(z_v, 글_c))`(라벨 = main synset 3,244 + 이 기억의 이름), 이름 사후 = 바탕 × 등록 우도비 3 × 확인 우도비(user 50, close_look 10).

**3 단계 재검색**: ① 이름(등록·확인 이름, 동의어, 아래말) → p_name 최고 < 0.5 면 자동으로 ② 이름 무시 생김새(`p_query ≥ 0.1`, 물체 안 질의 순위 1 — 등록 이름 빼고),
이름으로 확실한 물체가 있으면 영상↔영상 cos 도 → ③ `confirm_object` 로 이름 사후 갱신, 다음엔 ① 에서. 생김새로만 찾은 후보·비슷한 후보 둘·약한 후보에는 `ask_user`.

**측정**(BEHAVIOR 집 LIMO 탐사 기억, 그때 분할 FastSAM-s(지금 기본은 ObjectSAM) + SigLIP 2, 283 물체 — 정답 종류 질의 18·없는 물체 질의 40):

| | R@1 | R@5 | 이름으로 못 찾는 물체 R@5 | 없는 물체 헛찾음 (묻지 않고 행동) | 지연 |
|---|---|---|---|---|---|
| 이름만 | 0.11 | 0.22 | 0.00 | 0.05 (0.03) | ≈ 0.1 ms |
| 이름 + 생김새 | 0.39 | 0.56 | 0.33 | 0.15 (0.03) | ≈ 0.1 ms, 자유 글 ≈ 1 ms |

같은 장면 slam 자세 판(296 물체) 0.39·0.50·0.33·0.15 (0.05). 라디오 실제 사례: 4 조각 중 "speaker"·"bag" 로 등록된 둘이 생김새로 1·2 위, 확인 뒤 사후 0.13 → 0.88.
VLA 질의 벡터 쪽(`sgs_search_vec`)은 학습된 q 가 없어 아직 재지 않았다(가짜 기억 시험만).

**뒤 VLA 학습에 쓸 것**(구현 안 함 — 9절 후속): (1) 학습 장면에서 **일부 물체 이름을 일부러 틀리게**(다른 종류 이름·상위어·빈 이름) 넣어 물체 칸의 이름 확률보다
생김새 벡터를 믿게, (2) 에이전트 **힌트 id 지우기(hint dropout)·틀린 힌트** 섞기 — 힌트가 없거나 틀려도 자기 검색 상위 K 로 찾게, (3) 검색 InfoNCE 의 음성으로
같은 이름·다른 생김새 물체, (4) `confirmations.jsonl` 의 확인 기록(질의·등록 이름·그때 확률)을 우도비·문턱 보정과 검색 평가 자료로.

## 자체 기억 검색 — 에이전트 없이 (설계, 2026-10-05, 구현 전)

> **갱신(같은 날)**: 아래 "`<recall>` 토큰 → 상위 K 덧붙이기" 안은 **2.8 절 기억 요약 인코더로 대신한다**(기억 전체를 매 스텝 요약 토큰 32 개로 받고, 그 안의 검색 질의 2 개의 주목 점수로 정밀 칸을 고른다 — 두 번 돌림 없음). 아래의 점수 식·"없음" 열쇠·학습(InfoNCE, 어려운 오답, 힌트 지우기)·평가는 2.8 절이 그대로 이어 쓴다. 기록으로 남긴다.

**문제**: 지도 기억에는 물체가 계속 쌓이는데(수백 개) 몸통이 보는 물체 칸은 16 개(목표 + 가까운 순)뿐이다. 에이전트가 검색해 id 힌트를 주지 않으면 멀리·다른 방에 있는 목표는 칸에 못 들어와, 기억에 있는데도 탐사부터 한다. → **RecallVLA 가 스스로 기억 전체에서 필요한 물체를 불러온다.** 에이전트 힌트는 있으면 쓰는 선택 입력으로 내린다.

```
prefix: 영상 3 장 · 가까운 물체 16 칸 · 벽 · 방 · 몸 · 목표 칸 · 전체 지시 · 직전 단계 문장
  → <recall> 토큰 2 개(집기용·놓기용)를 한 스텝 더 돌림
  → 두 은닉 → 질의 q_pick, q_place (각각 이름 128 + 생김새 128, training/embed 의 얼린 128-d 공간)
  → 기억 전체 N 개와 점수 (몸통 밖: 시뮬은 GPU 커널, 실제는 sgsearch `sgs_search_vec` 과 같은 식)
  → 역할마다 상위 K = 4 + "없음" 판정
  → 불러온 칸 토큰 8 개를 <recall> 뒤에 덧붙임(역할 태그 집기 / 놓기, 순위 번호 없음)
  → 단계 문장 디코딩(불러온 칸을 보고: "the cup is in the kitchen; go to the kitchen")
  → 행동 전문가
```

- 불러온 칸을 지시·단계 문장 **앞**이 아니라 `<recall>` **뒤**에 덧붙이므로 prefix 를 다시 계산하지 않는다(인과 몸통에 이어 붙이기). 단계 문장과 행동은 불러온 칸을 본다.
- 검색은 단계 문장이 바뀔 때마다 다시 한다(컵 → 선반). 그 사이 스텝은 같은 id 를 따라가며 칸 값(로봇 기준 위치 등)만 매 스텝 새로 만든다.
- 열 길이: L ≤ 232 + `<recall>` 2 + 불러온 칸 8 = 242(2.3 절 한도 안에서 다시 계산).

### 점수 (물체 i, 역할 r)

```
s_ri = MLP_r( cos(q_r^name, 이름_i), cos(q_r^app, 생김새_i),        ← 의미론 + 임베딩
             상태 one-hot 4, log(1 + 마지막 본 뒤 시간), 위치 불확실도,
             로봇까지 경로 거리(지도 경로, 없으면 직선), 같은 방인지 )
```
- 이름_i = 이름 사후의 기대 글 벡터(확률 모드 `name_post` 로 가중 평균 — 이름이 틀려도 생김새 항이 받침), 생김새_i = vMF 대표 μ 를 128 로 투영.
- **"없음" 열쇠**: 학습되는 null 점수 s_r∅. 모든 s_ri < s_r∅ 면 "기억에 없음" → 단계 문장이 탐사로. 목표를 아직 못 본 판(C0 빈 지도)에서 정답이 "없음".
- 들고 있는 물체는 항상 칸에 둔다(검색과 별개).

### 학습

| 손실 | 내용 |
|---|---|
| 검색 InfoNCE | 역할마다 정답 물체(시뮬 판의 집기 대상·놓을 곳, 못 봤으면 "없음")에 대한 softmax CE, 후보 = 그 판의 기억 전체 + 없음. 음성에 같은 이름·다른 생김새, 같은 종류 이웃(식탁 의자 둘), 이름을 일부러 틀린 물체 |
| 기존 | 단계 문장 CE + flow(4.2 절), λ_rec 시작 0.5 (추정) |

- **불러온 칸을 학습 때 어떻게 넣나**: 앞으로 돌린 q 로 고른 상위 K 를 쓰되, 확률 p 로 정답을 끼워 넣는다(예정된 표본 — 처음 p = 1 → 0.2). 그래서 두 번 돌림: 1 회 `<recall>` 까지(가볍게, 전문가 없음) → 상위 K → 2 회 전체. 늘어나는 계산은 prefix 한 번(4.5 절 표로 다시 잴 것).
- **에이전트 없이 되게**: 목표 표시·목표 칸·힌트를 판의 일부에서 모두 지운다(지금 목표 표시 지우기 0.5 를 확장). 힌트를 줄 때는 일부를 일부러 틀리게.
- **이름 틀리기**: 학습 장면 물체 일부의 이름 사후를 다른 종류·상위어·빈 이름으로 → 생김새 항을 믿게(공용 물체 찾기 절 (1)).
- RL 교사는 그대로(특권으로 목표를 안다). 검색은 학생(BC)·RecallVLA 가 배운다. 교사의 칸 고르기는 정답 목표 + 가까운 순.

### GPU 시뮬에 필요한 것 (`training/RL/map`·`observation`)

- 판마다 **기억 표**(지도 근사가 이미 아는 물체 전부, N ≤ 256): 이름 행·생김새 행·상태·시간·불확실도·방. 지금은 가까운 16 만 칸으로 만든다 → 표 전체를 장치에 둔다.
- 점수·상위 K 커널(N × 256 내적 + 작은 MLP, 판마다), 호스트 동기 없음, CPU == GPU 비트 동일 검증(map_verify 에 추가).
- 같은 칸 인코더로 불러온 칸 토큰을 만든다(칸 형식 그대로 — 지도 좌표·id 없음, 로봇 기준 값만).

### 실제 실행기

- 같은 점수 식을 C++ 로(`sgsearch.h` 의 `sgs_search_vec` 을 역할·MLP 점수로 넓힘). 기억은 실시간 scenemap 스냅숏.
- 에이전트가 있으면 힌트 id 를 "힌트" 태그 칸으로 하나 더 넣을 수 있다(없어도 동작).

### 평가 (5 절에 더함)

- 검색: 역할별 R@1·R@4, "없음" 정확도, 이름이 틀린 물체 R@4.
- 과제: **에이전트 없이** 집기·놓기 성공률 — 목표가 ① 보임 ② 같은 방·안 보임 ③ 다른 방 ④ 옮겨짐 ⑤ 이름 틀림 ⑥ 아직 못 봄(탐사 필요). 비교: 가까운 16 칸만 / 에이전트 힌트 / 자체 검색 / 둘 다.
- 같은 이름 여럿("빨간 컵", "부엌의 컵") 구분률.
