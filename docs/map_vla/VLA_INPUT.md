# 우리 VLA 입력·출력 설계 (리모 + OMX-F, 지도 토큰)

작성 2026-10-03. **설계 문서**다. 2026-10-04 에 학습 쪽(시뮬·GPU) 구현을 이 설계에 맞췄다 — 절마다 끝의 **구현 상태** 메모(잰 값만). 학습 흐름(RL 전문가 → 시연 → VLA 모방학습)은 [training/README.md](../../training/README.md) 의 `RL/`·`BC/`, 로봇 설명은 [src/robot/README.md](../../src/robot/README.md).

π0.5 는 입력이 영상 + 관절 state + 글이다. 우리는 여기에 **지금 도는 물체 기억(Spark-DSG 장면 그래프, scenemap)** 을 **토큰 몇 개**로 넣은 작은 VLA 를 직접 만든다.

- 앞 문서 [MAP_STATE_PLAN.md](MAP_STATE_PLAN.md) 의 물체 슬롯(16 × 14, 클래스 id)을 이 문서가 바꾼다: 클래스 id 대신 **이름 뜻 벡터 + 생김새 벡터**, 손과의 관계, 로컬라이제이션 출처를 더했다.

## 0. 원칙

1. **모든 위치는 상대 좌표**다. 로봇(`base_link`) 기준, 손끝(`omx_end_effector_link`) 기준. 지도 원점 좌표(`map`)는 넣지 않는다.
2. **어떤 지도·집에서도 같은 뜻**이어야 한다. 지도마다 다른 값(지도 좌표, 방 id, 물체 id, 클래스 번호, 칸 순서, 지도 크기)은 넣지 않는다.
3. **로컬라이제이션이 필요 없는 값을 먼저** 쓴다. 지금 보이는 것은 카메라 + 깊이 + 순기구학으로 바로 잰다. 지도(기억)는 안 보이는 것에만, 출처와 불확실도를 붙여서.
4. **이름은 뜻으로 넣고 외우지 않게** 한다. 얼린 글 인코더 벡터 + 학습 때 이름 흔들기 + 처음 보는 이름으로 평가.
5. **시뮬은 실제 로봇과 같게**([plan.md](../plan.md) 코드 규칙). 같은 URDF(`src/robot/map_vla_description`)로 순기구학·카메라 위치를 계산하고, 학습 값은 정답 자세가 아니라 `slam` 자세로 만든다.

## 1. 입력 한눈에

| 입력 | 내용 | 토큰 |
|---|---|---|
| 카메라 2장 | 리모 깊이 카메라(Orbbec)의 RGB, OMX 손목 카메라(`wrist_cam_link`) RGB | 영상 토큰 |
| 몸 상태 56 | 2절 | 3 (팔 · 몸통 · 목표) |
| 물체 칸 ≤ 16 × 289 | 3절 | 물체마다 1 |
| 주변 공간 | 4절 | 2 (벽 · 방) |
| 지시 문장 | LLM(Qwen, KAU API)이 준 지금 단계 한 줄. 예: "식탁 위 컵을 집어" | 글 토큰 |

- 지도 관련 토큰은 많아야 **16 + 2 + 1(목표) = 19 개**다. 같은 지도를 글로 풀면 100–200 토큰이 든다.

> **구현 상태(1절, 2026-10-04)**: 토큰마다 학생 `training/BC/include/tf.h`(BC 설정 `arch: 1`) — 표본마다 토큰 150 = 영상 128(머리 카메라 64 + 손목 64, 얼린 SigLIP 2 B/32-256 패치 토큰) + 글 1 + 몸 3 + 물체 16 + 벽 1 + 방 1. 손목 카메라는 `wrist_cam_link` 자세(URDF 순기구학, 팔 6 각)에서 그린다(`src/bc_render.cu wrist_pose`). 지시 문장은 지금 LLM 이 아니라 표(`training/data/vla_v1/instr.jsonl`, 과제마다 바꿔 말하기)에서 고른다.

## 2. 몸 상태 (56)

| 묶음 | 값 | 개수 | 어디서 |
|---|---|---|---|
| 팔 관절 각도 | OMX-F joint1–5 + 그리퍼 | 6 | Dynamixel 현재 위치 |
| 팔 관절 속도 | joint1–5 + 그리퍼 | 6 | Dynamixel 현재 속도 |
| 관절 위치 xyz | joint1–5 축 + 손끝, 각 x·y·z (`base_link` 기준) | 18 | URDF 순기구학 |
| 손끝 방향 | 회전행렬 앞 두 열(6D) | 6 | 순기구학 |
| 손끝 속도 | 선속도 3 + 각속도 3 | 6 | 야코비안 × 관절 속도 |
| 몸통 속도 | vx, vy, wz | 3 | 리모 바퀴 오도메트리 |
| 직전 명령 | 바로 전 행동(5절) | 8 | 정책 자신 |
| 손끝 → 목표 | 목표 물체(또는 목표 지점) − 손끝, xyz | 3 | 3절 + 순기구학 |

- 토큰: **팔**(각도·속도·관절 xyz·손끝 방향·속도), **몸통**(몸통 속도), **목표**(손끝 → 목표, 직전 명령, 다음 경유 지점 방향·거리 — 4절).
- 관절 xyz·손끝 방향·속도는 각도·속도에서 계산되는 값이지만, 모델이 순기구학을 배울 필요가 없게 넣는다. 시뮬과 실제 모두 같은 URDF 로 계산해야 한다.
- 직전 명령은 행동을 부드럽게 하지만 기대면 되풀이한다 → 학습 때 가끔 지우거나 잡음.
- 속도 값은 실제 센서 잡음이 크다 → 시뮬 학습 때도 비슷한 잡음을 넣는다.

> **구현 상태(2절)**: 환경 관측(`training/RL/env/include/env.h` step_core)이 표 그대로 56 개다 — 팔 각 6, 속도 6, 관절 xyz 15 + 손끝 3, 손끝 방향 6, 손끝 속도 6, 몸통 vx·vy(0, 차동)·wz 3, 직전 명령 8, 손끝 → 목표 3(`observation/obs.h` 의 정적 검사 `G_PREV + 8 == G_EE_TGT`). 손끝 방향 6 개의 차례는 회전행렬 앞 두 열을 **행마다 엇갈려**(R00, R01, R10, R11, R20, R21) 둔다(값은 같은 두 열). 토큰 묶음: 팔 = 관측 0..41(42), 몸통 = 42..44, 목표 = 직전 명령 8 + 손끝 → 목표 3 + 다음 경유 지점 4(`bc.cu tf_pack_k`). 직전 명령 지우기·잡음과 속도 잡음은 학습 때 장치 값(`obs.h ObsAug`).

## 3. 물체 칸 (≤ 16 칸, 칸마다 289 → 토큰 1)

scenemap 물체(`sm_object`: `pos`, `extent`, `first_pos`, `n_obs`, `score`, `last_seen`, `state`)와 이름 캐시(`cache/names.json`), 물체 벡터(`objects/O<id>_emb.f16`)에서 만든다.

| 값 | 개수 | 계산 |
|---|---|---|
| 위치 xyz (로봇 기준) | 3 | 보이면 이번 프레임 마스크 + 깊이 → 카메라 → 로봇(카메라 장착은 URDF). 안 보이면 지도 `pos` − SLAM 자세 |
| 위치 xyz (손끝 기준) | 3 | 위 − 손끝(순기구학) |
| 거리·방향 (로봇에서) | 2 | 위치에서 |
| 크기 | 3 | `extent` (축 맞춤 상자) |
| 손끝 ↔ 중심 거리 | 1 | 손끝 기준 xyz 의 길이 |
| 손끝 ↔ 겉면 거리 | 1 | 손끝에서 상자 가장 가까운 면까지, 안이면 0 |
| 팔이 닿는지 | 1 | 리모를 안 움직이고 OMX 만으로 닿는지(URDF 관절 한계로 미리 계산한 작업 공간) |
| 처음 자리에서 옮겨진 양 | 3 | `pos − first_pos` (로봇 기준 회전만 적용) |
| 물체 속도 | 3 | 이전 스냅숏과의 차이(들려 움직일 때 등) |
| 상태 | 4 | 보임 / 사라짐 / 옮겨짐 / 들고 있음 (`state`) |
| 마지막 본 뒤 시간 | 1 | `last_seen` |
| 믿을 만한 정도 | 2 | 검출 점수(`score`), 본 횟수(`n_obs`) |
| **출처** | 1 | `지금 보는 중`(카메라에서 바로) / `기억`(지도) |
| **위치 불확실도** | 1 | 기억이면 마지막으로 본 뒤 로봇이 움직인 거리·회전에 따라 커짐(바퀴 오도메트리 오차) |
| 같은 방인지 | 1 | 방 배정 |
| 목표인지 | 1 | 목표 물체 표시(순서가 아니라 이 값으로) |
| 이름 확신도 | 2 | 라벨 표 1위 점수, 1위 − 2위 |
| **이름 뜻 벡터** | 128 | 이름(라벨 표 1위, 확신 낮으면 상위어)을 **얼린** SigLIP 2 글 인코더로 → `training/embed` 128-d 투영(얼림). 한국어 이름은 한국어 학생 인코더(같은 공간) |
| **생김새 벡터** | 128 | 물체 조각의 SigLIP 2 영상 벡터 → 같은 128-d 투영 |
| 합계 | 289 | 숫자 33 + 이름 뜻 128 + 생김새 128 |

- 칸마다 **같은 작은 MLP** 로 토큰 1개를 만든다. 칸에는 위치 번호를 붙이지 않는다(순서 없는 집합). 빈 칸은 마스크.
- 칸 고르기: 목표 물체는 항상 넣고, 나머지는 로봇에서 가까운 순으로 최대 16. 물체가 0개여도 동작한다.
- 이름 뜻 벡터와 생김새 벡터, 지시 문장이 **같은 SigLIP 2 공간**이라 "지시 ↔ 이름 ↔ 실제 생김새" 를 바로 비교할 수 있다. 이름이 틀려도(라디오를 "satchel" 로 부름) 생김새로 찾는다.
- 물체 방향(회전)·잡을 자리는 scenemap 에 없다. 필요하면 물체 점 구름(`objects/O<id>_points.ply`)으로 계산해 칸에 붙인다(긴 물건 집기).

> **구현 상태(3절)** — `training/RL/map/include/map_tok.h`(GPU 근사 지도 토큰, CPU == GPU 비트 동일 `map_verify`), 실제 scenemap 쪽 변환기 `sm_tok.h` 도 같은 작업 공간 규칙.
> - **이름 뜻·생김새·지시 벡터**: `training/embed` 의 얼린 128-d 공간(P, `sb32_pe_300k`)에 둔다 — 영어 글 = PE-L 글 탑 + P(라벨 표 `objects-v1` 의 text128 행 그대로), 한국어 = 한국어 학생 + P, 생김새 = 우리 GPU 렌더 조각 → C++ SigLIP 2 B/32 탑 → C++ MAP 풀링 + 머리 h(PyTorch 대비 코사인 최소 0.99996). 이 문서의 "SigLIP 2 글 인코더 → 128 투영" 은 embed 의 라벨 표 약속(글 = PE-L + P)으로 구현했다. 표 `training/data/vla_v1`: 이름 584 줄(시뮬 6 종류 + BEHAVIOR 2026 과제 100 개의 물체 synset 259, 동의어·상위어, 평가용 처음 보는 이름 7), 지시 40 문장, 생김새 7 줄(시뮬 6 종류 + 유령). 토큰에는 표 행 번호만 두고(계획서 4.4), 신경망 입력을 만들 때 장치 표에서 128 칸씩 옮긴다(칸 입력 304 = 숫자 33 + 128 + 128 + 1).
> - **이름 확신도 2 / 상위어**: 1위 점수 = cos(생김새, 이름), 1위 − 2위 = 이름 어휘 440 줄 안 다른 이름 최댓값과의 차(`vla_vocab.h`, 생김새 행 × 이름 종류 표). 1위 − 2위 < −0.08 이면 이름 행 = 상위어. **한계**: 지금 시뮬 물체는 색 상자라 생김새가 종류를 거의 못 가른다(종류끼리 코사인 0.92–0.98) → 맞는 이름도 셋 중 하나꼴로 상위어(A1 무작위 행동 판의 채운 칸 0.448 이 상위어). 메시 렌더 뒤 표·문턱을 다시 만든다(도구는 그대로).
> - **팔이 닿는지**: URDF 순기구학 + 실제 관절 한계로 joint2·3·4(241³)·joint5(5) 를 훑은 (r, z) 작업 공간 표(`omx_workspace.h`, 1 cm 칸 2,201 개, r ≤ 0.41 m, z −0.15–0.51 m base_link, 생성기 `training/RL/tools/omx_ws`). 물체 상자의 (r, z) 범위(바닥 자국 외접원)가 표와 겹치면 1. 예전 0.40 m 구는 뺐다.
> - **출처·위치**: 지금 보는 중(마지막 keyframe 에서 봄) 칸의 위치는 그 관측 자리(`Slot::meas`), 기억 칸은 지도 자리 − slam 자세. **위치 불확실도**는 마지막으로 본 뒤 믿는 오도메트리 이동·회전 × 오도메트리 잡음 규칙(그대로). 옮겨진 양·속도·같은 방·목표·상태·시간·점수·본 횟수는 예전 그대로 표 정의와 같다.
> - 학습 때 이름 흔들기(같은 무리 다른 말·상위어·비슷한 틀린 이름·지우기)·칸 지우기·지도 통째로 비우기는 장치 값(`obs.h ObsAug`, 6절).

## 4. 주변 공간 (토큰 2) · 목표 지점

| 토큰 | 값 | 어디서 |
|---|---|---|
| 벽 | 벽 상태 벡터 56(16 방향 거리 + 가까운 벽 선분 8 개), 로봇 기준 | `sm_snap_wall_state`. 지금 깊이 스캔으로 바로 계산하는 것이 원칙(로컬라이제이션 불필요) |
| 방 | 지금 방 종류 확률(kitchen·bathroom·bedroom·living room·office·unknown), 가까운 문 방향·거리 | 방 나누기·이름([model_selection.md](../model_selection.md) "방 나누기·이름") |
| (목표 토큰에) 다음 경유 지점 | 로봇 기준 방향·거리 | place 경로(`sm_snap_place_path`) − SLAM 자세 |

- 방 id·방 개수·지도 크기는 넣지 않는다.
- 거리는 5 m 쯤에서 자르고 먼 값은 로그로 눌러 정규화한다. 정규화 통계는 학습 데이터로 계산하고 실제 로봇도 같은 값을 쓴다.

> **구현 상태(4절)**: 방 토큰 = 방 종류 6(시뮬은 방 종류를 알아 확률이 한 칸 1 — 실제 방 분류기 확률 자리) + 가까운 문 x·y(로봇 기준)·거리·있음. 방 id·개수 없음. **다음 경유 지점**(sm_snap_place_path 대신): 믿는 점유 격자를 0.2 m 로 묶고 1 칸 부풀려(안 본 칸은 지나감) 목표 칸에서 8 이웃 BFS, 로봇 칸에서 내리막으로 5 칸(약 1 m) 간 자리 = 로봇 기준 x·y, 목표까지 경로 길이, 있음(`MapTok::way`, 1,296 B). A2·처음 지도 섞음 무작위 행동 판: 목표 칸이 있는 스텝의 0.995 에서 길을 찾고 경로/직선 1.325. **정규화**: 길이 값 = sign·ln(1 + min(|x|, 5 m)/0.5), 각도 /π, 시간·횟수 ln(1+x), 그 뒤 시뮬 자료(A1·A2 각 512 판 × 400 스텝, 처음 지도 섞음)로 낸 평균·표준편차로 표준화(`observation/include/tok_norm.h`, 생성기 `tools/tok_stats`) — 실제 로봇도 같은 헤더를 쓴다. 0/1·확률 값은 그대로, 없는 값(빈 칸·안 맞은 선분·문 없음·경유 지점 없음)은 0.

## 5. 출력

- 행동 8 = 몸통(vx, wz) 2 + 팔 joint1–5 5 + 그리퍼 1. 리모를 메카넘으로 쓰면 몸통 3(vx, vy, wz)으로 9.
- 청크: 10 Hz × 16–32 스텝(1.6–3.2 s). 앞 몇 스텝만 실행하고 새 영상·지도로 다시 추론한다.
- 액션 전문가: flow matching(π0.5·`BC` 계획과 같음).
- **글 출력(2026-10-04 설계 추가)**: 행동 앞에 같은 모델이 **지금 단계 문장**(예 "pick up the cup from the table", "the cup is not in the map; explore the living room", ≤ 16 토큰)을 내고, 행동 전문가는 그 문장을 포함한 prefix 를 본다(π0.5 의 고수준 단계 → 저수준 행동). 큰 모델 사양·토큰 배치는 [MAPVLA_SPEC.md](MAPVLA_SPEC.md) 2.3절. 지금 작은 학생(아래 구현 상태)은 글을 내지 않는다.

> **구현 상태(5절)**: 행동 8(차동). 환경은 늘 팔을 풀고, 단계마다 학습하는 행동은 **장치 값 비트 가림**(PPO `TrainState::act_mask`·`ppo_set_act_mask`·설정 단계 `act_mask`, BC `act_mask`·`bc_set_act_mask`) — 꺼진 행동은 0(= 팔 홈 자세)이라 팔 묶음과 비트가 같다(`env_verify --arm-zero`). 교사 표본·logp·엔트로피, BC 라벨·MSE·flow 손실, 학생 출력이 같은 가림을 쓴다. 학생 청크 = 10 Hz × H(기본 16) × 행동 8, flow matching 행동 전문가(토큰마다 학생은 행동 토큰 H 개가 prefix 를 보는 트랜스포머).

## 6. 학습 데이터 규칙 (일반화)

| 규칙 | 하는 것 |
|---|---|
| 여러 집 | BEHAVIOR 여러 장면으로 RL·시연을 모은다. 평가는 학습에 안 쓴 집으로 |
| `slam` 자세 | 기억 값은 정답 지도가 아니라 실제와 같은 오차가 든 `slam` 자세로 만든다 |
| 덜 만들어진 지도 | 물체 칸 무작위로 지우기, 위치 잡음, 가짜 물체 섞기(탐사 초반·검출 실수 흉내) |
| 지도 없이 | 가끔 지도 토큰을 통째로 비운다 → 카메라만으로 기본 동작, 지도는 보조 |
| 이름 바꾸기 | 같은 뜻 다른 말(cup ↔ mug ↔ 컵 ↔ 머그잔, 상위어 식기) — 라벨 표 동의어·WordNet 상위어 |
| 이름 지우기 | 가끔 이름 뜻 벡터를 비운다 → 생김새만으로도 |
| 틀린 이름 | 가끔 비슷한 다른 이름(컵 ↔ 그릇)으로 바꾼다 → 생김새와 맞춰 보기 |
| 지시 바꾸기 | "컵을 집어" → "머그잔 집어줘" 처럼 같은 뜻 다른 말 |
| 센서 잡음 | 관절·바퀴 속도, 깊이에 실제 수준의 잡음 |

> **구현 상태(6절)**: 장치 값 `ObsAug`(`training/RL/observation/include/obs.h`): 속도 잡음, 직전 명령 지우기·잡음, 이름 흔들기 4 종, 칸 지우기, 지도 통째로 비우기 — PPO 는 롤아웃·갱신이 같은 열쇠(같은 입력), BC 는 학생만(교사 라벨 입력은 깨끗). 지시 바꾸기 = 에피소드마다 과제의 바꿔 말하기 하나. 렌더(학생만): 판마다 색 변형·조명 방향·노출 흔들기와 팀 기본 설정 섞기(`render_aug`). 얼린 인코더 토큰 코사인(상태 128 개): 싼 설정 대 팀 기본 0.719, 싼 설정 대 흔든 싼 설정 0.689 — 흔들기 폭이 두 설정 차이와 같은 크기다. 여러 집·`slam` 자세·위치 잡음·가짜 물체는 예전 지도 근사 그대로(장면 생성기는 아직 하나).

## 7. 외웠는지 확인하는 평가

| 평가 | 통과 기준 |
|---|---|
| 학습에 **안 나온 물체 이름**만(예: 학습엔 컵·병, 평가엔 텀블러·주전자) | 학습 때 본 이름과 비슷한 성공률 |
| 학습에 **안 쓴 집** | 같은 집과 비슷한 성공률 |
| 지도 없음 대 있음 | 지도가 있을 때 더 좋아야 함(지도가 보조로 쓰이는지) |
| `gt` 지도 대 `slam` 지도 | 차이가 작아야 함(로컬라이제이션 오차에 강한지) |

> **구현 상태(7절)**: 처음 보는 이름 = `aug_eval_unseen` 1(이름 행을 같은 무리의 학습 안 쓴 이름 — mug·tumbler·crate·side chair·worktable·sideboard·wastebasket — 으로, 지시는 heldout 바꿔 말하기로; 학습 흔들기는 이 이름을 뽑지 않음). 지도 없음 = `use_map 0` 또는 `aug_p_map_off 1`. 안 쓴 집·`gt` 대 `slam` 평가는 아직(장면 생성기 하나, 지도 근사는 늘 slam).

## 8. 아직 정할 것

- **어디서 돌릴지**: 리모 위(Jetson Nano 4GB 또는 라즈베리파이 5 + DX-M1)면 작은 몸통(SigLIP 2 B/32 패치 토큰 — 물체 기억과 인코더를 나눠 씀 — + 작은 트랜스포머 6–8 층), PC·서버면 `BC` 계획의 Qwen3.5-2B(얼림)로 시작. 지금 SigLIP 2 엔진은 풀링된 벡터 하나만 내므로 패치 토큰을 내는 판을 다시 내보내야 한다([training/model/README.md](../../training/model/README.md)).
- **리모 바퀴 모드**: 차동(행동 8) 또는 메카넘(행동 9).
- **OMX-F 작업 공간**: "팔이 닿는지" 를 계산할 범위. URDF 관절 한계에서 뽑는다.
- **지금 보이는 물체의 즉시 3D**: scenemap 이 keyframe 마다 검출 + 깊이 → 3D 를 이미 계산한다. 지도에 넣기 전 값을 꺼내는 C ABI 가 필요하다.

> **구현 상태(8절)**: OMX-F 작업 공간은 뽑았다(3절 메모 — 손끝이 base_link z 0.51 m 까지, 곧 바닥 위 0.66 m 까지라 탁자 윗면 0.7–0.8 m 의 물체는 표 밖). 몸통은 안 B 의 작은 판(토큰마다 학생, 기본 d 256·6 층, 변수 9.2 M)으로 시작했다. 지금 보이는 물체의 즉시 3D 를 꺼내는 scenemap C ABI 는 아직 없다(시뮬 근사는 keyframe 관측 자리를 씀).
