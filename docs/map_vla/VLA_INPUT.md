# 우리 VLA 입력·출력 설계 (리모 + OMX-F, 지도 토큰)

작성 2026-10-03. **설계 문서**다. 코드는 아직 없다. 학습 흐름(RL 전문가 → 시연 → VLA 모방학습)은 [training/README.md](../../training/README.md) 의 `RL/`·`BC/`, 로봇 설명은 [src/robot/README.md](../../src/robot/README.md).

π0.5 는 입력이 영상 + 관절 state + 글이다. 우리는 여기에 **지금 도는 물체 기억(Spark-DSG 장면 그래프, scenemap)** 을 **토큰 몇 개**로 넣은 작은 VLA 를 직접 만든다.

- 앞 문서 [MAP_STATE_PLAN.md](MAP_STATE_PLAN.md) 의 물체 슬롯(16 × 14, 클래스 id)을 이 문서가 바꾼다: 클래스 id 대신 **이름 뜻 벡터 + 생김새 벡터**, 손과의 관계, 로컬라이제이션 출처를 더했다.

## 0. 원칙

1. **모든 위치는 상대 좌표**다. 로봇(`base_link`) 기준, 손끝(`omx_end_effector_link`) 기준. 지도 원점 좌표(`map`)는 넣지 않는다.
2. **어떤 지도·집에서도 같은 뜻**이어야 한다. 지도마다 다른 값(지도 좌표, 방 id, 물체 id, 클래스 번호, 칸 순서, 지도 크기)은 넣지 않는다.
3. **로컬라이제이션이 필요 없는 값을 먼저** 쓴다. 지금 보이는 것은 카메라 + 깊이 + 순기구학으로 바로 잰다. 지도(기억)는 안 보이는 것에만, 출처와 불확실도를 붙여서.
4. **이름은 뜻으로 넣고 외우지 않게** 한다. 얼린 글 인코더 벡터 + 학습 때 이름 흔들기 + 처음 보는 이름으로 평가.
5. **시뮬은 실제 로봇과 같게**([plan.md](../plan.md) 코드 규칙). 같은 URDF(`src/robot/map_vla_description`)로 순기구학·카메라 위치를 계산하고, 학습 값은 정답 자세가 아니라 `slam` 자세로 만든다.

## 1. 입력 한눈에

| 입력 | 내용 | 토큰 |
|---|---|---|
| 카메라 2장 | 리모 깊이 카메라(Orbbec)의 RGB, OMX 손목 카메라(`wrist_cam_link`) RGB | 영상 토큰 |
| 몸 상태 56 | 2절 | 3 (팔 · 몸통 · 목표) |
| 물체 칸 ≤ 16 × 289 | 3절 | 물체마다 1 |
| 주변 공간 | 4절 | 2 (벽 · 방) |
| 지시 문장 | LLM(Qwen, KAU API)이 준 지금 단계 한 줄. 예: "식탁 위 컵을 집어" | 글 토큰 |

- 지도 관련 토큰은 많아야 **16 + 2 + 1(목표) = 19 개**다. 같은 지도를 글로 풀면 100–200 토큰이 든다.

## 2. 몸 상태 (56)

| 묶음 | 값 | 개수 | 어디서 |
|---|---|---|---|
| 팔 관절 각도 | OMX-F joint1–5 + 그리퍼 | 6 | Dynamixel 현재 위치 |
| 팔 관절 속도 | joint1–5 + 그리퍼 | 6 | Dynamixel 현재 속도 |
| 관절 위치 xyz | joint1–5 축 + 손끝, 각 x·y·z (`base_link` 기준) | 18 | URDF 순기구학 |
| 손끝 방향 | 회전행렬 앞 두 열(6D) | 6 | 순기구학 |
| 손끝 속도 | 선속도 3 + 각속도 3 | 6 | 야코비안 × 관절 속도 |
| 몸통 속도 | vx, vy, wz | 3 | 리모 바퀴 오도메트리 |
| 직전 명령 | 바로 전 행동(5절) | 8 | 정책 자신 |
| 손끝 → 목표 | 목표 물체(또는 목표 지점) − 손끝, xyz | 3 | 3절 + 순기구학 |

- 토큰: **팔**(각도·속도·관절 xyz·손끝 방향·속도), **몸통**(몸통 속도), **목표**(손끝 → 목표, 직전 명령, 다음 경유 지점 방향·거리 — 4절).
- 관절 xyz·손끝 방향·속도는 각도·속도에서 계산되는 값이지만, 모델이 순기구학을 배울 필요가 없게 넣는다. 시뮬과 실제 모두 같은 URDF 로 계산해야 한다.
- 직전 명령은 행동을 부드럽게 하지만 기대면 되풀이한다 → 학습 때 가끔 지우거나 잡음.
- 속도 값은 실제 센서 잡음이 크다 → 시뮬 학습 때도 비슷한 잡음을 넣는다.

## 3. 물체 칸 (≤ 16 칸, 칸마다 289 → 토큰 1)

scenemap 물체(`sm_object`: `pos`, `extent`, `first_pos`, `n_obs`, `score`, `last_seen`, `state`)와 이름 캐시(`cache/names.json`), 물체 벡터(`objects/O<id>_emb.f16`)에서 만든다.

| 값 | 개수 | 계산 |
|---|---|---|
| 위치 xyz (로봇 기준) | 3 | 보이면 이번 프레임 마스크 + 깊이 → 카메라 → 로봇(카메라 장착은 URDF). 안 보이면 지도 `pos` − SLAM 자세 |
| 위치 xyz (손끝 기준) | 3 | 위 − 손끝(순기구학) |
| 거리·방향 (로봇에서) | 2 | 위치에서 |
| 크기 | 3 | `extent` (축 맞춤 상자) |
| 손끝 ↔ 중심 거리 | 1 | 손끝 기준 xyz 의 길이 |
| 손끝 ↔ 겉면 거리 | 1 | 손끝에서 상자 가장 가까운 면까지, 안이면 0 |
| 팔이 닿는지 | 1 | 리모를 안 움직이고 OMX 만으로 닿는지(URDF 관절 한계로 미리 계산한 작업 공간) |
| 처음 자리에서 옮겨진 양 | 3 | `pos − first_pos` (로봇 기준 회전만 적용) |
| 물체 속도 | 3 | 이전 스냅숏과의 차이(들려 움직일 때 등) |
| 상태 | 4 | 보임 / 사라짐 / 옮겨짐 / 들고 있음 (`state`) |
| 마지막 본 뒤 시간 | 1 | `last_seen` |
| 믿을 만한 정도 | 2 | 검출 점수(`score`), 본 횟수(`n_obs`) |
| **출처** | 1 | `지금 보는 중`(카메라에서 바로) / `기억`(지도) |
| **위치 불확실도** | 1 | 기억이면 마지막으로 본 뒤 로봇이 움직인 거리·회전에 따라 커짐(바퀴 오도메트리 오차) |
| 같은 방인지 | 1 | 방 배정 |
| 목표인지 | 1 | 목표 물체 표시(순서가 아니라 이 값으로) |
| 이름 확신도 | 2 | 라벨 표 1위 점수, 1위 − 2위 |
| **이름 뜻 벡터** | 128 | 이름(라벨 표 1위, 확신 낮으면 상위어)을 **얼린** SigLIP 2 글 인코더로 → `training/embed` 128-d 투영(얼림). 한국어 이름은 한국어 학생 인코더(같은 공간) |
| **생김새 벡터** | 128 | 물체 조각의 SigLIP 2 영상 벡터 → 같은 128-d 투영 |
| 합계 | 289 | 숫자 33 + 이름 뜻 128 + 생김새 128 |

- 칸마다 **같은 작은 MLP** 로 토큰 1개를 만든다. 칸에는 위치 번호를 붙이지 않는다(순서 없는 집합). 빈 칸은 마스크.
- 칸 고르기: 목표 물체는 항상 넣고, 나머지는 로봇에서 가까운 순으로 최대 16. 물체가 0개여도 동작한다.
- 이름 뜻 벡터와 생김새 벡터, 지시 문장이 **같은 SigLIP 2 공간**이라 "지시 ↔ 이름 ↔ 실제 생김새" 를 바로 비교할 수 있다. 이름이 틀려도(라디오를 "satchel" 로 부름) 생김새로 찾는다.
- 물체 방향(회전)·잡을 자리는 scenemap 에 없다. 필요하면 물체 점 구름(`objects/O<id>_points.ply`)으로 계산해 칸에 붙인다(긴 물건 집기).

## 4. 주변 공간 (토큰 2) · 목표 지점

| 토큰 | 값 | 어디서 |
|---|---|---|
| 벽 | 벽 상태 벡터 56(16 방향 거리 + 가까운 벽 선분 8 개), 로봇 기준 | `sm_snap_wall_state`. 지금 깊이 스캔으로 바로 계산하는 것이 원칙(로컬라이제이션 불필요) |
| 방 | 지금 방 종류 확률(kitchen·bathroom·bedroom·living room·office·unknown), 가까운 문 방향·거리 | 방 나누기·이름([model_selection.md](../model_selection.md) "방 나누기·이름") |
| (목표 토큰에) 다음 경유 지점 | 로봇 기준 방향·거리 | place 경로(`sm_snap_place_path`) − SLAM 자세 |

- 방 id·방 개수·지도 크기는 넣지 않는다.
- 거리는 5 m 쯤에서 자르고 먼 값은 로그로 눌러 정규화한다. 정규화 통계는 학습 데이터로 계산하고 실제 로봇도 같은 값을 쓴다.

## 5. 출력

- 행동 8 = 몸통(vx, wz) 2 + 팔 joint1–5 5 + 그리퍼 1. 리모를 메카넘으로 쓰면 몸통 3(vx, vy, wz)으로 9.
- 청크: 10 Hz × 16–32 스텝(1.6–3.2 s). 앞 몇 스텝만 실행하고 새 영상·지도로 다시 추론한다.
- 액션 전문가: flow matching(π0.5·`BC` 계획과 같음).

## 6. 학습 데이터 규칙 (일반화)

| 규칙 | 하는 것 |
|---|---|
| 여러 집 | BEHAVIOR 여러 장면으로 RL·시연을 모은다. 평가는 학습에 안 쓴 집으로 |
| `slam` 자세 | 기억 값은 정답 지도가 아니라 실제와 같은 오차가 든 `slam` 자세로 만든다 |
| 덜 만들어진 지도 | 물체 칸 무작위로 지우기, 위치 잡음, 가짜 물체 섞기(탐사 초반·검출 실수 흉내) |
| 지도 없이 | 가끔 지도 토큰을 통째로 비운다 → 카메라만으로 기본 동작, 지도는 보조 |
| 이름 바꾸기 | 같은 뜻 다른 말(cup ↔ mug ↔ 컵 ↔ 머그잔, 상위어 식기) — 라벨 표 동의어·WordNet 상위어 |
| 이름 지우기 | 가끔 이름 뜻 벡터를 비운다 → 생김새만으로도 |
| 틀린 이름 | 가끔 비슷한 다른 이름(컵 ↔ 그릇)으로 바꾼다 → 생김새와 맞춰 보기 |
| 지시 바꾸기 | "컵을 집어" → "머그잔 집어줘" 처럼 같은 뜻 다른 말 |
| 센서 잡음 | 관절·바퀴 속도, 깊이에 실제 수준의 잡음 |

## 7. 외웠는지 확인하는 평가

| 평가 | 통과 기준 |
|---|---|
| 학습에 **안 나온 물체 이름**만(예: 학습엔 컵·병, 평가엔 텀블러·주전자) | 학습 때 본 이름과 비슷한 성공률 |
| 학습에 **안 쓴 집** | 같은 집과 비슷한 성공률 |
| 지도 없음 대 있음 | 지도가 있을 때 더 좋아야 함(지도가 보조로 쓰이는지) |
| `gt` 지도 대 `slam` 지도 | 차이가 작아야 함(로컬라이제이션 오차에 강한지) |

## 8. 아직 정할 것

- **어디서 돌릴지**: 리모 위(Jetson Nano 4GB 또는 라즈베리파이 5 + DX-M1)면 작은 몸통(SigLIP 2 B/32 패치 토큰 — 물체 기억과 인코더를 나눠 씀 — + 작은 트랜스포머 6–8 층), PC·서버면 `BC` 계획의 Qwen3.5-2B(얼림)로 시작. 지금 SigLIP 2 엔진은 풀링된 벡터 하나만 내므로 패치 토큰을 내는 판을 다시 내보내야 한다([training/model/README.md](../../training/model/README.md)).
- **리모 바퀴 모드**: 차동(행동 8) 또는 메카넘(행동 9).
- **OMX-F 작업 공간**: "팔이 닿는지" 를 계산할 범위. URDF 관절 한계에서 뽑는다.
- **지금 보이는 물체의 즉시 3D**: scenemap 이 keyframe 마다 검출 + 깊이 → 3D 를 이미 계산한다. 지도에 넣기 전 값을 꺼내는 C ABI 가 필요하다.
