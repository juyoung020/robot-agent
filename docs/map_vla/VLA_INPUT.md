# 우리 VLA 입력·출력 설계 (리모 + OMX-F, 지도 토큰)

작성 2026-10-03. **설계 문서**다. 2026-10-04 에 학습 쪽(시뮬·GPU) 구현을 이 설계에 맞췄다 — 절마다 끝의 **구현 상태** 메모(잰 값만). 학습 흐름(RL 전문가 → 시연 → VLA 모방학습)은 [training/README.md](../../training/README.md) 의 `RL/`·`BC/`, 로봇 설명은 [src/robot/README.md](../../src/robot/README.md).

π0.5 는 입력이 영상 + 관절 state + 글이다. 우리는 여기에 **지금 도는 물체 기억(Spark-DSG 장면 그래프, scenemap)** 을 **토큰 몇 개**로 넣은 작은 VLA 를 직접 만든다.

- 앞 문서 MAP_STATE_PLAN.md 의 물체 슬롯(16 × 14, 클래스 id)을 이 문서가 바꾼다: 클래스 id 대신 **이름 뜻 벡터 + 생김새 벡터**, 손과의 관계, 로컬라이제이션 출처를 더했다.

## 0. 원칙

1. **모든 위치는 상대 좌표**다. 로봇(`base_link`) 기준, 손끝(`omx_end_effector_link`) 기준. 지도 원점 좌표(`map`)는 넣지 않는다.
2. **어떤 지도·집에서도 같은 뜻**이어야 한다. 지도마다 다른 값(지도 좌표, 방 id, 물체 id, 클래스 번호, 칸 순서, 지도 크기)은 넣지 않는다.
3. **로컬라이제이션이 필요 없는 값을 먼저** 쓴다. 지금 보이는 것은 카메라 + 깊이 + 순기구학으로 바로 잰다. 지도(기억)는 안 보이는 것에만, 출처와 불확실도를 붙여서.
4. **이름은 뜻으로 넣고 외우지 않게** 한다. 얼린 글 인코더 벡터 + 학습 때 이름 흔들기 + 처음 보는 이름으로 평가.
5. **시뮬은 실제 로봇과 같게**([plan.md](../plan.md) 코드 규칙). 같은 URDF(`src/robot/map_vla_description`)로 순기구학·카메라 위치를 계산하고, 학습 값은 정답 자세가 아니라 `slam` 자세로 만든다.

## 1. 입력 한눈에

| 입력 | 내용 | 토큰 |
|---|---|---|
| **RGB 그림 3장** | ① 리모 깊이 카메라(Orbbec)의 RGB ② OMX 손목 카메라(`wrist_cam_link`) RGB ③ **위에서 본 지도 그림**(1.1절, 지금 믿는 지도를 그린 256² RGB) — 셋 다 같은 SigLIP 2 탑(새 CNN 없음) | 영상 토큰 64 × 3 |
| 몸 상태 56 | 2절 | 3 (팔 · 몸통 · 목표) |
| 목표 칸 2 × 16 | 2.1절 — 집을 것·놓을 곳(물체 id 또는 지도 점), 로봇 기준 | 목표 토큰에 |
| 물체 기억 전체 N ≤ 256 × 289 → **기억 토큰 32 + 정밀 칸 8** (2026-10-05) | 3절, MAPVLA_SPEC 2.8 | 기억 요약 인코더 |
| 방 항목 ≤ 8, 탐사 경계 후보 ≤ 8 (2026-10-05) | 4절 | 항목마다 1 |
| 주변 공간 | 4절 | 2 (벽 · 방) |
| 지시 문장 | LLM(Qwen, KAU API)이 준 지금 단계 한 줄. 예: "식탁 위 컵을 집어" | 글 토큰 |

- (10-05 갱신) 지도 관련 토큰은 기억 32 + 정밀 칸 8 + 벽 1 + 방 항목 ≤ 8 + 탐사 경계 ≤ 8 + 목표 = 약 58 개다. 아래 옛 셈(16 + 2 + 1 = 19)은 기록. 지도 관련 토큰은 많아야 **16 + 2 + 1(목표) = 19 개**다. 같은 지도를 글로 풀면 100–200 토큰이 든다. 숫자 토큰(벽 16 방향 + 선분 8, 방·문, 경유 지점, 물체 16 칸, 목표 칸)은 그림이 생겨도 **모두 그대로** 둔다.
- **깊이는 그림으로 주지 않는다**(결정 2026-10-05, π0.5 도 RGB 만). 깊이는 지도·물체 칸·위에서 본 지도 그림을 만드는 데만 쓴다.
- **한 추론에 그림마다 지금 한 장**(카메라와 같음, π0.5 꼴). 지난 프레임을 쌓지 않는다 — 긴 기억은 지도 토큰과 위에서 본 지도 그림이 맡는다.

## 1.1 위에서 본 지도 그림 (셋째 그림, 결정 2026-10-05 — **10-06 뺌**)

> **2026-10-06 결정: 지도 그림을 입력에서 뺀다**(지도를 통째로 주면 MDP 에 어긋남). 물체 칸의 로봇 기준 상대 좌표·거리로 대신한다. 아래는 뺄 때까지의 기록. 할 일: `training/curriculum/README.md` "입력·상태".

정의는 하나다: `training/RL/map/include/topview.h`. GPU 학습(지도 근사)·실제 로봇 변환기(`sm_tok.h sm_topview_rgb`)·앱 화면(plan.md 5절)이 같은 규칙·같은 색을 쓴다.

- **무엇을 그리나 — 지금 믿는 지도만**: 스텝마다 **지금 자라는 믿음 지도**(GPU 지도 근사: 처음 지도 커리큘럼 C0/C1/C2, slam 자세 잡음, objmap 규칙을 거친 기억 / 실제: 지금 scenemap)에서 그린다. **정답 전체 지도에서 그리지 않는다.** 안 본 칸은 회색이고, 물체는 로봇이 본 만큼 나타나고 옮겨진다.
- **놓임**: 로봇이 가운데, 로봇 앞이 위(믿는 slam 자세로 돌림). 256 × 256 px, 화소 0.05 m(12.8 m — 지도 창 128 × 128 칸 0.10 m 를 덮음). 화소 (u, v) 가운데 = 로봇 좌표 x 앞 (128 − (v + 0.5))·0.05, y 왼 (128 − (u + 0.5))·0.05 의 한 점으로 칸을 읽음(가장 가까운 칸, 앤티에일리어싱 없음 → 결정적, GPU == CPU 비트 동일).

## 2.1 목표 칸 (집을 것 · 놓을 곳, 2 × 16 — 결정 2026-10-05)

앱에서 사용자는 위에서 본 지도를 보고 **물체를 누르면 그 물체 id**, **바닥·면을 누르면 정확한 지도 점**("여기에 놔")을 준다. VLA 는 그 점까지 가서 정확히 놓아야 한다. 그래서 물체 목표와 점 목표를 **한 꼴의 목표 칸**으로 합친다. 칸은 둘: **0 = 집을 것(PICK)**, **1 = 놓을 곳(PLACE)** — 물건 없이 "여기로 가" 의 점도 놓을 곳 칸에 넣고 집을 것 칸은 비운다.

| 값 | 자리 | 뜻 |
|---|---|---|
| 있음 | 0 | 이 목표가 주어짐 |
| 꼴 | 1, 2 | 물체(id) / 점 — 원-핫 |
| 앎 | 3 | 위치 값이 있음(물체가 지도에 있음 — 지금 또는 마지막으로 알던 자리, 또는 점) |
| 잃음 | 4 | 물체 목표의 위치가 **마지막으로 알던 자리**(지도에서 사라짐 GONE / 실제 지도에서 빠짐) |
| 위치 x·y·z | 5–7 | 로봇 base_link 기준: (목표 − 로봇) 을 로봇 yaw 로 돌린 값, z = 세계 z − 0.15 (칸 T_POS 와 같음) |
| 거리 | 8 | 수평 거리 |
| 방위 sin·cos | 9, 10 | y/거리, x/거리 (거리 < 1e-4 면 0, 1) |
| 손끝 기준 x·y·z | 11–13 | 위치 − 손끝(순기구학, base_link 축) |
| 0 | 14, 15 | 비움 |

- **0절 규칙 그대로**: 지도 좌표·물체 id·종류 번호는 넣지 않는다. 같은 값이 어떤 지도·집에서도 같은 뜻.
- **물체 목표는 일부러 겹친다**: 목표 칸에 값을 넣고, 그 물체의 칸(3절)의 "목표인지" 도 켠다. 점 목표는 칸이 없다(목표 칸만).
- **위치**: 물체 = 그 물체 칸과 같은 규칙(지금 보는 중이면 그 keyframe 관측 자리, 아니면 지도 자리 — 믿는 slam 자세 기준). 사라졌으면(GONE, 실제는 지도에서 빠짐) 마지막 자리 + 잃음 1. 아직 못 찾은 물체 = 있음 1·물체 1·나머지 0. 점 = 사용자가 준 지도 점(앱이 로봇 쪽 검사·옮김 뒤 — plan.md 5절).
- **정규화**(관측 X0 [432, 464), `observation/include/obs.h goal_val`): 표시·꼴·앎·잃음·sin·cos 는 그대로. 위치 xyz·거리·손끝 기준 xyz 는 **물체 칸 숫자와 같은 특징의 μ·σ**(`tok_norm.h` 특징 T_POS 0–2, T_DIST 6, T_POS_EEF 3–5 — 같은 5 m 자르기·로그 누름·표준화). 위치를 모르면 위치 값 0, 칸이 없으면 모두 0. 실제 로봇(실행기 `move_robot goal.rs`)은 같은 헤더를 읽고 같은 lnf_d 로 계산한다.
- **과제 값**: 스킬·지시문처럼 use_map·지도 끄기 흔들기와 무관하게 늘 넣는다(교사·학생 같음).
- **학생 목표 감추기(`p_goal_drop`)**: 감춘 판에서 **물체** 목표 칸은 통째로 0(목표 없음과 같은 입력), 칸 "목표인지" 0. **점 목표 칸은 감추지 않는다** — 점은 지시문("여기에 놔")에서 알 수 없기 때문. 점으로 가기 판은 몸 상태의 목표 값·경유 지점도 점 쪽이라 남긴다(POLICY 4.6).

> - **이름 뜻·생김새·지시 벡터**: `training/embed` 의 얼린 128-d 공간(P, `sb32_pe_300k`)에 둔다 — 영어 글 = PE-L 글 탑 + P(라벨 표 `objects-v1` 의 text128 행 그대로), 한국어 = 한국어 학생 + P, 생김새 = 우리 GPU 렌더 조각 → C++ SigLIP 2 B/32 탑 → C++ MAP 풀링 + 머리 h(PyTorch 대비 코사인 최소 0.99996). 이 문서의 "SigLIP 2 글 인코더 → 128 투영" 은 embed 의 라벨 표 약속(글 = PE-L + P)으로 구현했다. 표 `training/data/vla_v1`: 이름 584 줄(시뮬 6 종류 + BEHAVIOR 2026 과제 100 개의 물체 synset 259, 동의어·상위어, 평가용 처음 보는 이름 7), 지시 40 문장, 생김새 7 줄(시뮬 6 종류 + 유령). 토큰에는 표 행 번호만 두고(계획서 4.4), 신경망 입력을 만들 때 장치 표에서 128 칸씩 옮긴다(칸 입력 304 = 숫자 33 + 128 + 128 + 1).
> - **이름 확신도 2 / 상위어**: 1위 점수 = cos(생김새, 이름), 1위 − 2위 = 이름 어휘 440 줄 안 다른 이름 최댓값과의 차(`vla_vocab.h`, 생김새 행 × 이름 종류 표). 1위 − 2위 < −0.08 이면 이름 행 = 상위어. **한계**: 지금 시뮬 물체는 색 상자라 생김새가 종류를 거의 못 가른다(종류끼리 코사인 0.92–0.98) → 맞는 이름도 셋 중 하나꼴로 상위어(A1 무작위 행동 판의 채운 칸 0.448 이 상위어). 메시 렌더 뒤 표·문턱을 다시 만든다(도구는 그대로).

> - **출처·위치**: 지금 보는 중(마지막 keyframe 에서 봄) 칸의 위치는 그 관측 자리(`Slot::meas`), 기억 칸은 지도 자리 − slam 자세. **위치 불확실도**는 마지막으로 본 뒤 믿는 오도메트리 이동·회전 × 오도메트리 잡음 규칙(그대로). 옮겨진 양·속도·같은 방·목표·상태·시간·점수·본 횟수는 예전 그대로 표 정의와 같다.
> - 학습 때 이름 흔들기(같은 무리 다른 말·상위어·비슷한 틀린 이름·지우기)·칸 지우기·지도 통째로 비우기는 장치 값(`obs.h ObsAug`, 6절).

## 5. 출력

- 행동 8 = 몸통(vx, wz) 2 + 팔 joint1–5 5 + 그리퍼 1. 리모를 메카넘으로 쓰면 몸통 3(vx, vy, wz)으로 9.
- 청크: 10 Hz × 16–32 스텝(1.6–3.2 s). 앞 몇 스텝만 실행하고 새 영상·지도로 다시 추론한다.
- 액션 전문가: flow matching(π0.5·`BC` 계획과 같음).
- **글 출력(결정 2026-10-04, π0.5 꼴)**: 같은 모델이 추론마다 **다음 단계 문장**(짧은 명령문, ≤ 16 토큰 — 예 "go to the living room" → "pick up the cup from the table" → "put it on the shelf")을 먼저 내고, 행동 전문가는 그 단계 문장까지 든 prefix 를 보고 청크를 낸다. 입력 지시는 에이전트가 넘긴 **전체 목표 + 물체 id**(id 는 칸의 "목표인지"). 지도 기억이 입력이라 안 보이는 물체·다른 방으로 가는 단계도 고른다. 대화·긴 생성은 하지 않는다. 사양은 [MAPVLA_SPEC.md](MAPVLA_SPEC.md) 2.3·2.4·2.6절. 지금 작은 학생(아래 구현 상태)은 글을 내지 않는다.

> **구현 상태(5절)**: 행동 8(차동). 환경은 늘 팔을 풀고, 단계마다 학습하는 행동은 **장치 값 비트 가림**(PPO `TrainState::act_mask`·`ppo_set_act_mask`·설정 단계 `act_mask`, BC `act_mask`·`bc_set_act_mask`) — 꺼진 행동은 0(= 팔 홈 자세)이라 팔 묶음과 비트가 같다(`env_verify --arm-zero`). 교사 표본·logp·엔트로피, BC 라벨·MSE·flow 손실, 학생 출력이 같은 가림을 쓴다. 학생 청크 = 10 Hz × H(기본 16) × 행동 8, flow matching 행동 전문가(토큰마다 학생은 행동 토큰 H 개가 prefix 를 보는 트랜스포머).

| 덜 만들어진 지도 | 물체 칸 무작위로 지우기, 위치 잡음, 가짜 물체 섞기(탐사 초반·검출 실수 흉내) |
| 지도 없이 | 가끔 지도 토큰을 통째로 비운다 → 카메라만으로 기본 동작, 지도는 보조 |
| 이름 바꾸기 | 같은 뜻 다른 말(cup ↔ mug ↔ 컵 ↔ 머그잔, 상위어 식기) — 라벨 표 동의어·WordNet 상위어 |
| 이름 지우기 | 가끔 이름 뜻 벡터를 비운다 → 생김새만으로도 |
| 틀린 이름 | 가끔 비슷한 다른 이름(컵 ↔ 그릇)으로 바꾼다 → 생김새와 맞춰 보기 |
| 지시 바꾸기 | "컵을 집어" → "머그잔 집어줘" 처럼 같은 뜻 다른 말 |
| 센서 잡음 | 관절·바퀴 속도, 깊이에 실제 수준의 잡음 |

> **구현 상태(6절)**: 장치 값 `ObsAug`(`training/RL/observation/include/obs.h`): 속도 잡음, 직전 명령 지우기·잡음, 이름 흔들기 4 종, 칸 지우기, 지도 통째로 비우기 — PPO 는 롤아웃·갱신이 같은 열쇠(같은 입력), BC 는 학생만(교사 라벨 입력은 깨끗). 지시 바꾸기 = 에피소드마다 과제의 바꿔 말하기 하나. 렌더(학생만): 판마다 색 변형·조명 방향·노출 흔들기와 팀 기본 설정 섞기(`render_aug`). 얼린 인코더 토큰 코사인(상태 128 개): 싼 설정 대 팀 기본 0.719, 싼 설정 대 흔든 싼 설정 0.689 — 흔들기 폭이 두 설정 차이와 같은 크기다. 여러 집·`slam` 자세·위치 잡음·가짜 물체는 예전 지도 근사 그대로(장면 생성기는 아직 하나).

## 7. 외웠는지 확인하는 평가

| 평가 | 통과 기준 |
|---|---|
| 학습에 **안 나온 물체 이름**만(예: 학습엔 컵·병, 평가엔 텀블러·주전자) | 학습 때 본 이름과 비슷한 성공률 |
| 학습에 **안 쓴 집** | 같은 집과 비슷한 성공률 |
| 지도 없음 대 있음 | 지도가 있을 때 더 좋아야 함(지도가 보조로 쓰이는지) |
| `gt` 지도 대 `slam` 지도 | 차이가 작아야 함(로컬라이제이션 오차에 강한지) |

> **구현 상태(7절)**: 처음 보는 이름 = `aug_eval_unseen` 1(이름 행을 같은 무리의 학습 안 쓴 이름 — mug·tumbler·crate·side chair·worktable·sideboard·wastebasket — 으로, 지시는 heldout 바꿔 말하기로; 학습 흔들기는 이 이름을 뽑지 않음). 지도 없음 = `use_map 0` 또는 `aug_p_map_off 1`. 안 쓴 집·`gt` 대 `slam` 평가는 아직(장면 생성기 하나, 지도 근사는 늘 slam).

## 8. 아직 정할 것

- **어디서 돌릴지**: 리모 위(Jetson Nano 4GB 또는 라즈베리파이 5 + DX-M1)면 작은 몸통(SigLIP 2 B/32 패치 토큰 — 물체 기억과 인코더를 나눠 씀 — + 작은 트랜스포머 6–8 층), PC·서버면 `BC` 계획의 Qwen3.5-2B(얼림)로 시작. 지금 SigLIP 2 엔진은 풀링된 벡터 하나만 내므로 패치 토큰을 내는 판을 다시 내보내야 한다([training/model/README.md](../../training/model/README.md)).
- **리모 바퀴 모드**: 차동(행동 8) 또는 메카넘(행동 9).
- **OMX-F 작업 공간**: "팔이 닿는지" 를 계산할 범위. URDF 관절 한계에서 뽑는다.
- **지금 보이는 물체의 즉시 3D**: scenemap 이 keyframe 마다 검출 + 깊이 → 3D 를 이미 계산한다. 지도에 넣기 전 값을 꺼내는 C ABI 가 필요하다.

- **제안(2026-10-05, E6 잡기 물리 — 아직 입력에 넣지 않음, 사용자 결정 필요)**: 집기·놓기 학습에서 쓸 만한 값 중 이 문서에 없는 것.
  ① **쥠 닿음 1 값**(몸 상태 끝에): 그리퍼가 명령보다 덜 닫힌 채 멈춤 = 손가락이 무엇을 쥠. 실제 로봇은 Dynamixel 그리퍼 **현재 전류(present current)** 또는 명령 각 − 지금 각으로 잴 수 있다. 시뮬은 env `OF_CONTACT`/`OF_GRASP` 와 그리퍼 각(이미 몸 상태 6 번째)에서 바로 나온다.

  지금 들고 있음은 물체 칸 상태 "들고 있음"(지도의 믿음 규칙, scenemap updateHands 와 같음), 그리퍼 벌림은 몸 상태 그리퍼 각으로 이미 들어 있어 더하지 않았다. 넣으면 몸 상태 56 → 57/58 이 되어 교사·학생 입력 배치·체크포인트가 바뀐다.
