# 모델 선택 (model selection)

부품마다 **무엇을 기준으로, 어떤 후보 중에서, 어떤 실험으로** 고를지 정리한다.
결정이 나면 맨 아래 [결정 기록](#결정-기록)에 적는다. 전제(로봇·서버 사양)는 [`plan.md`](plan.md) 참고.

## 공통 제약

| 항목 | 내용 | 영향 |
|---|---|---|
| 로봇 컴퓨터 | 기본 리모 Jetson Nano (4GB), Ubuntu 18.04 | 무거운 모델은 로봇에서 못 돌림 → **학교 4090 서버에서 돌리고 결과만 받음** |
| 서버 | RTX 4090 (24GB) | 모든 모델이 동시에 올라가야 함 (분할 + 특징 + LLM + VLA) → 메모리 합계를 따진다 |
| ROS | 기본 리모는 Ubuntu 18.04 라 ROS 2 가 기본으로 안 깔림 | ROS 2 는 Docker 로 돌리거나 서버 쪽에서 돌리는 방법을 먼저 확인 |

## 고르는 방법 (모든 부품 공통)

1. 후보를 2~3개로 줄인다 (아래 표).
2. **같은 데이터**로 비교한다 — 우리 ros2 bag 녹화본 또는 같은 시뮬 장면.
3. 기준표의 숫자를 재서 표로 남긴다 (`tests/sandbox/` 에서 실험, 결과는 `docs/` 에).
4. 가장 중요한 기준을 통과한 것 중 가장 가벼운 걸 고른다.
5. [결정 기록](#결정-기록)에 날짜·근거와 함께 적는다.

## 1. SLAM (위치 추정 + 지도)

| 기준 | 재는 법 |
|---|---|
| 리모에서 돌아가나 | Jetson Nano 에서 CPU·메모리 사용량 |
| 위치 오차 | 방을 한 바퀴 돌고 출발점으로 돌아왔을 때 어긋난 거리 |
| 3D 가 필요한가 | scene graph 는 물체의 3D 위치가 필요 → 2D 라이다 pose + depth 카메라로 충분한지 확인 |

| 후보 | 특징 |
|---|---|
| Cartographer | 2D 라이다 SLAM. 리모 공식 데모 있음 |
| RTAB-Map | RGB-D(+라이다) 3D SLAM. 리모 공식 데모 있음. 무거움 |
| slam_toolbox | ROS 2 기본 2D SLAM. Nav2 와 잘 붙음 |

**기본안(잠정)**: 리모 공식 데모가 있는 것부터 (Cartographer → 부족하면 RTAB-Map).

## 2. 물체 분할 (SAM 계열)

| 기준 | 재는 법 |
|---|---|
| 속도 | 4090 에서 FPS |
| 정확도 | 물체 하나가 여러 조각으로 쪼개지는지(과분할), 놓치는지 |
| 메모리 | 4090 에서 다른 모델과 같이 올라가는지 |

| 후보 | 특징 |
|---|---|
| SAM 2 | 가장 정확, 가장 무거움 |
| MobileSAM | 원본 SAM 보다 약 7배 빠름. 실내 의미 지도 비교 연구에서 속도·정확도 균형이 가장 좋았음 |
| FastSAM | 가장 빠름, 대신 조각나고 부정확 |
| EfficientViT-SAM | 빠르고 정확도 좋음. 후보로 같이 잰다 |

필요하면 물체 후보를 먼저 찾는 **검출기**(YOLO-World, Grounding DINO)를 앞에 붙인다.

**결정: FastSAM** (2026-09-30). 속도 우선. 조각남·부정확은 DA(같은 물체 판단) 단계에서 보완할지 확인한다.

## 3. 의미 특징 (CLIP 계열)

| 기준 | 재는 법 |
|---|---|
| 글로 찾기 정확도 | 우리 물체 목록(컵, 의자 …)으로 잘라낸 물체 사진을 검색 → 맞힌 비율 |
| 속도·메모리 | 물체 하나당 시간, 4090 메모리 |

| 후보 | 특징 |
|---|---|
| CLIP (OpenCLIP) | ConceptGraphs·HOV-SG 등 대부분의 scene graph 논문이 사용 |
| SigLIP | CLIP 후속 계열. 같은 방식으로 비교 |

**기본안(잠정)**: OpenCLIP (참고 코드와 맞추기 쉬움).

## 4. DA (data association, 같은 물체 판단)

모델이 아니라 **규칙(알고리즘)** 을 고른다.

| 기준 | 재는 법 |
|---|---|
| 중복 | 같은 물체가 지도에 두 번 등록된 수 |
| 합쳐짐 | 다른 물체가 하나로 합쳐진 수 |

| 후보 | 특징 |
|---|---|
| 3D 겹침 + 특징 유사도 | ConceptGraphs 방식. 점구름이 겹치고 CLIP 특징이 비슷하면 같은 물체 |
| 위치 거리만 | 가장 단순. 기준선(baseline)으로 |

**결정: 자체 제작** (2026-09-30). 위 두 후보는 참고·비교 기준선으로 쓰고, 중복·합쳐짐 수로 우리 것과 비교한다. FastSAM 조각을 다시 합치는 것도 여기서 처리한다.

## 5. 맵 업데이트 (바뀐 물체 고치기)

| 기준 | 재는 법 |
|---|---|
| 변화 탐지 | 옮겨짐·사라짐·생김을 맞힌 비율 (P/R/F1) |
| 속도 | 지도 전체를 다시 만들지 않고 바뀐 부분만 고치는지 |

| 후보 | 특징 |
|---|---|
| DovSG 방식 | 바뀐 부분만 국소 갱신 |
| Khronos 방식 | 시간에 따른 변화를 따로 추적 |

**결정: 자체 제작** (2026-09-30). 위 두 방식은 참고로 쓰고, 변화 탐지 P/R/F1 로 성능을 잰다. 결과는 Spark-DSG 뷰어로 확인한다.

## 6. Scene graph 자료구조

| 후보 | 특징 |
|---|---|
| Spark-DSG | Hydra·Khronos 가 쓰는 라이브러리. 층·방·물체 계층 지원, `pip install` 가능 |
| 직접 만든 JSON | 가장 단순. agent(LLM)에게 그대로 넘기기 쉬움 |

**고르는 기준**: agent 가 읽기 쉬운지, 참고 코드를 그대로 쓸 수 있는지.

**결정: Spark-DSG + Spark-DSG 뷰어** (2026-09-30). 지도는 Spark-DSG 형식으로 저장하고, 뷰어로 웹 브라우저에서 3D 로 본다.

```bash
pip install spark-dsg          # 또는 refs/code/Spark-DSG 에서 pip install .
spark-dsg visualize 지도.json   # http://localhost:8080 에서 보기 (viser 웹 뷰어)
```

## 7. Agent (LLM)

| 기준 | 재는 법 |
|---|---|
| 계획 성공률 | 명령 10~20개 세트("컵을 식탁에 갖다 놔" 등)로 단계를 제대로 나누는지 |
| 응답 시간 | 명령 하나에 몇 초 |
| 비용·오프라인 | API 요금, 인터넷 없이 되는지 |

| 후보 | 특징 |
|---|---|
| API 모델 (Claude, GPT 등) | 계획 능력 가장 좋음, 요금·인터넷 필요 |
| 4090 에서 돌리는 오픈 모델 | 무료·오프라인, 대신 VLA 와 4090 메모리를 나눠 써야 함 |

## 8. VLA

| 기준 | 재는 법 |
|---|---|
| 성공률 | 시뮬레이션에서 집기·놓기 성공 비율 |
| 4090 에 들어가나 | 파인튜닝·추론 메모리 |
| 원격 추론 | 서버에서 돌리고 리모는 결과만 받을 수 있는지 |

| 후보 | 크기 | 특징 |
|---|---|---|
| **π0.5** | 3.3B | 기본 선택. openpi 에 원격 추론 내장. LoRA 파인튜닝 22.5GB 이상 → 4090 에 겨우 들어감 |
| SmolVLA | 0.45B | 가볍고 일반 GPU 학습용. π0.5 가 4090 에서 안 되면 대안 |
| GR00T N1.5 | 3B | NVIDIA. 추론 16GB 이상 |

## 9. 양자화

| 기준 | 재는 법 |
|---|---|
| 성공률 손실 | 원래 모델 대비 성공률이 얼마나 떨어지나 |
| 속도·메모리 이득 | 추론 시간, 메모리 |

| 후보 | 특징 |
|---|---|
| bf16 (원래대로) | 기준선 |
| int8 | 보통 손실 적음 |
| int4 | 가장 가벼움, 손실 확인 필요 |

리모(Jetson Nano 4GB)에는 양자화해도 π0.5 가 안 들어가므로, 양자화는 **서버 속도·메모리 절약** 목적이다.

## 10. 학습용 시뮬레이션

| 기준 | 재는 법 |
|---|---|
| 우리 로봇과 비슷한가 | 바퀴 달린 로봇 + 팔, 집 안 환경 |
| 4090 에서 돌아가나 | 렌더링·학습 속도 |
| π0.5 예제가 있나 | 바로 파인튜닝 해볼 수 있는지 |

| 후보 | 특징 |
|---|---|
| LIBERO | openpi 에 예제 있음. 책상 위 팔 조작만 (이동 없음) → **첫 연습용** |
| BEHAVIOR-1K | 집 안 이동 + 조작. 2025 대회 상위 팀 모두 π0.5 사용 → 참고 코드 많음. 무거움 |
| Gazebo | 리모 시뮬 모델 있음. 이동·SLAM 연습용, VLA 학습용으로는 약함 |
